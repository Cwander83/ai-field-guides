02 • Setup & Tool Selection Installation, Authentication & Decision Matrix

Installation, Auth & Backend-to-Device Matrix

Set up both toolchains in under three minutes. Keep Firebase MCP tightly scoped per project directory while initializing the android CLI globally for fast SDK, emulator, and Studio access.

1 Install & Initialize android CLI

Install the native binary for your host OS, then run android init to configure directories and default skills:

# macOS Apple Silicon (darwin_arm64) curl -fsSL https://dl.google.com/android/cli/latest/darwin_arm64/install.sh | bash # Linux x86-64 curl -fsSL https://dl.google.com/android/cli/latest/linux_x86_64/install.sh | bash # Windows Command Prompt curl -fsSL https://dl.google.com/android/cli/latest/windows_x86_64/install.cmd -o "%TEMP%\i.cmd" && "%TEMP%\i.cmd" android init && android auth login

Discover domain skills anytime via android skills find compose and install with android skills add <id>.

2 Authenticate & Scope Firebase MCP

Firebase MCP runs as a built-in subcommand of firebase-tools. Refresh OAuth credentials, add agent skills, and pin MCP flags:

# 1. Re-authenticate & install Firebase agent skills npx -y firebase-tools@latest login --reauth npx skills add firebase/agent-skills # 2. Register stdio MCP server (or claude mcp add) claude mcp add firebase npx -- -y firebase-tools@latest mcp \ --dir /abs/path/to/project \ --only firestore,auth,dataconnect

Pinning --dir and --only prevents accidental edits across unrelated Firebase projects.

Seven-Point Cockpit Reference Legend

1 Sidecar Discovery File: Read ~/.android/cli/sidecars/compose-preview.json to get the active dynamic loopback port, then verify with GET /api/status.
2 Conversation Isolation Header: Always send X-Sidecar-Conversation: <id> on POST /api/session, POST /api/render, and GET /api/state so the pane renders your thread.
3 Session Configuration: POST /api/session sets project_dir, Gradle/Bazel reference, fqns, and "wait": true to build and render cleanly.
4 Component Tree (bounds_url): Inspect sourceLocation, semantics, and modifiers in JSON to audit padding and accessibility without guessing.
5 User Mirror WebSocket (/mirror/ws): Streams live AVD or USB device video and input in the Device Hub UI; agents inspect and drive devices via CLI and adb.
6 Layout JSON & Diffs: Run android layout --pretty --diff first to capture exact element bounds, focus states, and changes in minimal tokens.
7 Annotated Screen Resolve: When WebViews or custom canvases hide from the layout tree, run android screen capture --annotate and substitute box #N centers with android screen resolve.

Firebase AI Logic + App Check: Kotlin & Prompt Anatomy

Firebase AI Logic lets your Android app invoke Gemini directly from Kotlin without standing up a custom proxy server—while Firebase App Check proves every request originates from your genuine app binary.

1 Gradle Dependencies (BoM 35.1.0)
// app/build.gradle.kts dependencies { implementation(platform("com.google.firebase:firebase-bom:35.1.0")) implementation("com.google.firebase:firebase-ai") // Local debug vs Play Store attestation debugImplementation("com.google.firebase:firebase-appcheck-debug") releaseImplementation("com.google.firebase:firebase-appcheck-playintegrity") }
2 App Check Init + Console SHA-256

Register your app's SHA-256 fingerprint in Firebase Console under Play Integrity, and install the matching provider in Application.onCreate():

Firebase.initialize(this) Firebase.appCheck.installAppCheckProviderFactory( if (BuildConfig.DEBUG) DebugAppCheckProviderFactory.getInstance() else PlayIntegrityAppCheckProviderFactory.getInstance() )

3. Invoking Gemini 3.8 Flash & Gemini 3.8 Live in Kotlin

06 • Rapid Build & UI Loop android CLI Mastery & Compose Preview Sidecar

android CLI Mastery & Compose Preview Sidecar Loop

Replace slow trial-and-error Gradle cycles with fast delta deployments, live Android Knowledge Base queries, and headless Compose Preview rendering that exposes every composable's coordinates and accessibility semantics.

1 Project, SDK, Docs & Fast Delta Run
  • SDK & Scaffolding: Manage toolchains with android sdk list --all / install, scaffold templates via android create, and inspect build targets with android describe.
  • Fast Delta Deploy: android install and android run --use-delta-install ship only changed dex and resource deltas.
  • Wear & Multi-Surface Types: Pass --type for ACTIVITY, WATCH_FACE, TILE, COMPLICATION, DECLARATIVE_WATCH_FACE, or WEAR_WIDGET.
  • Authoritative Docs: Query current APIs via android docs search "App Check" and read full pages with android docs fetch kb://....
2 Discovering Targets & Flavor Variants

Discover every @Preview and MultiPreview function in JSON before rendering:

android preview list \ --reference gradle://.?:app@debug \ --all --format=json

Flavor Gotcha: Modules with product flavors have no bare debug variant. Always include flavors first, such as gradle://.?:feature:home@demoDebug.

3. Compose Preview Sidecar Loop (Save First, Then Render!)

# 1. Read port from ~/.android/cli/sidecars/compose-preview.json & configure session with conversation header curl -s -X POST http://127.0.0.1:$PORT/api/session \ -H "X-Sidecar-Conversation: $CONVERSATION_ID" -H "Content-Type: application/json" \ -d '{"project_dir":"/abs/MyApp","reference":"gradle://.?:app@debug","fqns":["com.example.ui.HomeScreenKt.HomePreview"],"wait":true}' # 2. Edit Kotlin UI files -> wait until ALL saves finish -> trigger re-render (never parallelize edit + render!) curl -s -X POST http://127.0.0.1:$PORT/api/render \ -H "X-Sidecar-Conversation: $CONVERSATION_ID" -H "Content-Type: application/json" -d '{"wait":true}'
Accessibility & Layout QA Without Guessing Pixels via bounds_url
When --component-tree is active (on by default), GET /api/state returns a bounds_url JSON tree for every rendered PNG. Read sourceLocation (fileName, lineNumber) to jump straight to the composable, check modifiers (padding, clickable, size), and verify semantics (text, contentDescription, role, testTag) to catch inaccessible icon buttons automatically.

07 • Live Device Verification Device Hub Sidecar, Visual Targeting & XML Journeys

Device Hub Sidecar, Visual Targeting & XML Journeys

Previews confirm static layout; real journeys prove behavior. Combine the Device Hub sidecar and android emulator CLI with JSON-first inspection, visual box resolution, and strict sequential XML journey scripts.

Closed UI Inspection Loop: Layered architectural Compose planes feed exact coordinates into the live glass device, pulsing touch targets back through android layout and screen resolve.
1 Boot Check & JSON-First Inspection
  • AVD Control: Use android emulator list|start|stop|create|remove or Device Hub GET /api/devices (never start duplicate jobs on one device).
  • Wait for Full Boot: Online emulators may still be booting. Run:
    adb -s <serial> wait-for-device shell 'while [ -z "$(getprop sys.boot_completed)" ]; do sleep 1; done'
  • JSON First, Pixels Second: Start with android layout --device <serial> --pretty (add --diff after actions). Switch to android screen capture --annotate -o /tmp/screen.png for WebViews or custom canvases, then inspect the PNG visually.
2 Precision Input & Strict XML <journey>
  • Tap Resolved Boxes:
    adb -s <serial> shell $(android screen resolve --screenshot /tmp/screen.png --string "input tap #7")
  • Safe Text & Slow Scrolls: Confirm "focused" in element state, encode spaces as %s ("Hello%sworld"), and scroll slowly over 500ms (adb shell input swipe 250 400 250 200 500).
  • Sequential XML Journeys: Execute each <action> strictly as written in order; stop immediately on failure or crash and emit a Markdown report marking steps ✅ or ❌.

09 • Security & Fleet Ops App Check, Least-Privilege MCP & Remote Devices

App Check Enforcements, Least-Privilege MCP & Fleet Ops

Production AI mobile apps require tight boundaries at every hop—limiting what your coding agent can mutate in Firebase, proving app identity at runtime, and testing safely across remote hardware.

1 Least-Privilege Firebase MCP Rules
  • Always Pin --dir: Pass an absolute project path so agents never read or write the wrong Firebase alias.
  • Scope With --only: Enable only the tool groups needed for the sprint (for example firestore,auth,dataconnect) instead of exposing destructive project-wide surfaces.
  • Review Rules Before Deploy: Ask the agent to validate Firestore and Storage Security Rules before updating client queries.
2 Debug-to-Play Integrity Rollout
  • Local Debug Tokens: Register the Logcat token printed by firebase-appcheck-debug in Firebase Console for emulator tests.
  • Release Attestation: Swap to firebase-appcheck-playintegrity and add your Play App Signing SHA-256 fingerprint in Console.
  • Enforce Last: Monitor App Check metrics for gemini-3.8-flash and gemini-3.8-live traffic before flipping enforcement on.
3 Android Studio Live Bridge

When Android Studio is open, let the agent tap directly into its live PSI index rather than grepping blindly:

  • android studio check — verify running IDE instances.
  • android studio find-declaration & find-usages — trace Compose callbacks and ViewModels accurately.
  • android studio version-lookup — fetch latest Maven artifacts like firebase-bom:35.1.0 and SDK tools.
4 Remote Devices & Secure Capture Rules

Scale beyond local emulators when testing real sensors, Play Integrity, and WebViews:

  • Remote Physical Lab: Reserve and connect to cloud hardware via android device remote.
  • Tunnel Latency: Screen captures over tunneled devices take longer; re-capture only after state-changing actions.
  • DRM & Banking Blackouts: FLAG_SECURE windows capture strictly black in both screenshots and Device Hub mirrors.
One ADB Server Shared Across CLI and Sidecar
Because Device Hub and the android CLI share the same local ADB server, remote devices attached via adb connect 127.0.0.1:6555 appear automatically in GET /api/devices and can be mirrored live by the user while you inspect them.

11 • Clinic & Pre-Flight Troubleshooting Clinic & 6-Point Checklist

Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Hit a blank pane, dropped Live session, or misbehaving ADB command? Match your symptom below for a 10-second root-cause fix.

Symptom / Failure 10-Second Root-Cause Fix
1. Compose Preview pane stays blank after POST /api/session You omitted the X-Sidecar-Conversation: <id> header (or used a query parameter). Re-send with the exact HTTP header.
2. android preview render fails or renders stale UI edits Never invoke android preview render directly, and never call POST /api/render in parallel with file edits. Save all edits first, then call POST /api/render.
3. Gradle preview lookup fails on :feature@debug Modules with product flavors have no bare debug variant. Supply the flavor-first reference, e.g. gradle://.?:feature:home@demoDebug.
4. gemini-3.8-live drops immediately on physical release builds App Check rejected an unverified token. Ensure firebase-appcheck-playintegrity is installed and your Play App Signing SHA-256 is registered in Console.
5. adb shell input text drops words after the first space Raw spaces truncate Android text injection, or the field lacks focus. Check "focused" in android layout state and replace spaces with %s.
6. android layout returns empty inside a login or WebView WebViews and custom canvases hide from accessibility trees. Run android screen capture --annotate -o /tmp/s.png, view it, and tap via screen resolve.
7. Firebase MCP exposes unrelated projects or risky writes Pin the workspace with --dir /abs/path and restrict active tool families using --only firestore,auth,dataconnect.
6-Point Pre-Flight Checklist Before Shipping
☐ 1. Scoped MCP & Skills: firebase mcp --dir --only paired with firebase/agent-skills and android init.
☐ 4. Clean Compose Bounds: bounds_url verified for clickable semantics and contentDescription.
☐ 2. Current Models Only: Kotlin calls target gemini-3.8-flash and gemini-3.8-live via BoM 35.1.0.
☐ 5. Delta Deploy Ready: android run --use-delta-install boots cleanly on AVD with sys.boot_completed.
☐ 3. App Check Parity: Debug provider locally; Play Integrity + Console SHA-256 verified for release.
☐ 6. Sequential Journey Pass: All XML <actions> pass in order with a signed-off ✅ Markdown audit.
