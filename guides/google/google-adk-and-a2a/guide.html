Architecture: Vertical Tooling (MCP) vs. Horizontal Delegation (A2A)

The Golden Rule: MCP for Tools, A2A for Peers
Use MCP (MCPToolset) when your agent needs structured functions like querying SQL or reading Git files. Use A2A (RemoteA2aAgent) when delegating a multi-turn goal to another team’s specialist agent that maintains its own memory, reasoning loop, and private secrets.

04 • Deterministic Orchestration Composing LlmAgent with Sequential, Parallel & Loop Controllers

Deterministic Workflow Agents: Zero-Hallucination Control Flow

Asking an LLM router to decide every next step wastes latency and invites skipped checks. ADK separates reasoning nodes (LlmAgent) from deterministic workflow controllers (SequentialAgent, ParallelAgent, and LoopAgent) that execute in predictable code order.

Three Composable Control Topologies: Chain strict stages with SequentialAgent (left), fan out concurrent research with ParallelAgent (center), and iterate draft-critic cycles until quality passes with LoopAgent (right).
1 SequentialAgent
Runs sub_agents strictly one after another. Pair each stage’s output_key="parsed_spec" with {parsed_spec} placeholders in the next agent’s instruction.
2 ParallelAgent
Executes independent sub-agents concurrently in the same session, cutting wall-clock latency when querying docs, logs, and remote A2A peers simultaneously.
3 LoopAgent
Repeats its sub-agents until a reviewer tool sets tool_context.actions.escalate = True or the safety ceiling max_iterations is reached.

Composing All Three Primitives in 18 Lines of Python

from google.adk.agents import LlmAgent, SequentialAgent, ParallelAgent, LoopAgent
from google.adk.tools import ToolContext

def approve_draft(tool_context: ToolContext) -> dict:
    """Call only when the security report meets every citation requirement."""
    tool_context.actions.escalate = True  # Cleanly exits the enclosing LoopAgent
    return {"status": "approved"}

gather = ParallelAgent(name="GatherIntel", sub_agents=[cve_agent, repo_scan_agent])
writer = LlmAgent(name="Writer", model="gemini-2.5-pro",
                  instruction="Synthesize {cve_notes} and {scan_notes}.", output_key="draft")
critic = LlmAgent(name="Critic", model="gemini-2.5-flash", tools=[approve_draft],
                  instruction="Audit {draft}. Request fixes or call approve_draft.")

refine = LoopAgent(name="RefineLoop", sub_agents=[writer, critic], max_iterations=3)
root_agent = SequentialAgent(name="AuditPipeline", sub_agents=[gather, refine])
Distinct Output Keys Inside ParallelAgent
Because all branches of a ParallelAgent share the same active session state, assign each branch a unique output_key (such as cve_notes vs. scan_notes) so concurrent completions never overwrite each other.

05 • State, Guardrails & MCP Scoped State Prefixes, Lifecycle Callbacks & MCPToolset

Scoped State Prefixes, Callbacks & MCPToolset

Production agents need strict boundaries around what persists across turns and which tools are allowed to fire. ADK bakes persistence scopes directly into state key prefixes and wraps every model and tool boundary with synchronous guard callbacks.

1 Four Built-In State Scopes
  • No prefix (state["draft"]): Bound to the current sessionId conversation thread.
  • temp: (state["temp:raw_sql"]): Ephemeral scratchpad wiped automatically when the current invocation turn finishes.
  • user: (state["user:timezone"]): Persists across all sessions belonging to the same authenticated userId.
  • app: (state["app:feature_flags"]): Global read-mostly configuration shared across every user of the application.
2 Six Lifecycle Callback Intercepts
  • before_agent / after_agent: Check tenant quotas, inject trace tags, or redact PII on final responses.
  • before_model / after_model: Short-circuit cached prompts or inspect LLM outputs before tool dispatch.
  • before_tool_callback: Inspect (tool, args, tool_context); return a dict to block execution cleanly without crashing the agent loop.
  • after_tool_callback: Truncate oversized payloads or save binary blobs via tool_context.save_artifact().

Connecting External MCP Servers & Blocking Unsafe Calls

from google.adk.agents import LlmAgent
from google.adk.tools.mcp_tool.mcp_toolset import MCPToolset, StdioServerParameters

def block_destructive_sql(tool, args: dict, tool_context):
    sql = str(args.get("query", "")).upper()
    if any(op in sql for op in ("DROP ", "TRUNCATE ", "DELETE ")):
        return {"error": "Blocked by policy: read-only SELECT queries required."}
    return None  # Returning None allows normal tool execution

db_tools = MCPToolset(
    connection_params=StdioServerParameters(command="npx", args=["-y", "@bytebase/dbhub"]),
    tool_filter=["execute_sql", "list_tables"],  # Expose only approved MCP tools
)
analyst = LlmAgent(name="SqlAnalyst", model="gemini-2.5-flash",
                   tools=[db_tools], before_tool_callback=block_destructive_sql)

06 • Cross-Vendor Interoperability Agent2Agent (A2A) Protocol, Agent Cards & RemoteA2aAgent

Speaking A2A: Agent Cards, Tasks & Cross-Network Handoffs

When your Python ADK orchestrator needs help from a finance team’s Java service or a partner’s LangGraph agent, the Agent2Agent (A2A) standard lets them collaborate over JSON-RPC 2.0 and Server-Sent Events (SSE) using self-describing Agent Cards.

Opaque Peer Collaboration: Each domain keeps its internal prompts, databases, and keys sealed behind its own boundary while exchanging typed A2A Tasks, streaming status events, and structured Artifacts across the bridge.

1. Expose Any ADK Agent via to_a2a()

# server.py — serves /.well-known/agent-card.json
from google.adk.agents import LlmAgent
from google.adk.a2a.utils.agent_to_a2a import to_a2a

billing_agent = LlmAgent(
    name="billing_specialist",
    model="gemini-2.5-flash",
    description="Audits invoices and issues SLA credits.",
    instruction="Verify invoice IDs before credit quotes.",
    tools=[lookup_invoice, calculate_sla_credit],
)
a2a_app = to_a2a(billing_agent, port=8001)
# Run: uvicorn server:a2a_app --host 0.0.0.0 --port 8001

2. Consume a Remote Peer via RemoteA2aAgent

# coordinator.py — zero custom HTTP boilerplate
from google.adk.agents import LlmAgent
from google.adk.agents.remote_a2a_agent import (
    RemoteA2aAgent, AGENT_CARD_WELL_KNOWN_PATH
)

remote_billing = RemoteA2aAgent(
    name="billing_peer",
    description="Delegates invoice & SLA credit checks.",
    agent_card=f"https://billing.internal{AGENT_CARD_WELL_KNOWN_PATH}",
)
root_agent = LlmAgent(
    name="support_lead", model="gemini-2.5-pro",
    sub_agents=[remote_billing],
    instruction="Delegate billing questions to billing_peer."
)

Regression Testing with adk eval & One-Command Deploys

In multi-agent systems, a final answer that sounds polite is still a bug if the agent skipped an authorization tool or called the wrong A2A peer. adk eval grades both the exact tool-call trajectory and the semantic response quality on every pull request.

1 Configure Rubrics in test_config.json

Set strict pass thresholds for both tool sequence accuracy and response similarity:

{
  "criteria": {
    "tool_trajectory_avg_score": 1.0,
    "response_match_score": 0.85
  }
}

Run in CI: adk eval ./support_router tests/refunds.evalset.json --config_file_path=tests/test_config.json --print_detailed_results

2 TypeScript Runner & Zod Tool Pattern

In @google/adk, combine Zod-typed tools with InMemoryRunner inside Vitest suites:

import { LlmAgent, FunctionTool, InMemoryRunner } from "@google/adk";
import { z } from "zod";

const lookupOrder = new FunctionTool({
  name: "lookup_order",
  description: "Fetch order status by ID.",
  parameters: z.object({ orderId: z.string() }),
  execute: async ({ orderId }) => ({ orderId, state: "shipped" }),
});
export const rootAgent = new LlmAgent({
  name: "ops_ts", model: "gemini-2.5-flash", tools: [lookupOrder]
});

09 • Enterprise Governance A2A Authentication, Memory Scoping & Sandbox Safety

Security, A2A Auth & Multi-Tenant Memory Isolation

Connecting autonomous agents across team boundaries multiplies blast radius if identity, memory scopes, or remote Agent Cards are left unverified. Enforce these four enterprise guardrails before exposing any ADK service outside localhost.

1 Authenticated A2A Agent Cards
  • Declare securitySchemes: Publish OAuth 2.0, OpenID Connect, or mTLS requirements directly inside agent-card.json rather than relying on network obscurity.
  • Cloud Run OIDC Service-to-Service: Require IAM invoker tokens between internal Cloud Run A2A peers so rogue workloads cannot call /v1/message:send.
  • Treat Remote Replies as Untrusted: Validate structured A2A payloads against Pydantic or Zod schemas before feeding them into privileged local tools.
2 Prevent Cross-Tenant Memory Poisoning
  • Bind userId from Verified JWTs: Never let prompt text or client JSON body fields supply the userId passed to SessionService or Vertex Memory Bank.
  • Audit app: Writes: Restrict app:* state keys to startup config or admin pipelines; letting user turns mutate app: leaks data globally across tenants.
  • Scrub Secrets into temp:: Short-lived OAuth exchange tokens belong in ToolContext auth handlers or temp:, never persisted in session history.
3 Least-Privilege MCPToolset Filtering

Third-party MCP servers often ship 25+ read, write, and delete tools in one bundle. Always pass an explicit allowlist via tool_filter=["get_ticket", "search_docs"] and pair mutating tools with human confirmation (input-required A2A state or ADK tool confirmation).

4 Bounded Loops & Isolated Code Sandboxes

Always set a low max_iterations (typically 2–4) on every LoopAgent to prevent runaway token bills, and route dynamic Python calculation tasks to Vertex AI Agent Engine’s isolated Code Execution Sandbox instead of host subprocess calls.

Never Forward Raw User Credentials Over A2A Messages
A2A preserves agent opacity in both directions. Exchange scoped, audience-restricted OAuth tokens via protocol headers rather than pasting user API keys or session cookies inside conversational message/send text parts where remote LLM logs would capture them.

Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Diagnose the seven most common ADK and A2A pitfalls in seconds, then run the 6-point pre-flight check before promoting any multi-agent workflow to production.

Symptom / Error 10-Second Root-Cause Fix
1. adk web dropdown shows zero agents Run adk web from the parent directory above your agent package folder, and ensure __init__.py imports agent which defines root_agent.
2. {draft} placeholder raises KeyError in instruction The upstream agent failed or has not set output_key="draft" yet. Initialize default keys in session state or append ? ({draft?}) for optional state interpolation.
3. LoopAgent burns tokens without ever stopping No tool set tool_context.actions.escalate = True and max_iterations was omitted. Always pass max_iterations=3 and expose an explicit exit tool.
4. LLM ignores your Python custom function tool ADK generates tool schemas from type hints and docstrings. Add explicit parameter types, return type dict, and a clear docstring explaining when to call it.
5. RemoteA2aAgent fails on localhost inside Docker agent-card.json advertised http://localhost:8001 instead of the reachable service hostname/HTTPS URL. Pass public host/port or explicit RPC URL to to_a2a().
6. Cloud Run users lose history mid-conversation Default InMemorySessionService lives inside container RAM. Configure --session_service_uri with Cloud SQL Postgres or deploy on Vertex AI Agent Engine.
7. MCPToolset hangs or leaks zombie subprocesses Stdio MCP servers require clean async lifecycle management. Use current google-adk async runner patterns and restrict slow servers via tool_filter.
