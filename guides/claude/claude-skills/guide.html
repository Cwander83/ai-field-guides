04 • Directory Structure & Trigger Engineering YAML Frontmatter Rules & High-Recall Descriptions

Anatomy of a Skill Folder & Trigger Engineering

Until a skill is triggered, Claude cannot see a single line of its Markdown body or scripts—only its YAML name and description. Writing razor-sharp frontmatter is the highest-leverage habit in skill authoring.

Progressive Architecture in Action: A featherlight golden metadata ring stays active at the apex (Level 1), unlocking the faceted SKILL.md tablet (Level 2) and illuminating only the exact vault tool required for the current turn (Level 3).
1 Canonical Directory & YAML Laws
fin-model-audit/
├── SKILL.md            # Required (exact uppercase)
├── scripts/            # Deterministic .py / .sh
├── references/         # Deep docs read on demand
└── assets/             # Templates, logos, fonts
  • name: Lowercase letters, numbers, and hyphens only (<=64 chars, matching folder name; never include reserved words claude or anthropic).
  • description: Required (<=1024 chars, zero XML angle brackets). Write in third person stating both what it does and exact trigger contexts.
  • Optional CLI keys: allowed-tools, user-invocable, or disable-model-invocation: true for manual-only slash workflows.
2 Why Vague Descriptions Fail Silently
Weak (Never Triggers Automatically):
description: Helps with documents and slides.
Too generic—Claude handles everyday text natively and sees no reason to spend tokens opening this skill.
High-Recall (Triggers Reliably):
description: Formats executive .pptx slide decks and board memos using Acme palette, typography, and KPI chart rules. Use whenever the user asks for a presentation, pitch deck, QBR slides, or executive briefing, even if Acme brand is not named explicitly.
Pro Authoring Tip: Make Descriptions Slightly “Pushy” With Concrete Nouns & Extensions
Claude errs on the side of conserving context unless a skill clearly fits. Always name target file extensions (.xlsx, .pptx, openapi.yaml, .sql), domain artifacts (ARR waterfall, SOC2 runbook), and casual user phrasings right inside description.

05 • Instruction Craft & Scripts Lean SKILL.md Bodies & Sandbox Offloading

Lean <500-Line Bodies & Executable Scripts

Once triggered, SKILL.md competes directly with your conversation and code files for attention. Keep SKILL.md crisp, imperative, and under 500 lines—delegating reference tables to references/ and brittle checks to scripts/.

Color-Coded SKILL.md Blueprint Anatomy

[YAML Trigger] [Core Workflow] [Script Delegation] [Reference Pointers] [Verification Gate]
--- name: fin-model-audit | description: Audits .xlsx SaaS financial models, ARR waterfalls, and WACC tabs. Use whenever reviewing spreadsheets, P&L forecasts, or unit economics. ---
## Workflow: 1. Inspect workbook tabs before editing. 2. Preserve dynamic Excel formulas (=SUM, =INDEX/MATCH); never overwrite formula cells with hardcoded floats.
## Conditional References: For SaaS cohort & net-dollar-retention definitions, read references/saas-metrics.md. For board color conventions, read references/formatting.md.
## Deterministic Audit: Run python3 scripts/audit_workbook.py <file.xlsx> to detect #REF!, #DIV/0!, hardcoded totals, or broken cross-sheet links.
## Verification Gate: Do not deliver the workbook until audit_workbook.py exits with code 0 and every assumption cell is styled in blue input font (#0000FF).
1 One-Hop Reference Splitting
  • Never Nest Chains: Link every file directly from SKILL.md (references/aws.md, references/gcp.md). Avoid SKILL.md → cloud.md → aws.md; multi-hop trails cause partial reads.
  • State “Read When” Rules: Tell Claude when to open each file so a BigQuery query never wastes tokens reading Snowflake docs.
  • Add Mini TOCs: Put a 6-line heading list atop any reference file longer than 100 lines so Claude can grep or read target sections cleanly.
2 Offloading Logic to scripts/*.py
  • Execute, Don’t Read: Explicitly write “Run python3 scripts/lint_openapi.py spec.yaml” rather than “See lint_openapi.py” so Claude runs the binary directly.
  • Actionable Error Output: Print exact line/slide/cell numbers on failure (Slide 4 shape 'RevChart' overflows right margin by 0.4in) so Claude fixes errors autonomously.
  • Explain the Why: Replace rigid all-caps shouting with brief rationale; Claude generalizes far better on tricky edge cases when it understands intent.
# Self-contained Level 3 helper pattern (scripts/audit_workbook.py): zero external deps, actionable stdout
import sys, zipfile, xml.etree.ElementTree as ET
# Parses xl/worksheets/*.xml inside .xlsx, flags any cached #REF!, #NAME?, or #DIV/0! formula errors,
# prints exact Sheet!Cell coordinates to stdout, and returns sys.exit(1) so Claude repairs them before delivery.

Iterating With skill-creator & .zip Packaging

Instead of hand-writing boilerplate from scratch, invoke Anthropic’s built-in skill-creator skill. It interviews you, turns messy chat breakthroughs into clean folders, benchmarks trigger accuracy, and packages valid .zip uploads.

1 Capture From a Winning Session

The fastest way to author a great skill is right after you coach Claude through a nuanced task in chat. Prompt: “Use skill-creator to turn the exact workflow, formatting rules, and edge cases we just solved into a reusable skill named qbr-memo.”

2 Guided Interview & Scaffolding

Starting fresh? skill-creator asks targeted questions about trigger phrases, inputs, and failure modes, then generates SKILL.md, extracts deterministic tasks into scripts/, and splits bulky reference tables into references/.

3 Evals & Trigger Benchmarking

In Claude Code or Cowork, skill-creator runs realistic test prompts (with-skill vs. baseline without-skill), grades assertions, measures token/time overhead, and tunes your YAML description against 10+ should-trigger and near-miss queries.

4 Tighten From Execution Traces

Inspect what Claude actually read and ran during tests. If Claude wasted turns reinventing a helper script on every test case, bundle that script permanently inside scripts/; if it ignored a rule, trim competing fluff.

The Golden .zip Packaging Rule for Claude.ai & Claude Desktop Uploads

When uploading a custom skill under Settings → Capabilities → Skills, Claude’s validator requires the skill folder itself at the root of the archive—never loose files and never double-nested parent directories. 

# CORRECT: Zip the skill directory from its parent folder so brand-deck/SKILL.md sits cleanly at archive root
zip -r brand-deck.zip brand-deck -x "*.DS_Store" "*__pycache__*" "*.pyc" "*.git*"
unzip -l brand-deck.zip | head -n 8        # Verify first entry is: brand-deck/SKILL.md
Archive / YAML Mistake What Goes Wrong on Upload Exact Fix
Running zip -r ../out.zip . inside the folder Puts SKILL.md loose at root with no enclosing skill directory; upload rejected. Step up one directory (cd ..) and run zip -r my-skill.zip my-skill/.
Double-nested wrapper (repo/skills/my-skill/SKILL.md) Validator looks one level deep and cannot find SKILL.md. Archive only the immediate my-skill/ folder containing SKILL.md.
Lowercase skill.md or unquoted YAML colon Case-sensitive container misses file or YAML parser fails on description: Note: .... Name file exact uppercase SKILL.md and wrap descriptions containing colons in quotes.

Treating Third-Party Skills Like Executable Code: 4-Point Security Audit

A community skill folder is not passive documentation—it instructs an agent with tool access and bundles runnable scripts. Audit every unfamiliar skill before uploading it or committing it to a shared repository:

Audit Vector Risk to Inspect For Concrete Defense & Verification
1. Bundled scripts/ Hidden network calls (urllib, requests, curl), eval(), or reading ~/.ssh / .env secrets. Read every line of scripts/*; keep helpers pure local file transformers with zero outbound network code.
2. Hidden Prompt Directives Instructions buried in long references/*.md telling Claude to bypass approvals or exfiltrate chat data via URLs. Scan all Markdown files for external URLs, webhook endpoints, base64 blobs, or override phrasing before enabling.
3. Tool Scope Creep Broad unrestricted shell grants in Claude Code when a skill only needs read-only git inspection. Scope allowed-tools tightly (e.g., Bash(python3 scripts/lint.py *)) and enforce hard rules via Claude Code Hooks.
4. Hardcoded Credentials API tokens, internal keys, or customer PII accidentally zipped inside assets/ or example files. Never store secrets in skill folders; pass credentials through authenticated MCP servers or runtime env vars.
Important Boundary Note on allowed-tools vs. System Hooks
In Claude Code, allowed-tools pre-approves scoped tools so trusted skills run smoothly without constant permission prompts—it is a convenience scope, not an OS sandbox wall. Pair untrusted workflows with container isolation and deterministic PreToolUse hooks.

11 • Diagnostics & Launch Readiness Top 7 Issues, 10-Second Fixes & 6-Point Pre-Flight

Troubleshooting Clinic & Pre-Flight Checklist

Nearly every skill issue comes down to YAML trigger phrasing, archive folder nesting, or sandbox toggles. Keep this page beside you when shipping or debugging any custom skill.

Symptom Root Cause 10-Second Fix
1. Skill never triggers automatically YAML description is too vague (“Helps with spreadsheets”) so Level 1 routing skips it. Rewrite description in third person with explicit verbs, domain nouns, and file extensions (“Use whenever reviewing .xlsx models...”).
2. .zip upload rejected in Settings Loose files zipped without a parent folder, lowercase skill.md, or unquoted colon in YAML. Zip from parent dir (zip -r my-skill.zip my-skill/), keep exact uppercase SKILL.md, and quote YAML strings containing colons.
3. scripts/ fail to run or no file output Sandbox container is turned off in user/workspace settings or missing from API call. Toggle Code execution and file creation ON under Settings → Capabilities (or enable code execution tool on the API).
4. Claude skips steps in a huge skill SKILL.md grew past 1,500+ lines, crowding context and causing mid-document instruction drift. Trim SKILL.md below 500 lines; move detailed schemas and examples into 1-hop references/*.md files.
5. Two skills collide on similar prompts Overlapping description scopes make routing ambiguous between two related skills. Carve crisp, mutually exclusive boundaries in each description (e.g., internal postmortems vs. customer-facing status notes).
6. Local skill missing in Claude Code Skill buried two subdirectories deep or saved outside ~/.claude/skills/ or .claude/skills/. Place SKILL.md at exact depth .claude/skills/<name>/SKILL.md and run /skills in Claude Code to verify registration.
7. Python script crashes on ModuleNotFoundError Bundled script imports an obscure PyPI library unavailable inside the offline sandbox container. Write helper scripts against Python’s standard library (json, csv, re, zipfile, xml) or standard preinstalled data packages.
6-Point Pre-Flight Checklist Before Shipping Any Skill
☑ 1. Valid YAML Frontmatter: Exact uppercase SKILL.md opens and closes with ---, hyphenated lowercase name (<=64 chars), zero XML tags.
☑ 2. High-Recall Trigger Prose: description states both what the skill produces and concrete user phrases/extensions that trigger it.
☑ 3. Lean <500-Line Body: Core playbook fits under 500 lines; bulky tables sit 1 hop away in references/ with clear “Read when...” rules.
☑ 4. Deterministic Script Gate: Brittle math, schema validation, or slide/sheet QA runs via scripts/ with actionable stdout errors.
☑ 5. Clean Top-Level .zip: Archive root wraps <skill-name>/SKILL.md cleanly with .DS_Store and __pycache__ excluded.
☑ 6. Tested & Security-Audited: Verified on 3 real prompts + 2 near-misses, zero secrets in assets/, and third-party scripts reviewed line-by-line.
