04 • Connections & Auditable SQL Warehouses, Semantic MCP Layers & Query Inspection

Connecting Warehouses, Semantic Layers & Auditable SQL

Great natural-language analytics starts before the first prompt. Pointing Claude Data at clean analytical schemas and semantic MCP layers eliminates messy raw-table guesswork and sluggish full-table scans.

From Raw Event Chaos to Governed Analytics: Routing warehouse tables through read-only curated marts, semantic MCP servers (Lightdash/dbt), and Certified Queries ensures every chart tile rests on deterministic SQL.
1 Least-Privilege Warehouse Setup
  • Snowflake & Databricks: Grant USAGE and SELECT only on curated ANALYTICS.MARTS schemas—never raw ingestion staging or PII vaults—and attach a 30-second query timeout warehouse.
  • BigQuery & ClickHouse: Enforce partition-filter requirements on large event tables (require_partition_filter = true) so exploratory prompts always bound event_date.
  • Redshift & Salesforce: Pair workload-managed read queues with scoped Salesforce OAuth profiles limited to standard pipeline fields.
2 Why Semantic MCP Layers Change Everything
  • Zero Join Hallucinations: A Lightdash MCP or dbt Semantic Layer exposes pre-tested join paths, dimension hierarchies, and metric YAML directly to Claude.
  • Business Vocabulary Alignment: When a PM asks for “Active Paid Teams,” Claude calls the semantic metric active_paid_workspaces instead of guessing which raw event table counts logins.
  • Instant Telemetry Context: Pair warehouse KPIs with mcp-grafana to correlate revenue dips against API latency spikes.

Provisioning a Safe Read-Only Warehouse Role (Snowflake ANSI SQL Example)

-- Create a dedicated read-only role bounded to curated marts and a small auto-suspend warehouse:
CREATE ROLE IF NOT EXISTS CLAUDE_DATA_READONLY;
GRANT USAGE ON WAREHOUSE ANALYTICS_XS_WH TO ROLE CLAUDE_DATA_READONLY;
GRANT USAGE ON DATABASE PROD_ANALYTICS TO ROLE CLAUDE_DATA_READONLY;
GRANT USAGE ON SCHEMA PROD_ANALYTICS.MARTS TO ROLE CLAUDE_DATA_READONLY;
GRANT SELECT ON ALL TABLES IN SCHEMA PROD_ANALYTICS.MARTS TO ROLE CLAUDE_DATA_READONLY;
GRANT SELECT ON ALL VIEWS IN SCHEMA PROD_ANALYTICS.CERTIFIED TO ROLE CLAUDE_DATA_READONLY;
ALTER WAREHOUSE ANALYTICS_XS_WH SET STATEMENT_TIMEOUT_IN_SECONDS = 45 AUTO_SUSPEND = 60;

06 • Metric Governance Certified Queries & Single Source of Truth

Certified Queries: Ending “Two Numbers for Revenue”

Every fast-growing company hits the same analytics failure mode: Marketing presents $51.2M ARR at 9:00 AM, Finance presents $48.6M ARR at 9:15 AM, and the meeting derails into debugging SQL filters. Certified Queries solve this permanently inside Claude Data.

Why Unvetted Queries Drift

Raw tables mix test workspaces, failed card retries, annual proration quirks, and PST-vs-UTC boundary mismatches that skew totals by 4–9%.

How Certification Works

Data engineering publishes canonical SQL definitions with approved slice parameters. Claude prioritizes Certified Queries whenever those KPIs are asked.

What Viewers See

Charts backed by an unmodified Certified definition earn the green Certified Query badge; ad-hoc overrides drop to Exploratory SQL transparently.

Canonical Certified Query Example (Clean ANSI SQL — Zero Drift)

-- Certified Metric: enterprise_net_dollar_retention_monthly (Owner: Finance & Data Eng • Reviewed Quarterly)
WITH clean_mrr AS (
  SELECT DATE_TRUNC('month', s.snapshot_date_utc) AS report_month, a.customer_id, a.sales_region, a.plan_tier,
         SUM(s.normalized_mrr_usd) AS mrr_usd
  FROM prod_analytics.marts.fct_subscription_daily s
  INNER JOIN prod_analytics.marts.dim_accounts a ON s.account_id = a.account_id
  WHERE a.is_internal_test = FALSE AND a.is_refunded_dispute = FALSE
    AND s.billing_status IN ('active', 'past_due_grace') AND s.snapshot_date_utc = LAST_DAY(s.snapshot_date_utc)
  GROUP BY 1, 2, 3, 4
),
cohort_pair AS (
  SELECT curr.report_month, curr.sales_region, curr.plan_tier,
         COUNT(DISTINCT prev.customer_id) AS retained_customers,
         SUM(prev.mrr_usd) AS start_mrr_12m_ago, SUM(COALESCE(curr.mrr_usd, 0)) AS end_cohort_mrr
  FROM clean_mrr prev
  LEFT JOIN clean_mrr curr ON prev.customer_id = curr.customer_id AND curr.report_month = ADD_MONTHS(prev.report_month, 12)
  GROUP BY 1, 2, 3
)
SELECT report_month, sales_region, plan_tier, retained_customers,
       ROUND(end_cohort_mrr * 12, 0) AS certified_cohort_arr_usd,
       ROUND((end_cohort_mrr / NULLIF(start_mrr_12m_ago, 0)) * 100.0, 2) AS certified_ndr_pct
FROM cohort_pair WHERE start_mrr_12m_ago > 0 ORDER BY report_month DESC, sales_region;

Credential-Safe Live Sharing & Enterprise Governance

Historically, sharing a live AI-generated chart meant either sending dead screenshots or dangerously handing out shared database service-account keys. Claude Data’s Live Sharing architecture separates viewing approved visuals from holding raw database credentials.

1 What Dashboard Creators Can Do
  • Authenticate with their own authorized warehouse OAuth token or read-only analyst role.
  • Write exploratory prompts, inspect schema metadata, iterate on SQL joins, and publish approved tiles.
  • Choose workspace visibility (specific colleagues, Team project, or org-wide link) and revoke live shares at any moment.
2 What Live-Shared Viewers Can (& Cannot) Do
  • CAN: Open the shared dashboard, Scrollyteller, or Visual Short, see fresh approved chart data, toggle pre-built filter controls, and read the Certified badge + timestamp.
  • CANNOT: Inherit the creator’s database credentials, browse underlying warehouse tables, or run arbitrary ad-hoc follow-up SQL unless they authenticate their own warehouse role.

Defense-in-Depth Security Matrix Across Warehouse & Claude Workspace

Governance Layer How to Configure It Correctly Risk Eliminated
1. Read-Only Database Roles Bind connectors exclusively to SELECT-only roles with zero INSERT, UPDATE, DROP, or COPY privileges. Guarantees no prompt can ever mutate, truncate, or alter production warehouse state.
2. Dynamic PII Masking Apply Snowflake Dynamic Data Masking or BigQuery Policy Tags on email, ssn, phone, and billing street addresses. Prevents customer PII from entering chart tooltips, SQL results, or shared executive links.
3. Row-Level Security (RLS) Pass per-user OAuth identity to warehouse row-access policies (or graduate external embeds via Send to Sigma). Ensures regional managers querying directly only scan rows belonging to their assigned territory.
4. Admin Connector Allowlists In Claude Enterprise Admin settings, restrict MCP servers and native connectors to vetted corporate endpoints and SSO groups. Blocks shadow-IT connectors or unapproved third-party MCP servers from touching corporate data.

Warehouse PII Masking Policy Snippet (Snowflake Example)

-- Mask customer email addresses automatically whenever queried by analytical or AI dashboard roles:
CREATE OR REPLACE MASKING POLICY analytics.mask_customer_email AS (val STRING) RETURNS STRING ->
  CASE
    WHEN CURRENT_ROLE() IN ('COMPLIANCE_OFFICER_ROLE') THEN val
    ELSE CONCAT('***@', SPLIT_PART(val, '@', 2))
  END;

ALTER TABLE prod_analytics.marts.dim_users
  MODIFY COLUMN work_email SET MASKING POLICY analytics.mask_customer_email;

Troubleshooting Clinic & Pre-Flight Checklist

Almost every natural-language analytics hiccup comes down to timezone cutoffs, join cardinality, partition filters, or intentional credential boundaries. Keep this page handy before publishing any board.

Top 7 Issues & 10-Second Fixes

Symptom / Failure Mode Root Cause 10-Second Fix
1. Two teammates get slightly different revenue totals One prompt queried raw invoices in local TZ; the other excluded test orgs in UTC. Pin a Certified Query (green badge) and enforce explicit DATE_TRUNC('month', ts_utc) in Project Instructions.
2. Slow 45-second scan or warehouse timeout error Query scanned an unpartitioned multi-billion-row raw clickstream table. Point Claude at pre-aggregated dbt marts or require an explicit partition filter (WHERE event_date >= ...).
3. Viewer blocked from running follow-up SQL on a Live Share Expected security boundary: Live Sharing never delegates creator DB credentials. Add interactive filter dropdowns for common slices, or grant the colleague their own read-only warehouse OAuth role.
4. Global ARR inflated by ~8–15% across regions Multi-currency rows (EUR, GBP, JPY) summed directly without FX conversion. Check Inspect SQL; join dim_fx_rates or query normalized amount_usd columns exclusively.
5. Customer or deal count looks 3× higher than CRM One-to-many fan-out join (for example, joining accounts to invoice_line_items). Open the SQL drawer and replace COUNT(*) with COUNT(DISTINCT a.account_id) or pre-aggregate child CTEs.
6. Dashboard shows yesterday’s pipeline numbers Viewing the last cached execution result from an earlier session. Check the Last Refreshed UTC timestamp in the tile footer and click Refresh to re-execute live SQL.
7. Warehouse or Lightdash MCP missing in sidebar Connector not yet enabled on Enterprise Admin allowlist or OAuth token expired. Have a Workspace Admin enable the connector under Admin Settings → Connectors and re-authorize OAuth.

6-Point Pre-Flight Checklist Before Sharing Any Executive Asset

☑ 1. Green Certified Badge Confirmed

Core company KPIs (ARR, NDR, WAU, Gross Margin) pull from Certified Queries or Lightdash/dbt semantic definitions rather than raw staging tables.

☑ 2. SQL Drawer & Distinct Counts Audited

Opened Inspect SQL on every tile to verify COUNT(DISTINCT ...) guards, normalized USD currency columns, and sandbox exclusions.

☑ 3. Complete Windows & UTC Timestamp Checked

Trend charts plot complete periods (excluding half-finished current weeks unless labeled MTD/WTD) and show a fresh UTC refresh timestamp.

☑ 4. Least-Privilege & PII Masking Active

Connector uses a SELECT-only role with statement timeouts, partition filters, and zero unmasked customer emails or personal identifiers.

☑ 5. Right Format Matched to the Audience

Operators get an interactive Dashboard; Board & leadership get a chaptered Scrollyteller; Slack channels get a 60–90s Visual Short + live link.

☑ 6. Production Graduation Path Chosen

High-traffic prototypes are promoted to Certified Queries or handed off via Send to Sigma, Hex, or Grafana when permanent apps are required.
