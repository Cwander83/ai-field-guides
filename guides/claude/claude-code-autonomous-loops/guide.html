The Three Pillars of Autonomous Claude Code Workflows

Reliable autonomy rests on separating doing the work from judging whether the work is complete. When you trigger /goal, the primary coding model (such as Opus 5.5 or Fable 5.2) edits code and runs tests across multiple turns. After each turn settles, a fast, neutral evaluator inspects the transcript, tool outputs, and workspace state—returning one of four verdicts instead of blindly trusting the worker’s optimism. Meanwhile, claude agents lets you supervise multiple loops concurrently, and Code Artifacts package the finished diff into a live visual walkthrough.

Autonomous Execution & Independent Evaluator Cycle

Why Separate Worker & Evaluator Models Prevent Premature “Done!” Claims
Coding models naturally want to please you after fixing the obvious bug. Because the /goal evaluator only sees your exit criteria and raw command evidence, it catches unverified assumptions, skipped suites, or lingering type errors and automatically triggers the next turn.

04 • Goal Engineering & Spec Architecture Writing /goal Contracts & Goal + Rider Markdown Specs

Engineering /goal Contracts & Goal + Rider Specs

A loop is only as sharp as its exit condition. Vague prompts like “improve performance” confuse the evaluator, whereas concrete contracts backed by a Goal + Rider Markdown pair power hours of disciplined, self-correcting work.

1 How the Evaluator Judges Each Turn
  • Satisfied (PASS): Every named test command, type check, and deliverable file shows explicit passing evidence in tool output.
  • Needs Work (ITERATE): Output shows failing tests, partial diffs, or unverified claims; evaluator sends targeted feedback into the next turn.
  • Blocked / Impossible: Missing API credentials, broken external dependency, or contradictory constraints halt the loop cleanly so you can intervene.
2 The Goal + Rider Pattern
  • Goal File (~4,000-char spine): Ultra-crisp contract passed to /goal—holding the target outcome, read-first paths, exit commands, and stop rules.
  • Rider File (unlimited depth): Detailed spec committed in .claude/goals/<slug>-rider.md with phased steps, SQL/API schemas, edge cases, and non-goals.
  • Phased Commits: Instruct the loop to commit after each passing phase so /rewind or git reset never loses progress.
# Invoke /goal referencing a concise contract + deep committed Rider spec
/goal Read .claude/goals/webhook-rider.md first. Implement Phases 1-3 on this worktree, commit after each green phase, and stop only when pnpm test:webhooks, pnpm typecheck, and pnpm lint all exit 0 with zero skipped tests.
Continuous Execution Meets Deterministic Verification: Every coding turn spins through the crimson execution ring, passes across the neutral sapphire evaluator gate to verify real command outputs, and advances to the emerald completion beacon only when zero exit conditions remain unmet.

05 • Contract Anatomy & Anti-Patterns The 5 Building Blocks of a Bulletproof /goal Spec

Anatomy of a Bulletproof /goal & Rider Contract

Whether you write a one-line /goal command or a multi-phase Rider file, packing these five color-coded clauses eliminates drift, endless loops, and silent corner-cutting.

[1. Target Outcome] [2. Verifiable Exit Gate] [3. Boundary / Non-Negotiables] [4. Checkpoint / Commit Cadence] [5. Escalation / Impossible Stop Rule]
/goal Migrate all legacy REST billing endpoints in src/routes/v1/billing/ to idempotent Zod-validated handlers following .claude/goals/billing-rider.md. Exit gate: npm run typecheck, npm run lint, and npm test -- billing all run fresh after the final edit and exit 0 with 100% pass rate. Non-negotiables: do not skip, delete, or weaken existing assertions; do not touch src/routes/v2/ or production env files. Create a clean git commit after each endpoint passes its integration test suite, and summarize changed files at the end. If Stripe sandbox credentials are missing or a schema migration requires manual DBA approval, mark the goal blocked/impossible immediately and list the exact gap.

Vague Goals vs. Evaluator-Ready Contracts

Weak / Flaky /goal Why the Evaluator Struggles Hardened Replacement
“Refactor the auth module to be cleaner.” No objective pass signal; evaluator either passes too early or loops forever nitpicking style. “Split auth.ts into session.ts and jwt.ts per auth-rider.md; all 28 unit tests and tsc --noEmit pass.”
“Fix the flaky CI test.” Passing once by luck fools the loop unless stress repetition is required. “Eliminate race condition in checkout.spec.ts; run npx playwright test --repeat-each=10 with 0 failures.”
“Make the dashboard load faster.” “Faster” cannot be checked without a baseline metric and benchmark script. “Reduce dist/app.js bundle under 180 KB gzipped and keep npm run build && npm test green.”
Rider Sizing Rule: Keep the /goal Spine Under ~4,000 Characters
Because the evaluator re-reads your /goal contract on every turn, keep the active goal string compact and link to your detailed Rider Markdown file on disk. That saves evaluator tokens and ensures critical non-negotiables never get truncated.

Parallel Fleet Supervision & Safe Session Navigation

Long autonomous runs shine when you parallelize cleanly and recover fearlessly. Combining specialist .claude/agents/, /subtask, claude agents, and atomic /rewind lets one engineer direct an entire squad of isolated workers.

A Fleet Orchestration: claude agents & /subtask
  • Project Personas (.claude/agents/): Define scoped subagents (e.g., reviewer.md, migrator.md) with explicit model tiers and allowed tools.
  • /subtask Delegation: Offload verbose log searches or test shards so raw 20k-token stack traces never pollute your primary /goal context.
  • claude agents Dashboard: Inspect every background worker across worktrees from one terminal UI, or run claude agents --json --all for CI polling.
B Safe Navigation: /resume, /fork, /branch, /rewind
  • CLI-to-Desktop /resume: Kick off three loops from your terminal, then call /resume inside Claude Code Desktop to inspect diffs and file trees visually.
  • /fork vs. /branch: Use /fork to spawn a background side-experiment while staying put; use /branch <name> when you want to switch into the new fork immediately.
  • Atomic /rewind (Esc + Esc): Rolls back both conversation turns and Claude’s file edits in lockstep to any prior checkpoint.

Anatomy of a Reusable Verifier Persona in .claude/agents/test-verifier.md

---
name: test-verifier
description: Neutral test and type-check runner invoked by /goal loops via /subtask
model: opus-5.5
tools: Read, Grep, Glob, Bash
---
Run only read-only checks and test commands. Never modify source files or add .skip/.only flags.
Return exact exit codes, failed test names, and minimal stack lines back to the parent session.
Pro Recovery Playbook: When a /goal Loop Drifts on Turn 8
Never argue with an autonomous loop that has filled 70% of its context window with broken attempts. Hit /goal clear, run /rewind back to Turn 3 (where the baseline was clean), tighten one constraint in your Rider file, and relaunch /goal with fresh context.

09 • Safety, Budgets & Anti-Cheating Rules Guardrails for Long-Running Autonomous Loops

Guardrails for Long-Running Autonomous Loops

Giving an agent thirty turns of autonomy demands engineering discipline. Without hard spend limits, isolated worktrees, and anti-cheating rules, an eager model can burn budget, mutate shared branches, or quiet a failing test by relaxing assertions.

🛡 Four Hard Boundaries Every Loop Needs
  • Always Isolate Disk State: Launch unattended runs with claude --worktree so uncommitted edits never collide with your main checkout.
  • Cap Spend & Turns: Pass --max-budget-usd (or turn limits) on every headless or overnight run so a stubborn bug cannot spin endlessly.
  • Ban Test Dilution: State explicitly in both CLAUDE.md and your Rider: zero .skip, zero lowered coverage thresholds, zero mocked-away failures.
  • Sandbox Secrets & Prod: Deny production database URLs and force-pushes via Claude Code permissions or sec-default mods.
! Catching Subtle Loop Failure Modes
  • Silent Mock Relaxation: If a worker edits a test expectation just to make Jest pass, your evaluator prompt and PR diff check must reject the turn.
  • Context Poisoning: After 10+ failed compile logs, context quality degrades. Use /subtask for noisy runs and /rewind if the main thread gets stuck.
  • Unverified “Should Pass” Claims: Require fresh post-edit command execution—never allow the loop to cite a test run from three edits ago.
  • Human Merge Gate: Autonomous loops open drafts and Code Artifacts; humans approve merges to main.

Drop-In Safety Clauses for Your Repo’s CLAUDE.md

## Autonomous /goal Loop Policy
1. Never add .skip, .only, @pytest.mark.skip, or relaxed assertions to make a /goal check pass.
2. Always run the full target test and typecheck commands AFTER your final file edit before finishing.
3. Commit working milestones per phase; never push directly to main or run destructive database resets.
4. If external secrets, staging access, or ambiguous product decisions block progress, halt and report BLOCKED.
Pair Loops With Deterministic Hooks or Mods for 100% Enforcement
Prompt rules inside CLAUDE.md cover 95% of cases, while deterministic pre-tool hooks (blocking git push --force or edits to .env.production) make critical boundaries unbreakable even on turn twenty.

11 • Diagnostics & Launch Readiness Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Almost every autonomous loop hiccup stems from ambiguous exit criteria, noisy context buildup, or missing environment isolation. Keep this ten-second triage table beside your terminal before kicking off unattended runs.

Symptom / Failure Root Cause 10-Second Fix
1. Evaluator stops early and declares PASS on broken code /goal lacked an explicit command check (e.g., only said “finish refactor”). Include exact shell exit gates (npm test && tsc --noEmit) and require fresh output after the final edit.
2. Loop repeats the exact same failing edit across turns Context window is saturated with stale error logs or conflicting hypotheses. Run /goal clear, hit /rewind to the last green checkpoint, add the missing clue to your Rider, and restart.
3. Main session hits 80% context after two test runs Full build/test stdout was printed straight into the parent conversation. Delegate test execution through /subtask using a read-only .claude/agents/ verifier that returns only failures.
4. Loop immediately halts with BLOCKED / IMPOSSIBLE Missing .env secrets, offline dependency, or contradictory constraint in Rider. Inspect the evaluator’s gap report, supply the sandbox env var or relax the conflicting rule, and re-arm /goal.
5. Two parallel loops overwrite each other’s files Both sessions launched in the same working tree instead of isolated Git worktrees. Always start parallel sessions with claude --worktree <task-name> and track them in claude agents.
6. Worker silenced a failing test to pass the gate No anti-dilution guardrail in CLAUDE.md or /goal non-negotiables. Add “zero .skip/weakened assertions” to CLAUDE.md, review /diff in Desktop, and /rewind the cheat turn.
7. Published Code Artifact shows outdated diff or logs Additional commits landed after the artifact was first generated. Run a quick follow-up prompt asking Claude to sync the existing Code Artifact with current HEAD and test results.

6-Point Pre-Flight Checklist Before Launching an Autonomous /goal Loop

✓
Isolated Worktree Active: Launched with claude --worktree <slug> on a clean base commit.
✓
Budget & Model Sized: Selected Opus 5.5 (or Fable 5.2 High effort) with --max-budget-usd set.
✓
Compact Goal + Deep Rider: Kept /goal under ~4,000 chars and moved phased detail into .claude/goals/.
✓
Objective Exit Gate Set: Named exact test, lint, and type-check commands that must pass after final edits.
✓
Anti-Cheating Rules Pinned: Disallowed .skip, deleted assertions, or unapproved dependency changes.
✓
Review & Artifact Plan Ready: Configured claude agents monitoring, Desktop /resume diff check, and final Code Artifact export.
