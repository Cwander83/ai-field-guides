1 Baseline Prerequisites
  • Remote Connectors: A TLS-terminated HTTPS endpoint exposing /mcp (Streamable HTTP or SSE) plus OAuth 2.1 metadata or static Bearer headers.
  • Cloud Managed Agents: Anthropic Console API key, declared Environment ID, and Vault IDs for authenticated MCP calls.

04 • Core Workflow: Brain / Hands Decoupling Long-Lived Loops Without DIY Agent Harnesses

Decoupling the Brain From the Hands

Building your own production agent loop looks simple on day one—until timeouts, partial tool errors, context compaction, and shell escapes break in production. Managed Agents separate the durable cognitive loop from isolated execution workspaces.

Architectural Separation: The cognitive loop reasons above a strict trust boundary, dispatching deterministic tool commands down to disposable sandbox containers while keeping secrets and session state safely isolated.
1 What the “Brain” Owns (Control Plane)
  • Multi-Turn Loop Management: Streams model responses, parses tool calls, handles exponential backoff on transient 429/5xx errors, and enforces max-turn budgets.
  • Session Checkpointing: Writes every message, tool request, and artifact pointer into durable storage so clients can disconnect and resume hours later.
  • Context Compaction: Summarizes stale tool outputs automatically when long investigations approach context limits without losing active goals.
2 What the “Hands” Own (Sandboxes)
  • Disposable Workspaces: Each session boots inside an isolated container with scratch disk for cloning repos, running tests, and compiling reports.
  • Blast-Radius Containment: A runaway rm -rf or malformed Python package affects only that ephemeral container—never the control plane or sibling tenants.
  • Network Egress Rules: Lock outbound container traffic to explicit package registries or DENY_ALL so untrusted scripts cannot phone home.
Why You Should Stop Writing Custom while True Tool Loops
A DIY harness must implement prompt caching, streaming SSE recovery, tool-timeout interrupts, human-in-the-loop pause/resume, and sandbox cleanup. Managed Agents bundle all five behind four clean primitives: Agents, Environments, Vaults, and Sessions.

06 • Remote MCP Connectors & OAuth Vaults Connecting https://.../mcp Safely Across Surfaces

Remote HTTPS/SSE Connectors & OAuth Vaults

Remote MCP moves integrations off local laptops onto standard https://.../mcp endpoints. Combined with OAuth 2.1 and Vaults, one connector works seamlessly across Claude Web, Mobile, Cowork, and headless Managed Agents.

Zero-Trust Credential Brokering: The frosted cryptographic gatehouse exchanges scoped OAuth tokens for outbound https://.../mcp calls while long-lived secrets remain locked inside the Vault—never exposed to the sandbox.
1 Four Remote Auth Patterns
  • OAuth 2.1 + PKCE & PRM: Server publishes Protected Resource Metadata (.well-known/oauth-protected-resource) so Claude discovers scopes automatically.
  • Dynamic Client Registration (DCR): RFC 7591 lets Claude register as an OAuth client dynamically without manual admin client-ID copying.
  • Enterprise IdP Token Exchange: Org admins federate Okta/Entra ID so employees inherit scoped access silently without 10 separate login popups.
  • Static Bearer / Vault Headers: For machine-to-machine services, store the API key inside a Vault credential rather than pasting headers in plaintext.
2 Transport & Reachability Checklist
  • Streamable HTTP First: Prefer MCP’s modern Streamable HTTP (POST /mcp with optional SSE stream) over legacy dual-endpoint SSE for cleaner load balancing.
  • Disable Proxy Buffering: On Nginx, Cloudflare, or ALB, disable response buffering on /mcp so streaming tool progress never stalls until timeout.
  • Firewall & Private Mesh: Cloud connectors require public HTTPS or Anthropic IP allowlisting; self-hosted cma-server reaches private VPC /mcp servers directly.
Cross-Surface Payoff: Connect Once, Use Everywhere
Adding a custom connector under Settings → Connectors → Add Custom Connector makes that authenticated https://.../mcp server instantly usable from desktop, web browsers, and mobile Claude apps—no Node.js or Python setup on user devices.

07 • Enterprise VPC Deployment Self-Hosting cma-server With PostgreSQL & Multi-Cloud Inference

Self-Hosting cma-server in Your VPC

Regulated industries and teams with internal-only microservices can run the entire Managed Agents control plane inside their own Kubernetes cluster or VPC using cma-server—retaining 100% session sovereignty.

1 PostgreSQL 16+ Persistence

Without a database, cma-server falls back to volatile memory and wipes sessions on restart. Production clusters wire CMA_STORE__DATABASE_URL to PostgreSQL 16+ so agent specs, turn checkpoints, and audit trails persist durably across pod rollouts.

2 Control & Listen Connections

High-throughput deployments configure dedicated CMA_STORE__CONTROL_DATABASE_URL (heartbeats and maintenance) and CMA_STORE__LISTEN_DATABASE_URL (PostgreSQL LISTEN/NOTIFY events). Avoid transaction-mode poolers like PgBouncer on the listener URL.

3 Inference Gateway Routing

Route model calls out of cma-server directly to Anthropic API, Amazon Bedrock, Google Cloud Vertex AI, Microsoft Foundry, or an internal LiteLLM/Envoy proxy for unified spend caps, PII scrubbing, and regional failover.

4 Horizontal Scaling & Failover

Because session state lives in PostgreSQL rather than pod RAM, run 3+ stateless cma-server replicas behind an internal load balancer. If one node crashes mid-turn, another replica resumes the exact event stream seamlessly.

09 • Security & Context Efficiency Blast-Radius Containment, Prompt Injection Defense & Schema Hygiene

Security, Blast-Radius Containment & Schema Hygiene

Connecting autonomous agents to live company systems introduces two distinct risks: oversized blast radii if a tool mutates data unchecked, and indirect prompt injection hidden inside external tickets, PR comments, or database rows.

Read vs. Write Gates

Separate read tools (get_*, search_*, query_*) from write tools (delete_*, merge_*, send_*). Auto-approve reads so agents move fast, and enforce human confirmation on every external state change.

Anti-Tool-Poisoning

Treat every third-party MCP tool description and returned payload as untrusted data. Pin vetted server versions, strip hidden HTML/markdown instructions, and never mix untrusted web-scrape tools with privileged write keys in one session.

MCP Schema Hygiene

Every MCP tool injects its JSON schema into the system prompt (~150–300 tokens each). Loading 60 tools wastes 12,000+ tokens before Turn 1 and lowers accuracy. Filter each agent down to 5–15 sharp tools.

Four-Layer Defense Matrix for Production MCP Deployments

Threat Vector Failure Mode Without Controls Managed Agents + MCP Defense
1. Secret Exfiltration via Bash Prompt-injected code inside sandbox prints env or curls API tokens to an attacker host. Store tokens in server-side Vaults (never container env vars) and lock sandbox networking to allowed_hosts.
2. Indirect Prompt Injection Malicious text inside a Jira ticket tells the agent to export customer emails via Slack MCP. Require confirmation gates on outbound/write tools and scope OAuth tokens strictly to least-privilege read scopes.
3. Tool Poisoning / Rug Pulls An external MCP server silently mutates its tool description after approval to hijack model behavior. Audit remote servers before allowlisting, pin verified internal gateways, and alert on unexpected tool schema diffs.
4. Context Bloat & Wrong Tool Pick Connecting 5 full SaaS servers dumps 80 overlapping tools, burning tokens and causing hallucinated parameters. Split into specialized role agents (Triage vs. Finance) and allowlist only exact needed tool names per agent.
Never Bridge Untrusted Public Inputs With Unattended Admin Write Scopes
If an agent reads public GitHub issues, incoming support emails, or arbitrary web pages, assume adversarial text will arrive. Keep that session’s Vault tokens read-only or gate every write action behind human approval.

11 • Diagnostics & Launch Readiness Top 7 Issues, 10-Second Fixes & 6-Point Pre-Flight

Troubleshooting Clinic & Pre-Flight Checklist

Most Managed Agent and Remote MCP snags come from proxy buffering, OAuth redirect URIs, PgBouncer listener pooling, or bloated tool lists. Use this quick clinic to diagnose and resolve issues in seconds.

Symptom Root Cause 10-Second Fix
1. Remote /mcp hangs or times out Reverse proxy (Nginx/ALB/Cloudflare) buffers SSE chunks instead of streaming immediately. Disable proxy buffering on /mcp (e.g., proxy_buffering off;) and set idle timeouts above 300s.
2. OAuth handshake fails on connect Missing .well-known PRM metadata, strict redirect mismatch, or blocked DCR endpoint. Verify RFC 9728 metadata, allowlist Claude’s OAuth callback URL, or supply custom OAuth client credentials.
3. cma-server loses sessions on restart CMA_STORE__DATABASE_URL unset, causing fallback to ephemeral in-memory store. Point CMA_STORE__DATABASE_URL to PostgreSQL 16+ and confirm schema migrations succeed at boot.
4. DB event listener disconnects randomly CMA_STORE__LISTEN_DATABASE_URL routed through a transaction-mode PgBouncer pooler. Connect LISTEN_DATABASE_URL directly to PostgreSQL (or session-mode pooler) so LISTEN/NOTIFY stays open.
5. Sandbox bash fails to hit internal API Sandbox egress policy blocks outbound calls, or developer tried calling Vault secrets inside bash. Route private API access through server-side /mcp + Vault instead of container scripts; allowlist only package hosts.
6. Agent picks wrong MCP tool or stalls Too many overlapping tool schemas (50+) bloat prompt context and confuse parameter selection. Trim mcp_toolset down to 5–15 sharp tools per agent and write crisp single-purpose parameter descriptions.
7. 401/403 from Bedrock, Vertex, or Foundry Expired cloud IAM role, missing region quota, or mismatched model ID mapping in router. Verify cloud IAM/OIDC permissions, confirm model availability in target region, and test gateway health endpoint.
6-Point Pre-Flight Checklist Before Shipping Any Managed Agent
☑ 1. Zero Secrets in Blueprints: Agent JSON/YAML lists only https://.../mcp URLs; all tokens live inside Vaults.
☑ 2. PostgreSQL 16+ Wired: Self-hosted cma-server points to durable PostgreSQL with direct listener connectivity.
☑ 3. Tight Sandbox Egress: Container environment locks outbound traffic to exact allowed_hosts or DENY_ALL.
☑ 4. Read/Write Gates Active: Mutating, merging, billing, or external messaging MCP tools pause for human sign-off.
☑ 5. Lean Tool Budget (≤15): Redundant MCP tools are filtered out so schema overhead stays crisp and accurate.
☑ 6. Streaming & Auth Tested: Verified unbuffered /mcp SSE/HTTP responses, OAuth token refresh, and provider failover.
