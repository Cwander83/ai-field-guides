Proactive Coordinator & Parallel Branch Reconciliation

Instead of manually juggling five terminal tabs and copying diffs by hand, the Proactive Coordinator acts as your automated tech lead—fanning tasks across isolated cloud Claude Code sessions and bringing cleanly reconciled branches back to one thread.

Fan-Out to Isolated Branches, Converge at Verification: Each cloud worker gets its own repository clone and dedicated Git branch so parallel builds never collide on disk before branch diff reconciliation.

The 4-Stage Coordinator Dispatch & Reconciliation Flow

1 Task Scoping & File Partitioning

Read your Project specs and ask the Coordinator to split work into non-overlapping modules (for example: Worker A owns src/api/billing/, Worker B owns src/components/checkout/, Worker C owns tests/e2e/).

2 Full Cloud Worker Sessions

Every dispatched worker is a complete cloud Claude Code instance—not a toy text helper. It reads files, runs compilers, executes Playwright or unit tests, and commits checkpoints to its own Git branch.

3 Proactive Progress & Q&A Loop

Workers notify the parent Coordinator whenever a milestone finishes or a spec ambiguity appears. You answer once in the main thread, and the Coordinator relays your decision directly to the blocked worker.

4 Branch Aggregation & PR Conflicts

Once workers pass local checks, the Coordinator aggregates branch diffs into a unified review. If two workers touched the same shared interface, overlaps surface as standard Git PR merge conflicts for crisp resolution. 

Coordinator Dispatch Example (Claude Code Project — Fable 5.2):
"Split our Stripe Subscription Pause feature across 3 parallel cloud workers on isolated branches:
1) Worker A (feat/pause-api): Add POST /v1/subscriptions/pause + webhook handler in src/api/billing/. Run pytest -k billing.
2) Worker B (feat/pause-ui): Build PauseModal.tsx in src/ui/settings/ matching our Design tokens. Run npm run typecheck.
3) Worker C (test/pause-e2e): Write Playwright happy-path & double-click idempotency specs once A & B expose route types.
Push proactive updates only on blockers or test completion, then reconcile branch diffs into one staging PR."
Pro Tip: Partition Shared Interfaces First to Avoid Merge Conflicts
When two workers depend on one TypeScript interface or OpenAPI schema, have Worker A lock and commit the contract file first (or define it in your parent prompt) before Worker B and Worker C branch out.

Context Hygiene: /btw, /fork, /rewind & Directive Anatomy

Multi-hour coding sessions fail when tangential questions, dead-end refactors, and raw stack traces pollute the Coordinator’s context window. Keep your primary timeline razor-sharp with four dedicated context-hygiene controls.

1 /btw Zero-Pollution Side Threads

Need to ask “What flag resets Alembic migrations?” without derailing an active multi-branch build? Type /btw <question>. Claude spins an ephemeral side thread using read-only Project awareness and answers instantly—leaving zero tokens inside your Coordinator or worker history.

2 /fork Divergent Experiments

Want to test Redis caching vs. SQLite edge caching without ruining a clean working thread? Run /fork to branch the conversation at the current checkpoint, benchmark both approaches side by side in the Session Rail, and keep only the winning branch.

3 Project Reminders & Diagnostic Links

Pin built-in Project reminders so rules like “always run uv test before commit” survive resets automatically. When a worker hits a tricky failure, generate a read-only diagnostic thread link so teammates can inspect logs safely without touching your repo.

4 /rewind & /clear Policy Recovery

Press Esc twice or run /rewind to revert both chat turns and native file-edit snapshots cleanly (remember: raw shell/bash side effects require Git reset). Between finished epics, run /clear to wipe stale history while automatically keeping CLAUDE.md policies intact.

Background MCP Tasks & Live Jupyter Notebook Cell Sync

Slow integration test suites, warehouse exports, and interactive data notebooks no longer hold your terminal hostage. Background MCP routing and real-time Jupyter cell sync let engineering and data exploration run smoothly side by side.

Clean Branching & Non-Blocking Execution: Side investigations (/btw) and divergent forks (/fork) stay cleanly separated from the main timeline while Background MCP tasks stream live progress rings to the Session Rail HUD.
1 Background MCP Tasks (Non-Blocking)
  • Automatic Async Offload: When a connected MCP server triggers a long-running operation—such as a cloud container build, BigQuery warehouse export, CI test matrix, or game-engine asset import—Claude Code moves it to the Background MCP Tray inside the Session Rail HUD.
  • Keep Coding While It Runs: Your local terminal, VS Code editor, and Coordinator chat stay completely responsive so you can review diffs, answer worker questions, or edit docs in parallel.
  • Completion Notification: Once the MCP job resolves, the Coordinator receives a concise summary payload and resumes the dependent step automatically.
2 Jupyter Notebook Cell Sync & Kernels
  • Beyond Brittle JSON Edits: Historically, editing .ipynb files as raw JSON stripped cell execution counts or caused merge headaches inside open browser tabs.
  • Live Kernel + IDE Sync: Pairing NotebookEdit with IDE/JupyterLab session-rail extensions and the Jupyter MCP server lets Claude attach directly to your running IPython kernel, execute targeted cells, inspect pandas frames or tracebacks, and hot-sync updated cell outputs straight into VS Code or JupyterLab.
  • Safe Branch Testing: Fork ML experiments with /fork while keeping baseline notebook checkpoints recoverable via /rewind.
Golden Habit: Keep Background MCP Logs Compact

Configure custom MCP servers and build wrappers to return structured summaries (status, duration, artifact URL, and the final 20 lines of any failure trace) rather than streaming 10,000 lines of raw compiler noise back into the Coordinator thread. Use read-only diagnostic links whenever a teammate needs to inspect the full verbose build trace.

07 • Runtime Security, Gateway & Privacy Expanded Auto-Mode Controls & Client-Identity Safeguards

Expanded Auto-Mode Gateway & Client-Identity Safeguards

Giving autonomous cloud workers and MCP tools room to move fast requires guardrails that stop dangerous commands and block subtle privacy leaks. November 2026 releases pair expanded Auto-Mode gateway policies with strict client-identity protections.

1 Expanded Auto-Mode Gateway Controls
  • Smart Classifier Middle Ground: Launch with claude --enable-auto-mode (or toggle mid-session via Shift+Tab). Instead of approving every trivial read or running completely unchecked, a background safety classifier audits each tool call before execution.
  • Gateway Rules & Tool Escalation Blocks: Tune project rules via /auto-mode-setup and inspect baseline policies with claude auto-mode defaults. Expanded gateway checks intercept indirect prompt injections—stopping untrusted web docs from tricking Claude out of safe WebFetch into raw curl shell scripts.
  • Soft vs. Hard Denials: Routine workspace tests auto-approve cleanly, risky commands pause for explicit human review, and forbidden operations hard-fail with clear audit explanations.
2 Client-Identity & Email Leak Safeguards
  • Why It Matters (v2.1.325+): Earlier coding harnesses injected the signed-in user’s account email into prompt context, causing models to inadvertently embed personal emails inside automated User-Agent headers, API calls, or generated scripts.
  • Hard Identity Boundary: Current Claude Code builds actively scrub personal account emails from model context and block using user account emails as client identity across shell scripts, web fetches, file writes, and outbound MCP requests.
  • Clean Telemetry & Attribution: Enterprise gateways use organization-assigned service headers or explicit Git author settings—never leaking private developer emails to third-party servers.

Always remember the boundary: Auto-Mode classifiers dramatically reduce risk for everyday repos, yet they do not replace OS/container isolation. Keep untrusted third-party code inside cloud Claude Code worker VMs and store real OAuth tokens inside Vault-backed remote MCP servers rather than local shell environment files.

Critical Recovery Boundary: Understand What /rewind Can and Cannot Undo

/rewind (or Esc + Esc) atomically reverts conversation messages and edits made through Claude’s native file tools (Edit, Write, NotebookEdit). However, it cannot undo external shell side effects (such as sed -i scripts, database drops, or external API POSTs). Run risky experiments inside isolated cloud worker branches where discarding a bad branch costs zero cleanup.
