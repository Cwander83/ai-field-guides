Cloud Remote Sessions vs. Local Desktop Reach

When a Cowork task relies on web connectors (Gmail, Slack, Notion, HubSpot, Drive) or research, it runs inside an encrypted cloud remote session—so you can start it from your phone or close your laptop lid while Claude finishes. Whenever a task needs files in a mounted local folder or native macOS apps without APIs, Claude Desktop executes locally using scoped permissions and Background Spaces.

Plan Tiers, macOS Grants & Ecosystem Decision Matrix

Cowork and Computer Use span Pro, Max, Team, and Enterprise subscriptions, pairing cloud remote execution with explicit, revocable macOS permissions whenever local files or desktop windows are involved.

1 Subscription Tiers & Execution Modes
  • Pro & Max Plans: Full Cowork access, cloud remote sessions, Chrome extension tasks, and macOS Computer Use (Max provides higher continuous task quotas).
  • Team Plan: Shared workspace connectors, team-approved MCP catalogs, and zero model training on work inputs or outputs.
  • Enterprise Plan: Org Owner/Primary Owner governs Computer Use, local folder mounts, and external MCP allowlists with SSO and audit logs.
  • Cloud vs. Local Rule: Cloud sessions survive closed laptops and mobile handoffs; local mounts & macOS UI automation require Desktop open and awake.
2 60-Second macOS Permission Setup
  1. Install Claude Desktop for macOS and toggle on Cowork & Computer Use inside Settings → Capabilities.
  2. Open System Settings → Privacy & Security → Screen & System Audio Recording and enable Claude (lets Claude read background app state).
  3. Open Privacy & Security → Accessibility and enable Claude (grants isolated click and keystroke dispatch).
  4. Grant per-task Local Folder Mounts only to dedicated working directories like ~/Documents/Invoices—never root ~/.
One-Minute Check: Cloud Remote Session vs. Local Desktop Execution
Ask yourself one question before hitting Run: “Does this task touch a folder on my hard drive or a native macOS app?” If No (Gmail, Drive, Slack, HubSpot, web portals), Claude runs in a Cloud Remote Session you can monitor from your phone. If Yes, keep your Mac awake and mount only the exact folder needed.

04 • Core Workflows: Execution Waterfall MCP Connectors → Built-In Browser → Computer Use

Mastering the 3-Tier Tool Hierarchy

Great Cowork operators think in layers. Rather than asking Claude to click around your screen for data that already lives behind a clean API, you guide workflows through a cascading waterfall: structured MCP pipes first, browser lenses second, and desktop pixels third.

Top-Down Precision Waterfall: Tier 1 MCP connectors deliver instant structured JSON; Tier 2 built-in browser handles authenticated portals; Tier 3 Computer Use steps in only when native desktop UI interaction is mandatory.
1 Tier 1: MCP Connectors

First stop for SaaS systems of record. Zero screen parsing, full pagination, and cloud remote compatibility.

Native roster: Slack, Gmail, Google Drive, Microsoft 365, HubSpot, QuickBooks, Canva, Jira & Notion.

2 Tier 2: Built-In Browser

Steps in when a vendor portal, HR dashboard, or supplier invoice site has no MCP API.

Two flavors: Cowork’s built-in sandbox browser, or Claude in Chrome reusing your live session cookies.

3 Tier 3: Computer Use

The tactile fallback for local macOS apps, custom Finder moves, or legacy desktop software.

Key strength: Operates inside a background macOS Space so you keep working uninterrupted.

Always State Connector Preference in Multi-App Tasks
When a workflow touches both SaaS and desktop apps, explicitly name your Tier 1 connectors: “Read messages via Slack MCP and pull slides from Google Drive MCP; only open Chrome if a vendor link requires portal login.” That one sentence cuts task runtime by up to 80% and prevents unnecessary screen captures.

05 • Core Workflows: Prompt & Scope Design 5-Part Cowork Task Anatomy & Folder Mount Patterns

Prompt & Task Anatomy + Scoped Folder Mounts

Vague prompts like “clean up my invoices” invite guesswork. Combining five explicit building blocks—Goal, Scope, Connectors, Fallback, and Confirmation Gate—gives Claude crystal-clear guardrails on the very first run.

The 5-Part Cowork Task Anatomy

[1. Goal & Deliverable] Reconcile all March contractor invoices into a clean reconciliation CSV and draft summary email. [2. Scope / Folder Mount] Read and write strictly inside the mounted ~/Finance/March_Recon folder. [3. Preferred Connectors] Pull invoice attachments via Gmail MCP and match vendor IDs against QuickBooks MCP. [4. Browser / Desktop Fallback] If a portal link lacks an attachment, download the PDF via Claude in Chrome; use macOS Preview only for scanned OCR. [5. Confirmation Gate] Pause and show me a line-item summary before posting any QuickBooks bills or sending the CFO email.
Task Component What It Governs During Execution Risk When Left Unspecified
Goal & Deliverable Defines exact output artifact (CSV, Slack digest, Jira ticket batch, renamed files). Claude stops mid-way or produces chat prose instead of saved files.
Scope / Folder Mount Restricts local filesystem reach to one dedicated working directory. Broad mounts risk scanning personal docs or writing to wrong folders.
Preferred Connectors Pins Tier 1 MCP APIs (Slack, Drive, M365, Notion, Jira) before touching browsers. Slow pixel clicking inside a web app when an instant API exists.
Browser / Desktop Fallback Names exact Tier 2 portal or Tier 3 macOS app permitted when APIs fall short. Claude aborts at the first login wall or guesses the wrong local app.
Confirmation Gate Forces a hard pause before payments, sends, deletes, or production writes. Unreviewed batch actions dispatch before you verify edge cases.

Three Proven Local Folder Mount Patterns

A The Quarantine Drop-Box

Mount only ~/Cowork_Inbox/. Drag raw PDFs, screenshots, or exports in; let Claude rename, extract CSVs, and place finished results into ~/Cowork_Inbox/Done/.

B Read-Only Reference + Output

Grant read access to ~/Client_Assets/ and write access only to ~/Client_Deliverables/ so original brand kits or contracts can never be overwritten.

C Zero-Local Cloud Mode

Skip mounting any local folder at all when working between Drive, Notion, Slack, and HubSpot—keeping the entire run inside a portable cloud remote session.

Never Mount ~/, ~/Desktop, or Password Managers
Keep local folder mounts surgical. A dedicated per-workflow folder acts as a physical blast-radius boundary and prevents stray temporary files from cluttering your desktop.

06 • Core Workflows: Zero-Interference Desktop Control Background macOS Spaces & Input Yielding

Background macOS Computer Use Without Hijacking Your Mouse

Earlier desktop agents locked you out of your own Mac, yanking your mouse cursor across the screen every two seconds. Claude’s Background macOS Computer Use runs clicks, scrolling, and keystrokes inside a hidden Space while your active cursor stays completely yours.

Isolated Dual-Layer Execution: Write emails or edit code on your primary display while Claude quietly drives desktop apps inside an off-screen macOS workspace behind frosted isolation.

How Background Spaces & Auto-Pause Safety Work

1 Hidden macOS Space Isolation

When Tier 3 activates, Claude Desktop spins up target app windows inside a separate virtual Space. Screenshot inspection and synthetic pointer/keyboard events route directly to that Space—so your active window focus never flickers.

2 Automatic Input-Interference Yielding

If you switch into Claude’s working window, move the mouse over its active target, or type on the keyboard inside that Space, Claude detects user input immediately, auto-pauses, and hands control back to you cleanly.

Best Practices for Smooth Background Desktop Runs
Keep target apps signed in before launching a batch, avoid locking your Mac screen (use a dim display sleep timer instead of lock-on-idle), and watch the live thumbnail in Claude’s sidecar whenever you want to verify a multi-step native export without switching Spaces.

Two Recurring Engines: Cowork /schedule vs. Chrome Schedules

Once a manual workflow works reliably, promote it to autopilot. Anthropic gives you two distinct scheduling engines—knowing which one runs with your laptop lid closed and which one relies on your live browser cookies prevents missed morning runs.

A Cowork Scheduled Tasks (/schedule)
  • Cadences: Run hourly, daily, weekdays, or weekly directly from any Cowork thread via /schedule or the Schedule button.
  • Cloud Remote Tasks (Lid Closed OK!): Workflows using only Tier 1 MCP connectors (Slack, Gmail, Drive, Jira, Notion, HubSpot) execute in Anthropic’s cloud even while your MacBook is asleep in a backpack.
  • Local Folder & macOS Tasks: Any schedule touching local mounted files or Tier 3 Computer Use queues until Claude Desktop is open and your Mac is awake.
B Chrome Scheduled Tasks
  • Purpose-Built for Web Portals: Runs recurring workflows through Claude in Chrome inside your authenticated browser profile.
  • Zero Re-Authentication Friction: Ideal for SSO-protected vendor dashboards, bank/carrier portals, competitor pricing checks, and recurring web form submissions that lack MCP APIs.
  • Device Requirement: Because it uses your live Chrome profile and session cookies, your computer and Chrome must be awake at the scheduled trigger window.

09 • Enterprise Governance & Safety Architecture Permission Hygiene, Approval Gates & Prompt Injection Defense

Governance, Privacy & Human-in-the-Loop Safety Gates

Giving an AI agent access to your email, files, and desktop buttons demands clear boundaries. Anthropic pairs least-privilege folder mounts and macOS privacy switches with mandatory confirmation gates before irreversible actions occur.

1 Irreversible-Action Confirmation Gates
  • Hard Pause Categories: Financial transfers, invoice payments, outbound customer emails, bulk file deletions, and permission changes trigger an explicit pause card.
  • Preview Before Commit: Every gate displays the exact dollar amount, recipient list, or file path so you can approve, edit, or cancel in one click.
  • Admin Policy Locks: Team and Enterprise admins can mandate approval gates on external MCP writes even if a prompt omits them.
2 Defending Against Indirect Prompt Injection
  • Untrusted Web Tabs & PDFs: Random web pages, scraped forums, or external vendor emails can hide adversarial text trying to hijack browser actions.
  • Session Isolation: Close sensitive banking, password manager, and admin tabs before letting Chrome tasks browse unfamiliar third-party sites.
  • Least-Privilege Connectors: Connect only the specific MCP tools needed for a workflow; revoke unused OAuth tokens quarterly.

Security & Permission Hygiene Across Surfaces

Control Layer Recommended Safe Configuration Common Anti-Pattern to Avoid
Local Folder Mounts Dedicated per-task folder (e.g., ~/Work/Invoices) mounted just for that job. Mounting your entire home directory (~/), Documents, or .ssh keys.
macOS OS Permissions Grant Screen Recording & Accessibility only to verified Claude Desktop; audit monthly. Leaving unattended unlocked Macs running open-ended third-party web scraping.
Outbound Comms & Spend Create drafts or stage carts first; require explicit click-to-send confirmation. Instructing “auto-reply and pay all invoices without asking.”
Enterprise Governance Org-approved MCP allowlist, Team/Enterprise zero-training guarantee, SSO & audit logs. Connecting unvetted community MCP binaries holding production credentials.
What to Do If a Scraped Page Looks Suspicious

If Claude pauses and warns about unexpected instructions inside an email, PDF, or webpage—or tries to navigate toward an unrelated domain—click Stop immediately. Close the untrusted tab, revoke any temporary folder mount if not needed, and inspect the execution trace before restarting from a clean prompt.

Never Store Secrets in Plain-Text Prompts
Do not paste API keys, passwords, or credit card numbers directly into chat or scheduled prompts. Rely on official OAuth MCP connectors or sign in manually once inside Chrome before starting a browser task.

11 • Diagnostics & Launch Readiness Top 7 Issues, 10-Second Fixes & 6-Point Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Use this diagnostic table whenever a macOS permission blocks a click, a scheduled task skips overnight, or Claude picks a slow UI route instead of an API—followed by our 6-point pre-flight checklist.

Symptom / Issue Root Cause 10-Second Fix
1. Computer Use fails to click or read a desktop window macOS Screen Recording or Accessibility toggle missing/stale after an app update. Open System Settings → Privacy & Security, toggle Claude off and back on in both Screen Recording and Accessibility, then relaunch Desktop.
2. Background task keeps pausing mid-run You moved the mouse inside Claude’s active Space or typed during execution. That is the input-interference safety pause working as designed; leave the Space undisturbed and click Resume in the Cowork pane.
3. /schedule task did not run overnight Task depended on a local mounted folder, Chrome tab, or Tier 3 app while laptop slept. Split pure MCP work into a cloud-only /schedule job, or schedule local/Chrome tasks during awake desk hours with Mac sleep disabled.
4. Claude clicks around Chrome instead of using Slack/Drive MCP connector was disconnected or prompt omitted preferred Tier 1 tools. Re-authenticate the connector under Settings → Connectors and name it explicitly (e.g., “Use Gmail MCP and Drive MCP first”).
5. Task stops with “Folder Access Denied” Output path sits outside the folder mounted for the current Cowork session. Grant a scoped mount to the exact working directory (e.g., ~/Finance/March_Recon) or direct outputs into the mounted folder.
6. Chrome task stalls at an SSO or MFA prompt Session cookie expired or portal requires hardware key / authenticator tap. Sign into the portal manually in your Chrome tab first, complete MFA, then click Continue in Claude’s task bar.
7. Cowork features missing on Team or Enterprise account Organization administrator has not enabled Desktop Computer Use or specific MCPs. Ask an Org Owner/Primary Owner to review Organization settings → Capabilities and allowlist required connectors.

6-Point Pre-Flight Checklist Before Delegating

✓
1. Verify Tier 1 MCPs First: Connect Slack, Gmail, Drive, Notion, Jira, or QuickBooks so Claude uses instant APIs before browsers or clicks.
✓
2. Check macOS Privacy Grants: Confirm Claude is enabled under both Screen Recording and Accessibility on macOS.
✓
3. Mount a Tight Sandbox Folder: Point local tasks at a dedicated subfolder like ~/Cowork_Inbox—never root ~/.
✓
4. Add an Explicit Approval Gate: Require a pause before payments, outbound sends, or deletes; prefer draft mode for comms.
✓
5. Match Engine to Sleep State: Keep /schedule overnight jobs pure-cloud MCP; run Chrome/local schedules while your Mac is awake.
✓
6. Test Once Before Scheduling: Run every new recipe manually once, inspect the 3-tier execution trace, then promote to /schedule.
Final Takeaway: Delegate Execution, Keep Command
One Claude unites cloud speed, browser reach, and quiet background macOS Spaces under one roof. Use APIs first, keep folder mounts narrow, guard irreversible steps with approval gates, and let your cursor stay yours.
