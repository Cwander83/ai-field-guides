Three Distinct Systems Teams Routinely Conflate

1 Tracing (Facts)

Answers “What happened?” Records inputs, retrieved chunks, tool calls, latency, and cost. A camera without a definition of burglary.

2 Evals (Judgments)

Answers “Did version B beat baseline A?” Scores outputs across a fixed dataset so prompt, model, or retrieval edits are measurable.

3 Guardrails (Actions)

Answers “Block or redact right now?” Inline runtime safety filters firing before a response reaches the user—not offline measurement.

Architecture: The Scorer Pyramid & Closed Offline/Online Loop

Define “Worse” Before You Edit a Single Prompt
Silent regressions hide behind three invisible shifts: your code/prompt edits, silent vendor model updates, and drifting user inputs. Set explicit failure gates up front: structural validity must stay 100%, overall pass rate cannot drop more than 3% below production baseline, and no P0 customer slice can drop more than 1 rubric tier.

Building Golden Datasets & Tooling Decision Matrix

The costliest rookie mistake is inventing 500 synthetic edge cases before writing a single scorer. Start with 5–10 real inputs—half proud production wins, half real user failures—and expand strictly when new failure modes surface.

Anatomy of a High-Signal Golden Dataset Row (evals/datasets/audit-reports.jsonl)

{"input": {"company": "Acme Corp", "url": "https://acme.example"}, "expected": {"sections": ["summary","pricing","features","risks"]}, "metadata": {"topic": "pricing", "tier": "enterprise", "source": "manual"}}
{"input": {"company": "Globex", "url": "https://globex.example"}, "expected": {"sections": ["summary","pricing","features","risks"]}, "notes": "2026-07 bug: fabricated SOC2 tier", "metadata": {"topic": "risks", "tier": "self-serve", "source": "prod-failure-2026-07"}}
1 Rich Segment Metadata

Tag every row with topic, tier, intent, and source. Aggregate scores hide segment collapses; metadata pinpoints them.

2 Minimal expected Facts

Store decidable anchors (required keys, numeric bounds), not brittle 400-word essays. Put broken prod outputs in notes, never expected.

3 Freeze 4 Coordinates

Log dataset_hash, prompt_sha, model_id, and scorer_version on every run. Without all four, “we scored 4.2” is folklore.

04 • Code Scorers First Zero-Cost Structural, Schema, AST, Citation & Abstention Pre-Screens

Deterministic Code Scorers: Free, Fast & Flake-Free

If a requirement is decidable, write it in code. Python and TypeScript scorers execute in under a millisecond, cost $0.00, return identical verdicts on every run, and shield your LLM judge budget from structurally broken outputs.

STAGE 1 • $0 CODE SCREEN:
Runs on 100% of rows; flags broken structure in <2ms.
STAGE 2 • LLM JUDGE:
Grades only Stage-1 passes (plus a 20% audit sample).
STAGE 3 • HUMAN REVIEW:
Focused strictly on uncertain splits & P0 incidents.

Production Scorer Module (evals/scorers/structure.py)

import ast, json, re
from bs4 import BeautifulSoup

def structural_and_range_screen(output: str) -> dict:
    soup = BeautifulSoup(output, "html.parser")
    found = {el.get("data-section") for el in soup.select("[data-section]")}
    missing = [s for s in ("summary", "pricing", "features", "risks") if s not in found]
    el = soup.select_one("[data-score]")
    val = float(el["data-score"]) if (el and re.match(r"^\d+(\.\d+)?$", el.get("data-score", ""))) else -1.0
    return {"score": float(not missing and 0.0 <= val <= 100.0), "reason": f"missing={missing}, score={val}"}

def citation_and_abstention_screen(output: str, allowed_doc_ids: set[str]) -> dict:
    if not allowed_doc_ids:  # Empty retrieval guard: require explicit abstention
        ok = bool(re.search(r"insufficient (context|data)|not found in sources", output, re.I))
        return {"score": float(ok), "reason": "must abstain when retrieved context is empty"}
    cited = set(re.findall(r"\[doc:([a-zA-Z0-9_-]+)\]", output))
    phantom = sorted(cited - allowed_doc_ids)
    return {"score": float(bool(cited) and not phantom), "reason": f"cited={len(cited)}, phantom={phantom}"}

Six High-ROI Deterministic Assertions to Wire First

1. JSON / Pydantic Schema

Validate keys, enums, and types via Model.model_validate_json() or is-json.

2. AST & SQL Syntax

Parse generated code with ast.parse(), tsc --noEmit, or is-sql before running tests.

3. Citation ID Grounding

Verify every cited [doc:id] or URL actually exists inside the retrieved chunk list.

4. Sparse-Data Abstention

Seed zero-context cases and assert the model declines instead of fabricating numbers.

5. Forbidden Leak Regex

Block leaked system markers, raw API keys, competitor slurs, or apologetic boilerplate.

6. Cost & Latency Caps

Catch runaway reasoning loops early using deterministic token, cost, and latency budgets.

05 • Calibrated LLM Judges Rubric Engineering, Bias Mitigation & Human Alignment Loops

Calibrated LLM-as-a-Judge & Rubric Anatomy

Once structural checks pass, use an LLM judge to grade subjective quality—like groundedness or actionability. Without calibration, however, judges behave like lenient substitute teachers who reward polished verbosity over truth.

Color-Coded Anatomy of a Bias-Resistant Judge Prompt

[1. SINGLE CRITERION] Grade ONLY Grounded Actionability for B2B sales. Ignore formatting/style (scored separately in code).
[2. ANTI-BIAS GUARDRAIL] Do NOT reward length, formal tone, or bullet count. A concise accurate report beats a verbose padded one.
[3. ANCHORED RUBRIC TIERS] 1.0 = all comparative claims trace to source + ≥2 concrete actions • 0.5 = 1 unsupported claim • 0.0 = fabricated facts.
[4. CONTRASTIVE ANCHORS] Canary PASS: 3-line verified price table + next step. Canary FAIL: 6-paragraph essay inventing a SOC2 badge.
[5. REASON-FIRST JSON] Output JSON ONLY at temperature 0: {"reason": "<cite exact unsupported claim first>", "score": 0.0, "pass": false}.
[6. EXPLICIT PASS FLOOR] Enforce threshold: 0.75 in config so ambiguous {"pass": true, "score": 0.0} judge payloads never pass CI!

The 5 Systematic Judge Biases (And Mechanical Defenses)

Judge Bias / Trap How It Corrupts Your Scores Verified Engineering Mitigation
1. Verbosity & Confidence Bias Longer, formal, authoritative-sounding hallucinations outscore short accurate answers. Forbid length rewards in the rubric; keep a permanent canary test pairing a short-correct answer against a verbose-wrong one.
2. Pairwise Position Bias When comparing Output A vs. Output B, judges systematically favor whichever slot appears first. Run Position-Swapped Pairwise Judging: evaluate (A, B) and (B, A); count a win only when both orderings agree.
3. Self-Preference Bias Models rate prose generated by their own model family higher due to shared stylistic priors. Use a cross-family judge (or pin one neutral rubric grader across all candidate providers) and anchor strictly on verifiable facts.
4. Rare-Class Accuracy Trap If real failures occur on 10% of rows, a broken judge that always says PASS hits 90% accuracy! Never calibrate on raw % accuracy. Measure TPR (sensitivity on true passes) and TNR (catch rate on known failures) or Cohen's κ.
5. Slider Noise (1–10) Unanchored 1–10 scales jitter between 7 and 8 across identical runs, creating phantom regressions. Default to Boolean (PASS/FAIL) or 3–4 anchored categories; pin temperature: 0 and average 3 trials for diffs under 5 pts.
The 30-Minute Human Calibration Loop (Target: 80–90% Agreement)
Label 20 real outputs yourself (10 passes, 10 genuine failures) with 1-sentence reasons. Run your judge prompt against those 20 rows without peeking, inspect every disagreement, and tighten rubric anchors until both TPR and TNR exceed 85%—matching typical agreement between two human engineers.

Declarative Test Matrices with promptfooconfig.yaml

Declarative configuration lets you test two prompts across two models in a clean 2 × 2 matrix—combining zero-cost pre-screen assertions, latency ceilings, and calibrated rubric judges inside one version-controlled file.

Complete Worked Config (evals/promptfooconfig.yaml)

description: Competitive audit report generator — PR regression suite
prompts:
  - file://prompts/audit-report.txt            # Production baseline prompt
  - file://prompts/audit-report.candidate.txt  # Single isolated change under test
providers:
  - { id: openai:gpt-5, label: prod-gpt5 }
  - { id: openai:gpt-5-mini, label: candidate-mini }

defaultTest:
  options:
    provider: { id: openai:gpt-5-mini, config: { temperature: 0 } }  # Pinned judge model
  assert:
    # LAYER 1: FREE DETERMINISTIC PRE-SCREEN (runs on every case, $0 judge cost)
    - { type: is-html, metric: structure }
    - { type: contains-html, value: 'data-section="summary"',  metric: structure }
    - { type: contains-html, value: 'data-section="pricing"',  metric: structure }
    - { type: contains-html, value: 'data-section="features"', metric: structure }
    - { type: contains-html, value: 'data-section="risks"',    metric: structure }
    - { type: javascript, metric: numeric_range,
        value: 'const m = output.match(/data-score="([0-9.]+)"/); return m && +m[1] >= 0 && +m[1] <= 100 ? 1 : 0;' }
    - { type: cost, threshold: 0.08, metric: budget }
    - { type: latency, threshold: 45000, metric: performance }

tests:
  - description: Enterprise prospect — pricing & grounded actionability
    vars: { company: Acme Corp, url: "https://acme.example", your_product: WidgetPro }
    metadata: { topic: pricing, tier: enterprise, source: manual }
    assert:
      - type: llm-rubric
        metric: grounded_actionability
        threshold: 0.75   # CRITICAL: prevents {pass: true, score: 0} default pass footgun!
        value: |
          Grade ONLY Grounded Actionability. Do not reward length or confident tone.
          1.0 = every comparative claim traces to fetched data AND >=2 concrete next actions.
          0.75 = claims traceable, actions generic. 0.5 = unsupported claim. 0.0 = fabricated.
          Respond with JSON only: {"reason": "<2 sentences>", "score": <number>, "pass": <boolean>}

  - description: Sparse-data anti-fabrication guard (private stealth competitor)
    vars: { company: StealthCo, url: "https://stealth.example", your_product: WidgetPro }
    metadata: { topic: risks, tier: enterprise, source: prod-failure-2026-08 }
    assert:
      - { type: python, value: file://evals/scorers/structure.py:citation_and_abstention_screen }

07 • RAG & Agent Trajectories Decomposing Retrieval vs. Generation & Scoring Multi-Step Tool Graphs

Evaluating RAG Pipelines & Agent Trajectories

Scoring only the final message of a RAG app or tool-using agent masks broken plumbing. If RAG fails, you need to know whether to fix the retriever or the prompt; if an agent succeeds by accident after calling the wrong tool, answer-only judges miss the bomb completely.

1. RETRIEVAL QUALITY:
Context Precision & Recall on fetched chunks.
2. CLAIM FAITHFULNESS:
Supported claims ÷ total claims in answer.
3. AGENT TRAJECTORY:
Tool sequence, schema args & step budget.

1. The RAG Triad: Isolate Retriever Bugs from Generator Hallucinations

Diagnostic Question Core Metric (Ragas / Phoenix) How It Computes & Which Layer to Fix When Low
Did we fetch the right chunks? Context Precision & Context Recall Checks whether ground-truth facts appear in top-k chunks without noisy distractors. Low score → fix chunking, embeddings, or reranker.
Did the LLM stick to context? Faithfulness / Groundedness Wire this first! Splits output into atomic claims: supported_claims / total_claims against retrieved text (1 supported + 1 invented date = 0.50). Low score → tighten prompt abstention rules.
Did it answer the user's ask? Answer Relevancy Penalizes evasive, off-topic, or bloated answers even when grounded in context. (Note: Ragas grades runtime retrieval; DeepEval's HallucinationMetric grades against static curated context.)

2. Multi-Step Agent Trajectories & Mock Tool Sandboxes

1 Score the Tool Graph in Code

Record structured tool_calls on every trace. Assert tool selection (trajectory:tool-used), ordering (lookup_policy before issue_refund), JSON arg validity, and step budgets (step_count ≤ 6) deterministically for $0—reserving judges strictly for final task resolution.

2 Replay Against Mock Sandboxes

Never point agent evals at live Stripe, production SQL, or shifting web search! Inject deterministic fixture sandboxes (frozen JSON responses + simulated HTTP 429/500 faults) so trajectories stay 100% reproducible and side-effect-free.

2. Controlling Offline CI Spend vs. Online Production Sampling

1 Two-Speed CI Budget Math
  • PR Smoke Gate (<90s, ~$0.40): Runs 15–25 P0 rows + 100% deterministic code checks + pinned gpt-5-mini judge. Fails exit 1 on any structural break or P0 drop.
  • Nightly Full Matrix (~$2–$5): Runs all 100+ cases × 3 trials, full Ragas retrieval metrics, and frontier judge audit.
  • PR Diff Bot: Posts a concise Markdown comment listing exact regressed case IDs and metadata.topic slices.
2 Online Production Sampling (5–10%)
  • Reference-Free Rubrics: Live traffic has no expected label; score property checks + groundedness against retrieved spans.
  • Observation-Level Judging: Score specific LLM/retriever spans rather than giant multi-minute root traces—completes in seconds.
  • Predictable Spend: At ~$0.02/eval, deterministic hashing of 5% of 10,000 daily runs costs ~$10/day (~$300/mo).

3. The Weekly 20-Minute Flywheel Ritual

How Production Failures Become Next Week's Armor
Every Monday: filter online traces where faithfulness < 0.75, user thumbs-down fired, or code property checks flagged → cluster into distinct failure modes → promote 1–3 representative traces into evals/datasets/*.jsonl tagged prod-failure-YYYY-MM → ship the fix on a branch → record a fresh 4-coordinate baseline!

Cross-Tool Synergy: Self-Verifying Agent Engineering

Evals unlock autonomous coding agents! When your spec.md defines target eval metrics and an isolated git worktree runs promptfoo as its local verification loop, an agent can iterate safely until proven better than production.

End-to-End Workflow: Upgrading a RAG Feature Without Guessing

Workflow Stage Concrete Action & Command Failure Prevented
1. Spec & Baseline Define AC in spec.md: “Raise topic=risks faithfulness ≥0.88 without regressing latency or enterprise slices.” Record baseline.json on main. Eliminates subjective “looks cleaner to me” debates during pull-request review.
2. Parallel Worktrees Spawn two git worktrees: Worktree A tests hybrid BM25+vector reranking; Worktree B tests a stricter abstention prompt. Keeps experiments isolated so single-variable attribution stays 100% clean.
3. Agent Verify Loop Coding agent runs npx promptfoo@latest eval on a dev split, inspects failing case reasons, and iterates on chunk boundaries. Agent self-corrects missing HTML tags and phantom citations before a human ever reviews.
4. Held-Out CI Gate GitHub Actions runs against a held-out test split, posts the segment table on the PR, and promotes the winning branch. Catches overfitting where a prompt memorized dev examples instead of solving the root bug.
Goodhart's Law Guardrail: Lock evals/ Read-Only in AGENTS.md!
Autonomous coding agents optimize relentlessly for green exit codes. Add a hard non-negotiable in AGENTS.md (and enforce via CODEOWNERS/CI): “Coding agents may NEVER edit evals/datasets/*, weaken scorer assertions, or lower threshold values during implementation tasks.”

11 • Quick Reference Troubleshooting Clinic & 6-Point Eval Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Keep this page beside your editor and CI dashboard. Almost every noisy score swing, false-green build, or surprise judge invoice maps directly to one of seven structural eval bugs below.

Top 7 Eval Pitfalls & 10-Second Structural Fixes

Symptom You Observe Root Cause & 10-Second Engineering Fix
1. Judge scores swing every run on unchanged code Judge temperature > 0 or vague 1–10 rubric. Pin judge temperature: 0, switch to Boolean or 4 anchored tiers, and run --repeat 3 to compare trial means.
2. Polished wrong answers beat concise right ones Classic verbosity bias. Add “Do not reward length or formal tone” to the rubric and test against a permanent short-correct vs. verbose-wrong canary pair.
3. Judge agrees 90% with humans yet misses bugs Class-imbalance illusion (always saying PASS hits 90% when failures are 10%). Calibrate TPR and TNR separately on a balanced 10-pass / 10-fail human set.
4. llm-rubric passes even with score: 0 Documented Promptfoo footgun: pass defaults to true when no floor is set! Always specify an explicit threshold: 0.75 and require boolean pass in JSON.
5. Overall score is 0.88, but enterprise users complain Global averages bury segment regressions. Tag every dataset row with metadata.topic and tier, and fail CI if any P0 slice drops below baseline.
6. RAG Faithfulness is low while answers sound right Retriever returned noisy chunks and the LLM improvised from pretraining memory. Check Context Precision/Recall first—fix chunking/reranking, not prompt prose.
