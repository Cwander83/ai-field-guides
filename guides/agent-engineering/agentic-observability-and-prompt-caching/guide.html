OpenTelemetry Normalization & The Break-Even Rule

1 Migrating Legacy gen_ai.system

OpenTelemetry GenAI conventions carry Development status and replace gen_ai.system with gen_ai.provider.name (anthropic, openai, gcp.vertex_ai).

Set OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental and normalize attributes inside your Collector.

2 Cache Write Break-Even Math

A 5-minute write (1.25x) breaks even on 1 hit (1.35x vs 2.0x raw). Never write a cache read zero times (+25% waste).

A 1-hour write (2.0x) breaks even on 2 hits (2.2x vs 3.0x)—ideal whenever pauses exceed 5 minutes.

Always Track Total Input vs. Cache Read Separately
In OTel GenAI spans, gen_ai.usage.input_tokens includes cached tokens, while gen_ai.usage.cache_read.input_tokens and gen_ai.usage.cache_creation.input_tokens break out discounted and write-premium counts for true FinOps billing.

Propagating Context Across Subagent & MCP Boundaries

When an orchestrator delegates work over an HTTP webhook, task queue, or Model Context Protocol (MCP) tool call, automatic thread-local context is lost. Always inject the active W3C traceparent into payload metadata (such as MCP _meta) and extract it before creating child spans, or derive deterministic trace IDs from a shared correlation key. 

// TypeScript: Register Vercel AI SDK Telemetry + Subagent MCP Trace Propagation
import { registerTelemetry } from "ai";
import { context, propagation } from "@opentelemetry/api";
import { LangfuseSpanProcessor } from "@langfuse/otel";
import { LangfuseVercelAiSdkIntegration } from "@langfuse/vercel-ai-sdk";

// 1. Export standardized gen_ai.* spans to Langfuse or any OTLP backend
export function register() {
  registerTelemetry({ integrations: [new LangfuseVercelAiSdkIntegration()] });
}

// 2. Inject W3C traceparent into MCP _meta before handing off to a subagent
export function buildMcpHandoffParams(toolArgs: Record<string, unknown>) {
  const carrier: Record<string, string> = {};
  propagation.inject(context.active(), carrier);
  return { ...toolArgs, _meta: { traceparent: carrier.traceparent, tracestate: carrier.tracestate } };
}

Static-First Prefix Ordering & Cache Breakpoint Architecture

Provider KV caches match prompts strictly from byte zero forward. One dynamic timestamp or reordered tool schema near the top of your payload invalidates every downstream token on every turn.

Figure 6.1 • Immutable Prefix Stack: Foundational tools, system rules, and frozen history stay locked inside the golden KV cache base, while only new delta tokens pay full compute on each turn.

Anatomy of a Cache-Friendly Prompt Stack (Tools → System → History → Turn)

[1. Tools Array (Frozen)] All JSON schemas sorted deterministically; never add or remove tools mid-run.
[2. System Prompt + Breakpoint #1] Static persona, policies, repo conventions → cache_control: ephemeral.
[3. Append-Only History + Breakpoint #2] Immutable user/assistant/tool turns frozen up to the prior step.
[4. Volatile Latest Turn (Uncached)] Current time, live git status, active file diff, and user prompt go strictly last.
1 Three Silent Cache Killers

Top-of-Prompt Timestamps: Putting Current time: 14:32:07 inside the system prompt forces a 0% cache hit rate. Push timestamps into the newest user message or expose a get_time tool.

Dynamic Tool Swapping: Dropping unavailable tools invalidates the Tools tier and everything below it. Keep the tool array static and restrict calls via tool_choice or policy validation.

2 Choosing 5-Minute vs. 1-Hour TTL

Default 5-Minute TTL (1.25x write): Optimal for tight autonomous loops where tool executions finish in seconds and turns fire continuously.

Extended 1-Hour TTL (2.0x write): Essential for human-in-the-loop coding assistants, code review approvals, or slow CI waits that often pause for 6 to 45 minutes between turns.

Tool-Output Compaction & Dynamic Cheap-to-Frontier Routing

Long-horizon agents quickly accumulate tens of thousands of stale search logs and file dumps. Compaction keeps working memory crisp, while dynamic routing protects margins from verbose reasoning output costs.

Figure 7.1 • Compaction Funnel & Model Cascade: Verbose historical tool outputs pass through a pruning gate into condensed summaries, then route across fast small models and frontier reasoning tiers.
1 Historical Tool-Output Compaction

Observation Truncation: Cap raw bash, log, or DOM tool responses immediately (keeping head/tail slices or structured JSON fields) before appending to history.

Server-Side Compaction: Use Anthropic context editing (clear_tool_uses / compact-2026-01-12) or OpenAI Responses API compact_threshold (which returns encrypted compaction items).

Batch Rule: Never compact on every turn—rewriting history resets the KV cache prefix. Compact in milestone batches (for example, once history passes 60K tokens).

2 Cheap-to-Frontier Model Routing

Output Cost Asymmetry: Generated output and reasoning tokens cost 3x to 8x more than standard input tokens—and up to 50x more than cached reads.

Tiered Cascade: Route intent routing, JSON formatting, log summarization, and guardrail evals to fast small models (such as Haiku, Flash, or mini tiers); escalate architecture and tricky bug fixes to frontier reasoning models.

Subagent Isolation: Offload noisy exploration to cheaper worker subagents that return a crisp 1,500-token synthesis to the main cached orchestrator.

Routing + Caching Synergy: Isolate Each Model Tier's Prefix
Prompt caches are keyed per model ID, so never flip the same growing conversation array back and forth between a small model and a frontier model. Instead, route side-tasks (classification, formatting, compaction summaries) into isolated single-turn calls or dedicated small-model subagents while keeping the main reasoning prefix locked on one primary model.

3. Ledger-Accurate Effective Input Price & Doom-Loop Guard

def compute_turn_cost_and_guard(usage, base_in_per_m, base_out_per_m, ttl="5m"):
    write_mult = 2.0 if ttl == "1h" else 1.25
    uncached = max(usage.input_tokens - usage.cache_read - usage.cache_creation, 0)
    in_cost = (uncached + write_mult * usage.cache_creation + 0.10 * usage.cache_read) * (base_in_per_m / 1e6)
    out_cost = (usage.output_tokens + usage.reasoning_tokens) * (base_out_per_m / 1e6)
    effective_in_rate = (in_cost / max(usage.input_tokens, 1)) * 1e6
    return {"total_usd": round(in_cost + out_cost, 6), "effective_in_per_m": round(effective_in_rate, 3)}
Measuring True Cache Health with Effective Input Rate
Comparing effective_in_per_m against your model's base input rate exposes cache regressions immediately: a healthy multi-turn agent loop drops effective input cost by 75% to 88% below list price even after accounting for initial 1.25x writes.

PII Redaction in Traces, Budget Alerts & FinOps Rollout

Production observability must protect customer secrets and stop runaway agent loops before they generate surprise invoices. Enforce privacy defaults at the Collector edge and roll out optimizations in measured stages.

1 Privacy-First Content Capture & Redaction

By OpenTelemetry default, message payloads (gen_ai.input.messages and gen_ai.output.messages) remain off so spans record only safe operational metadata: latency, model, finish reasons, and token counts.

When debugging requires prompt text in staging or sampled production runs, insert an OTel Collector redaction or transform regex filter to scrub API keys, bearer tokens, emails, and SSNs before OTLP export.

2 Automated Budget Alerts & Loop Breakers

Hard Runaway Caps: Enforce per-session ceilings on turn count (e.g., max_turns = 20), cumulative reasoning tokens, and USD spend directly inside the agent harness.

Anomaly Alerts: Trigger PagerDuty or Slack warnings whenever rolling 15-minute cache_hit_ratio drops below 70%, finish_reasons reports repeated length truncations, or cost per completed task spikes 2x above baseline.

Three-Phase Production FinOps Rollout Playbook

P1 Shadow Baseline

Enable gen_ai.* structural spans with content capture off. Measure baseline cost per task, p95 TTFT, and current accidental cache hit rate for 48 hours.

P2 Prefix Lock & Compact

Move timestamps and dynamic diffs out of system prompts, freeze tool arrays, add cache_control breakpoints, and enable batched tool compaction.

P3 Route & Eval Gate

Route classification and summarization steps to fast small models while validating online Langfuse or Arize AX correctness scores stay within 1% of baseline.

Compliance Warning: Never Bypass Sampling & Scrubbing in Regulated Workloads
Enabling full prompt body capture in production without Collector-side PII redaction can replicate proprietary source code, credentials, and user data into external observability storage. Separate structural FinOps metrics (always 100% sampled) from redacted debug trace payloads (1% to 5% sampled or gated by error status).

Key FinOps Alert Thresholds & Automated Actions

cache_read == 0 every turn Dynamic timestamp, UUID, or reordered tool schema near top of prompt. Move dynamic fields into the latest user turn; sort tool schemas deterministically.
