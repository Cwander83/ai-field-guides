What Jev Is (And Why RLCD Beats RLHF for Software Control Flow)

1 Zero Text Generation

Jev (TypeSafe AI) never writes prose, explanations, or markdown fences. Every answer is strictly a probability distribution over options you defined.

2 Trained With RLCD

Chat LLMs use RLHF (optimizing for pleasing prose). Jev uses Reinforcement Learning for Calibrated Decisions so 0.80 tracks an ~80% empirical hit rate.

3 Not a Coding Agent

Never set jev-latest as the brain of Claude Code or Cursor. Use your coding agent to write product code that calls Jev on hot request paths.

Architecture: Unstructured State In, Typed Probabilistic Judgments Out

The Core Separation of Powers
Jev supplies the judgment; your code supplies the decision. Because Jev is stateless, cannot call tools, and cannot emit unparsed text, a wrong prediction is just a bounded value you can gate on confidence—never a rogue agent loop.

04 • Core Primitives Choosing & Designing Choice, Score & Noul Questions

Mastering the Three Primitives: Choice, Score & Noul

Every judgment in System One maps to one of three shapes. Choose by the mathematical structure of the answer you need—and batch all of them into a single request.

Pick by Output Geometry: Use Choice for unordered sets (up to 255 keys), Score for ordered situational rubrics (2–10 levels), and Noul for atomic yes/no probabilities (0.0–1.0).
1 Choice (Unordered)
  • Returns choice, probabilities, and confidence (up to 255 keys).
  • Always include other: null so out-of-scope inputs never force a bad match.
  • Disambiguate close twins with {what, not_for, examples} objects.
2 Score (2–10 Levels)
  • Returns score (Σ i·p_i), legend, probabilities, confidence.
  • Describe situations, never degrees: write “Broken, workaround exists”, not “Medium”.
  • Measure one dimension per Score; give extreme cases their own top level.
3 Noul (Binary P(yes))
  • Returns single float noul in 0.0..1.0.
  • One condition per Noul: split “angry AND wants refund” into two Nouls.
  • Phrase positively (1.0 = yes). Note: 0.5 means unsure, never “medium skill”!

Upgrading Confused Options With Structured Criteria (Python SDK)

from typesafe_sdk import Choice, Noul, TypeSafeClient

with TypeSafeClient(model="jev-1.13.0") as client:  # reads TYPESAFE_API_KEY
    res = client.system_one(
        state="Has my returned pair of size-10 trail runners reached your warehouse yet?",
        questions={
            "intent": Choice(
                instructions="Which return workflow applies to this message?",
                criteria={
                    "return_policy": {"what": "Eligibility rules or starting a new return",
                                      "not_for": "Progress of a parcel already shipped back",
                                      "examples": ["Can I return worn shoes?", "How long is the return window?"]},
                    "return_status": {"what": "Tracking or refund timing of a return already sent",
                                      "not_for": "Asking whether an item is eligible to be returned",
                                      "examples": ["Did my return arrive?", "When will my refund post?"]},
                    "other": None,
                },
            ),
            "already_shipped": Noul(instructions="Does the customer state they already sent the item back?"),
        },
    )  # Cookbook result: 13 batched questions in 1 call ran 12.2x cheaper & 10.0x faster than 13 single calls!

05 • State Craft & Request Design Filtering Distractors, Dot-Path Targeting & Structured Fan-Out

State Craft: Why Input Hygiene Is 80% of Accuracy

Unlike chat sessions where teams dump entire database rows into context “just in case,” Jev accuracy drops sharply when state contains irrelevant noise. Filter ruthlessly in code before calling the API.

Color-Coded Anatomy of a High-Signal System One Request

[1. PINNED MODEL] "model": "jev-1.13.0" — Locks exact weights so calibrated thresholds never shift unexpectedly.
[2. NAMED STATE OBJECT] "state": {"ticket": {"msg": "..."}, "order": {"charges": [...]}, "refund_policy": "..."} — Separates facts & policy from judgment logic.
[3. DOT-PATH POINTER] "instructions": "Does refund_policy support the request in ticket.msg given order.charges?" — Directs attention to exact fields.
[4. SITUATIONAL CRITERIA] "criteria": {"true": "Explicit duplicate captured charge covered by policy", "false": "Single valid charge or outside policy"}
[5. ESCAPE VALVE] "other": null on every Choice — Prevents forced high-confidence misclassifications on out-of-distribution inputs.
[6. ATOMIC DECOMPOSITION] Ask 3 simple questions (refund_asked, duplicate_charge, policy_covers) and combine with && in code!
A Put Policy in state, Not Prompts

Pass your live refund_policy or plan entitlements inside state, and keep instructions generic (“Does refund_policy cover this request?”). When business policy changes tomorrow, zero question definitions or thresholds need rewriting.

B Structured Dict Instructions

instructions and criteria accept JSON objects as well as strings! Pass labeled candidate records inside each question to run 50-way entity deduplication or passage reranking in a single HTTP round trip.

Worked Pattern: Single-Trip Entity Deduplication Across Candidate Records

from typesafe_sdk import Noul, TypeSafeClient

def build_dedupe_questions(candidates: list[dict]) -> dict[str, Noul]:
    return {
        f"same_as_{c['id']}": Noul(
            instructions={
                "candidate_record": {"name": c["name"], "city": c["city"], "last_company": c["last_company"]},
                "question": "Is the incoming 'resume' in state for the exact same person as 'candidate_record'?",
            }
        )
        for c in candidates
    }

with TypeSafeClient(model="jev-1.13.0") as client:
    res = client.system_one(state={"resume": parsed_resume_text}, questions=build_dedupe_questions(top_25_rows))
matches = [cid for cid, ans in res.nouls.items() if ans.noul > 0.85]  # Zero prose, 1 round trip!
When to Make a Second Request Instead of Batching
Batch everything into one request unless Question B's option keys literally depend on Question A's winner (e.g., walking a 5,000-node taxonomy tree) or you must fetch an external database row first. Otherwise, speculative single-trip batching always wins.

06 • Uncertainty & Routing Three-Band Confidence Thresholds & Four Canonical Patterns

Confidence Gating & The Four Core Patterns

Rank with probabilities; gate automation with confidence. Calibration applies across populations, not single calls—so risk-sensitive actions always pair answer values with explicit confidence floors.

Three-Band Risk Control: Never apply one global threshold. Showing an account balance tolerates confidence ≥ 0.60; moving money demands > 0.90 plus confirmation; < 0.50 routes straight to a human.

The Four Architectural Patterns That Cover 95% of Production Workloads

Pattern How It Works in Code High-Leverage Use Case
1. Speculative Fan-Out Send all candidate questions in one call (category, bug_severity, refund_asked); ignore unused keys on non-matching branches. Support & intake pipelines avoiding serial waterfall latency.
2. Confidence-Gated Routing Branch on (answer, confidence) pairs: auto-act above high bar, ask user to confirm in middle band, escalate below floor. Refunds, transfers, account mutations, autonomous tool gates.
3. Composite Scoring Ask 3–5 atomic Score/Noul dimensions, normalize each to 0..1, and compute weighted sums in code (0.4*py + 0.4*arch...). Lead prioritization, candidate rubrics (IC vs. EM weights from 1 call), spam risk.
4. Intent Routing Place Jev at the front door to pick between a $0 SQL handler, a cheap small LLM, a frontier reasoning model, or a human specialist. Slashing frontier LLM bills by 60–80% without losing quality on hard queries.

Composite Scoring + Three-Band Routing Snippet

# Tune weights in Git PRs without touching prompts — reuse identical atomic answers across multiple policies!

    + 0.30 * answers["sender_identity_mismatch"].noul

Production Blueprint: One-File Policy & Quality Gates

Keep every question definition and numeric threshold inside one dedicated policy file (lib/decisions.ts) so product and security reviews read a single 60-line file instead of hunting across route handlers.

1. Centralize Questions & Thresholds (lib/decisions.ts)

import { choice, noul, score } from "@typesafe-ai/sdk";

export const INTAKE_QUESTIONS = {
  request_type: choice("What is the user asking for?", {
    new_report: "Generate a new competitive audit report", edit_report: "Modify an existing report",
    billing: "Invoices, refunds, or payment failures",     support: "Product bug or how-to question", other: null,
  }),
  is_abusive:       noul("Does the message contain threats, slurs, or harassment?"),
  refund_requested: noul("Is the user explicitly asking for money back or account credit?"),
  urgency:          score("How time-sensitive is this request?", [
    "Can wait indefinitely", "Needed this week", "Needed today", "Production outage or active revenue loss",
  ]),
};

export const QUALITY_QUESTIONS = {
  rubric_fit: score("How completely does 'report' satisfy the delivery rubric?", [
    "Empty or off-topic", "Partial sections; misses core ask",
    "Answers ask but thin evidence", "Complete, specific, and thoroughly evidenced",
  ]),
  claims_supported: noul("Is every factual claim in 'report' supported by a cited passage in 'sources'?"),
};

export const THRESHOLDS = {
  minIntakeConfidence: 0.60, refundToHuman: 0.70, minRubricScore: 2.20, minCitationSupport: 0.75,
} as const;

2. Pre-Delivery Quality Gate Around Paid Deliverables (lib/quality-gate.ts)

import { TypeSafeClient } from "@typesafe-ai/sdk";
import { QUALITY_QUESTIONS, THRESHOLDS } from "@/lib/decisions";

const client = new TypeSafeClient({ model: "jev-1.13.0" }); // Server-only TYPESAFE_API_KEY

export async function gatePaidDeliverable(report: string, sources: string[]) {
  const { answers } = await client.systemOne({ state: { report, sources }, questions: QUALITY_QUESTIONS });

  if (answers.rubric_fit.confidence < 0.50) {
    return { action: "human_review" as const, reason: "ambiguous_rubric_fit" };
  }
  if (answers.rubric_fit.score < THRESHOLDS.minRubricScore ||
      answers.claims_supported.noul < THRESHOLDS.minCitationSupport) {
    // Never bill a customer for a hallucinated or incomplete LLM draft!
    return { action: "retry_draft" as const, fit: answers.rubric_fit.score, cited: answers.claims_supported.noul };
  }
  return { action: "ship" as const };
}

Persist {model, question_version, answers, confidence, chosen_action} to Postgres so you can replay threshold changes offline. Note that setting TYPESAFE_LOG_LEVEL=debug redacts auth headers but logs raw request/response bodies—keep debug off in PII environments!

5 Real-World Copy-Paste System One Recipes

Recipe & Goal Copy-Paste Production Pattern
1. Zero-Service RAG Reranker
Filter noisy vector chunks in 1 call		 Build one Noul per retrieved chunk: q = {f"p{i}": Noul(instructions={"query": query, "passage": c.text, "q": "Does passage help answer query?"}) for i, c in enumerate(chunks)}. Keep chunks with ans.noul > 0.60 sorted descending.
2. 4-Outcome LLM Safety Battery

09 • Model Jaggedness & Governance Where System One Breaks & How Code Compensates Cleanly

Know the Edges: jev-1.13 Jaggedness & Hard Rules

TypeSafe publishes explicit failure modes (“jaggedness”) for jev-1.13. Respecting what Jev cannot do is what separates rock-solid production pipelines from mysterious accuracy drops.

The 7 Documented Jaggedness Traps (And Exact Code Fixes)

Jaggedness Trap What Goes Wrong The Clean Engineering Pattern
1. Counting & Arithmetic Asking “Are more than 5 of these 40 items defective?” fails—Jev is not a calculator. Fan out 40 parallel Noul questions (one per item) in one call, then run sum(p > 0.7 for p in nouls) > 5 in code!
2. Date & Time Ordering Reads dates as text tokens rather than ordered timestamps (“Is Date A 30 days before B?”). Extract date fields with Choice (month/day/year + not_stated) or regex, then compare with native datetime.
3. Hyper-Literal Reading Answers the exact words written, not implied business intent. State boundary conditions explicitly inside criteria; align instructions and criteria so they never contradict.
4. Double Negatives Multi-hop indirection or “Is it untrue that X lacked Y?” degrades calibration. Ask direct, single-hop positive questions pointed at named state paths.
5. Cross-Question Sums Noul(X) + Noul(not X) is not constrained to equal 1.00 across independent questions. Never rely on cross-question probability identities; use a single Choice if options must sum to 1.0.
6. Adversarial State Prompt injections inside untrusted user text can nudge probabilities. Strip untrusted markup, write explicit criteria, and never let low/medium confidence trigger destructive actions alone.
7. Alias Drift (jev-latest) New model releases move probabilities slightly against tuned thresholds. Pin model="jev-1.13.0" in production and log response.model on every decision trace.

Worked Fix: Counting Defects Without Asking the Model to Count

# WRONG: Noul("Do at least 3 reviews mention shipping damage?") -> unreliable mental math!
# RIGHT: 1 atomic Noul per review in a single batched call + deterministic Python sum:
questions = {
    f"dmg_{i}": Noul(instructions={"review": r, "q": "Does 'review' report physical shipping damage?"})
    for i, r in enumerate(reviews)
}
resp = client.system_one(state={"product_sku": sku}, questions=questions)
damaged_count = sum(1 for ans in resp.nouls.values() if ans.noul >= 0.75)

11 • Quick Reference Troubleshooting Clinic & 6-Point Production Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Keep this page next to your lib/decisions.ts policy file. Nearly every surprising probability or API error maps to one of seven mechanical fixes below.

Top 7 System One Pitfalls & 10-Second Fixes

Symptom You Observe Root Cause & Immediate 10-Second Fix
1. confidence stays stuck below 0.40 Overlapping rubric levels, compound multi-part question, or missing facts in state. Split into 1 dimension per question and rewrite Score levels as concrete situations.
2. Model confuses two similar Choice keys Short string labels blur boundary cases. Upgrade both keys to structured objects with explicit what, not_for, and examples arrays, plus other: null.
3. Easy cases fail when full JSON row is passed Context rot from noisy distractor fields. Filter state in code first so only fields cited by your questions cross the wire, and reference exact dot-paths.
4. Counts, totals, or date checks are wrong Asking Jev to do math or calendar ordering. Emit one Noul per item (or extract date parts) and run arithmetic/date comparisons in native Python/TypeScript.
5. Threshold pass rates shifted without code edits Using floating alias jev-latest across a model update. Pin exact version jev-1.13.0 in production and re-calibrate on your golden JSONL set before bumping.
6. HTTP 401, 422, or 429 / 529 401: internal whitespace or wrong TYPESAFE_API_KEY (verify api.typesafe.ai domain!). 422: inspect body for malformed criteria field. 429/529: enable SDK exponential backoff.
7. Coding agent invents non-existent SDK methods Outdated training priors or stale skill. Run npx skills add typesafe-ai/skills --skill typesafe-ai (or update plugin) so the agent reads current SDK signatures.
6-Point Pre-Flight Checklist: Before Shipping Any System One Decision
☐ 1. Server-Only Key & Verified Domain: TYPESAFE_API_KEY lives strictly on the server talking to api.typesafe.ai (never browser code or lookalike URLs).

☐ 2. One-File Policy & Pinned Model: All questions and risk-tiered THRESHOLDS live side-by-side in one file with model pinned to jev-1.13.0.

☐ 3. Atomic & Escape-Hatched Primitives: Every question tests one condition, Nouls read positively (1 = yes), and every Choice includes other: null.
☐ 4. Ruthlessly Filtered State: Code strips unrelated fields before calling system_one(); zero math, counting, or date comparisons inside instructions.

☐ 5. Confidence Fallbacks Wired: Low-confidence predictions route explicitly to human review, user confirmation, or retry—never blind execution.

☐ 6. Validated on Labeled Traffic: Calibrated against 20–50 real labeled examples (and benchmarked via system-one-adapter) before gating users or CI!
