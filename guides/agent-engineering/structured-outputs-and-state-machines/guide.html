How CFG & FSM Logit Masking Guarantee Zero Syntax Errors

Prompts cannot enforce formal syntax reliably across thousands of runs. Constrained decoding solves formatting at the token-sampling layer by masking illegal vocabulary choices before a token is ever picked.

Figure 5.1 • Token-Level Grammar Filtering: Candidate vocabulary tokens pass through the active grammar state; invalid characters and keys are deflected to zero probability while schema-compliant tokens lock cleanly onto the output track.
1 Schema-to-Grammar Compile

Your JSON Schema compiles into a Finite State Machine (regular patterns) or Context-Free Grammar (recursive objects) and caches by schema hash.

2 Microsecond Bitmasks

Engines such as XGrammar 2 and llguidance pre-classify context-independent tokens so per-step bitmasks compute in under 40 microseconds.

3 Logit -Infinity Masking

Disallowed tokens receive a -inf logit bias prior to softmax. Even with creative temperatures, malformed JSON becomes mathematically impossible.

API Anatomy: OpenAI text.format & Anthropic output_config

Schema Wrapper (response_format / output_config.format) + Reasoning First (reasoning_summary key) + Strict Guard (additionalProperties: false) + Typed Decision (enum / union)

Pydantic v2, Zod v4 & Discriminated-Union Contracts

Maintain a single source of truth for schemas, runtime checks, and compiler types. Modern Zod v4 and Pydantic v2 export strict JSON Schemas natively while validating domain math and discriminated-union tags.

TS Zod v4 Native z.toJSONSchema()

Zod v4 replaces the deprecated zod-to-json-schema package with built-in z.toJSONSchema(schema), targeting draft-2020-12 or draft-07 cleanly.

Use z.strictObject() and z.discriminatedUnion("kind", [...]) so every variant automatically emits closed objects.

PY Pydantic v2 model_json_schema()

Powered by a Rust core, Pydantic v2 compiles complex union models via Model.model_json_schema() and powers google-genai and OpenAI SDKs directly.

Combine ConfigDict(extra="forbid") with @model_validator to enforce cross-field business rules after decoding.

Union Formula: Discriminator Literal (kind) + Variant Fields (tool_name, args) + Nullable Optional (.nullable()) + Closed Object (extra="forbid") 
// TypeScript (Zod v4): Single source of truth for LLM Schema + Switch Exhaustiveness
import * as z from "zod";

const StepDecision = z.discriminatedUnion("kind", [
  z.strictObject({ kind: z.literal("call_tool"), tool: z.enum(["lookup_order", "refund"]), orderId: z.string() }),
  z.strictObject({ kind: z.literal("ask_user"), question: z.string(), missingField: z.string().nullable() }),
  z.strictObject({ kind: z.literal("complete"), summary: z.string() }),
]);

export const providerSchema = z.toJSONSchema(StepDecision, { target: "draft-2020-12" });
# Python (Pydantic v2 + google-genai): Structural schema + semantic cross-field invariant
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, model_validator

class RefundProposal(BaseModel):
    model_config = ConfigDict(extra="forbid")
    kind: Literal["refund_proposal"]
    invoice_cents: int = Field(gt=0)
    refund_cents: int = Field(gt=0)

    @model_validator(mode="after")
    def verify_cap(self) -> "RefundProposal":
        if self.refund_cents > self.invoice_cents:
            raise ValueError(f"refund_cents ({self.refund_cents}) exceeds invoice_cents ({self.invoice_cents})")
        return self
Cross-Provider Strict Schema Portability Checklist
To make one schema work smoothly across OpenAI, Anthropic, and Gemini: avoid optional properties (use .nullable() instead of .optional()), set additionalProperties: false on every nested object, and keep complex regex lookarounds in your Pydantic or Zod post-validator rather than in the token grammar.

Streaming Partial JSON & Bounded Validation-Repair Loops

Waiting for a complete JSON payload makes interactive apps feel frozen. Incremental parsers render partial objects live as tokens arrive, while capped validation-feedback loops self-heal semantic mistakes cleanly.

1 Progressive Partial JSON Streaming

OpenAI streams raw structured tokens, while Anthropic emits input_json_delta events carrying partial_json slices. Libraries such as Vercel AI SDK Output.object and Python jiter auto-close unfinished brackets mid-stream.

Key rule: Expose streamed chunks as DeepPartial<T> for UI rendering only; run strict validation and trigger state transitions only after the final token arrives.

2 Bounded Semantic Repair Loops

When PydanticAI raises ModelRetry or a Zod validator rejects a value, inject the exact field path and violation message back into the conversation for a targeted correction turn.

Keep error payloads surgical: cite only the failing JSON pointer (for example /refund_cents) and the invariant rule, not an entire raw stack trace. 

// TypeScript (Vercel AI SDK): Stream typed DeepPartial objects safely before final commit
import { streamText, Output } from "ai";
import * as z from "zod";

const PlanSchema = z.strictObject({
  headline: z.string(),
  steps: z.array(z.strictObject({ title: z.string(), risk: z.enum(["low", "high"]) })),
});

const result = streamText({
  model: providerModel,
  output: Output.object({ schema: PlanSchema }),
  prompt: "Draft a database index migration plan.",
});

for await (const partial of result.partialOutputStream) {
  renderLiveDraftCard(partial); // Safe DeepPartial: fields populate progressively as tokens arrive
}
const finalVerifiedPlan = await result.output; // Fully validated against PlanSchema on stream end

The 4-Stage Bounded Repair Protocol

Attempt Stage Trigger Condition Runtime Action Next State
Initial Call (0) Constrained decoding enabled Stream tokens; verify schema + semantic rules on EOF. TRANSITION_OK or Retry 1
Repair Try 1 Semantic check fails (e.g., bad ID) Append concise JSON-pointer error via ModelRetry. TRANSITION_OK or Retry 2
Repair Try 2 Second invariant mismatch Lower temperature to 0.0; include allowed enum/ID hints. TRANSITION_OK or Escalate
Circuit Open (3) retry_count >= max_retries Halt generation immediately; preserve failed trace in DLQ. DEAD_LETTER / Human
Why You Must Cap Repair Loops at 2 or 3 Attempts
Unbounded self-healing loops burn tokens rapidly when a model lacks a required fact in context and keeps guessing invalid IDs. Treating repair exhaustion as a deterministic transition to DEAD_LETTER turns silent hangs into observable alerts.

Enforce a hard global max_steps counter plus per-tool repeat limits so an agent cannot call the same failing search tool endlessly.

from dataclasses import dataclass

TRANSITIONS = {
    ("IDLE", "EV_START"): "PLANNING",
    ("PLANNING", "EV_CALL_READ"): "EXECUTING_READ",
    ("EXECUTING_READ", "EV_OBS_READY"): "PLANNING",
    ("PLANNING", "EV_PROPOSE_WRITE"): "AWAITING_APPROVAL",
    ("AWAITING_APPROVAL", "EV_APPROVE"): "EXECUTING_WRITE",
    ("AWAITING_APPROVAL", "EV_REJECT"): "PLANNING",
    ("EXECUTING_WRITE", "EV_COMMITTED"): "COMPLETED",
}

@dataclass
class MachineContext:
    state: str = "IDLE"
    steps: int = 0
    max_steps: int = 12

def step_machine(ctx: MachineContext, event: str, guard_ok: bool = True) -> str:
    if ctx.steps >= ctx.max_steps:
        ctx.state = "DEAD_LETTER"
        return ctx.state
    nxt = TRANSITIONS.get((ctx.state, event))
    if nxt is None or not guard_ok:
        raise ValueError(f"Blocked transition from {ctx.state} on {event}")
    ctx.steps += 1
    ctx.state = nxt
    save_checkpoint(ctx)  # Persist every step to Postgres or Temporal
    return ctx.state

Idempotency, Checkpointing & Dead-Letter Transitions

Structured outputs protect what enters your state machine; idempotency keys, durable checkpoints, and dead-letter queues protect what happens when workers crash mid-flight or upstream APIs time out.

1 Deterministic Idempotency Keys

If an agent sends a payment or creates a ticket and the HTTP response drops, a naive retry executes the side effect twice. Derive an idempotency_key from sha256(run_id + step_index + action + payload_hash).

Check a durable execution ledger before firing external APIs; if that key already recorded SUCCEEDED, return the cached receipt immediately.

2 Durable Checkpoints & Replay

Commit state snapshots (enum state, message cursor, remaining max_steps, and pending tool intent) to Postgres or Temporal event histories after every transition.

Long-lived human approvals can sleep for hours or days at zero compute cost until an external webhook signals resumption.

D Dead-Letter Transitions

Route exhausted repairs or step-budget overruns into DEAD_LETTER with full inputs, schema version, and validator diagnostics for human triage.

V Schema Versioning

Stamp every checkpoint with schema_version. When deploying breaking union changes, run pure upcasters before replaying paused runs.

R Shadow Canary Rollouts

Run new schema versions in shadow audit mode first to measure repair rates, grammar compile latency, and enum drift before gating traffic.

Idempotent Side-Effect Ledger Guard (TypeScript)

export async function executeIdempotentTool(runId: string, step: number, proposal: ToolCall) {
  const key = sha256(runId + ":" + step + ":" + proposal.name + ":" + canonicalJson(proposal.args));
  const existing = await ledgerRepo.findByKey(key);
  if (existing?.status === "SUCCEEDED") {
    return existing.cachedReceipt; // Short-circuit duplicate side effect safely
  }
  await ledgerRepo.markInFlight(key, proposal);
  const receipt = await dispatchExternalTool(proposal, { idempotencyKey: key });
  await ledgerRepo.markSucceeded(key, receipt);
  return receipt;
}
Separate Speculative Reads from Commit Writes
Let agents run read-only queries freely inside PLANNING with fast retries, yet funnel every state-mutating tool through an idempotent EXECUTING_WRITE state backed by a ledger and an optional human gate.

Troubleshooting Clinic & Production Pre-Flight Checklist

Use this field clinic to diagnose the seven most frequent structured-output and state-machine failures in seconds, followed by six readiness gates every agent must clear before production traffic.

Symptom & Error Root Cause 10-Second Production Fix
400: Invalid strict schema Object missing additionalProperties: false or optional key omitted from required. Use z.strictObject() or extra="forbid"; declare optional fields as ["string", "null"].
First-call latency spike Cold CFG/FSM compilation for large or deeply nested schemas. Warm common schemas on server boot and reuse identical schema strings to hit provider caches.
Accuracy drops in strict mode Schema forces final enum classification before any reasoning tokens. Add a reasoning_summary field ahead of the decision field in property declaration order.
Infinite tool or repair loops Missing global max_steps cap or ambiguous repair error prompts. Enforce hard step ceilings, cap ModelRetry at 2, and inject exact JSON-pointer paths.

6-Point Pre-Flight Production Readiness Checklist

□ 1. Strict Mode Verified: Confirm every provider schema sets additionalProperties: false, places all fields in required, and passes provider dry-run validation.

□ 2. Reasoning Order Tested: Verify complex routing schemas place scratchpad reasoning keys ahead of strict classification enums so quality stays high.

□ 3. Bounded Loops Active: Test that hitting max_steps or exhausting 2 semantic retries transitions cleanly into DEAD_LETTER rather than hanging.

□ 4. Idempotency Ledger Proven: Simulate a network timeout during EXECUTING_WRITE and verify the replay returns the cached receipt with zero duplicate writes.

□ 5. HITL Token Bound to Hash: Verify modifying any parameter of a paused proposal invalidates prior approval signatures and forces fresh review.

□ 6. Checkpoint Migration Safe: Confirm persisted checkpoints carry schema_version tags and replay smoothly across rolling deploys.
