Architecture: Local Agent Mode vs. Cloud Coding Agent vs. GitHub MCP

All three execution surfaces read the same repository instruction files (.github/copilot-instructions.md and AGENTS.md), ensuring consistent architecture, lint rules, and test verification whether an engineer is pair-programming live or delegating backlog tickets overnight.

L When to Stay Local (VS Code Agent Mode)

Use Agent Mode when requirements are exploratory, you need rapid visual feedback on a local dev server, or you want interactive diff review across complex cross-cutting refactors. Think of it as a senior pair programmer sharing your keyboard and terminal.

C When to Delegate Async (Cloud Coding Agent)

Assign issues to @copilot for well-scoped backlog work: unit test coverage, bug fixes with repro steps, dependency migrations, or docs updates. It runs in an isolated GitHub Actions sandbox and opens a Draft PR while you stay in flow.

Choosing the Right Copilot Plan & Execution Mode

Ask Mode VS Code, JetBrains, Web Read-only Q&A; explains code and searches #codebase. Zero file writes. Onboarding to modules, debugging stack traces, reviewing SQL queries.
Edit Mode VS Code, JetBrains Scoped diffs on user-selected files only; no shell execution or autonomous loops. Deterministic edits across 2–5 known files (props, TypeScript types, JSDoc).
Agent Mode VS Code (GA), JetBrains, CLI Autonomous synchronous loop: edits files, runs shell commands, calls MCP tools, self-fixes. End-to-end features, complex refactors, failing test triage, live API wiring.

Code Review GitHub PRs & Rulesets Agentic diff analysis (Lite / Balanced / Max) on Actions; leaves inline suggestions. Automated first-pass PR screening via branch rulesets before human review.

Persistent Repo Memory: Instructions, Globs & Prompt Files

Repeating coding conventions in every chat prompt wastes time and AI credits. Version-controlled instruction files turn your repository into a self-documenting contract automatically injected into VS Code Agent Mode, Cloud Coding Agent, Copilot CLI, and Code Review.

Layered Context Architecture: Combine one concise repo-wide baseline (.github/copilot-instructions.md or AGENTS.md) with path-scoped .instructions.md glob files and reusable .prompt.md workflows so agents load only relevant rules.

The 4-Tier GitHub Copilot Instruction Hierarchy

File Path Pattern Scope & Trigger Honored By Best Content to Put Inside
.github/copilot-instructions.md Always-on (Repo-wide) VS Code, JetBrains, Coding Agent, Code Review Tech stack, exact build/lint/test commands, directory layout, non-negotiable conventions (<150 lines).
.github/instructions/*.instructions.md Path-scoped via YAML applyTo VS Code Agent Mode, Coding Agent, Code Review Domain-specific rules: React component patterns, SQL migration safety, Terraform module guards.
AGENTS.md (root or subdir) Cross-agent standard Coding Agent, Code Review, Copilot CLI, Codex Portable engineering handbook shared across Copilot and third-party agents; nearest file wins in monorepos.
.github/prompts/*.prompt.md On-demand /slash command VS Code Copilot Chat & Agent Mode Repeatable multi-step SOPs: scaffolding an API route, writing E2E specs, auditing PR accessibility.

Wiring github/github-mcp-server: Remote OAuth & Toolsets

The official Go-based GitHub MCP Server exposes GitHub Issues, Pull Requests, Actions logs, and Code Security alerts directly to Copilot Agent Mode. Its GA remote endpoint (https://api.githubcopilot.com/mcp/) authenticates via OAuth 2.1 + PKCE—eliminating static Personal Access Tokens on developer laptops.

Recommended: Remote OAuth (.vscode/mcp.json)
{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "X-MCP-Toolsets": "repos,issues,pull_requests,actions",
        "X-MCP-Readonly": "false",
        "X-MCP-Lockdown": "true"
      }
    }
  }
}

Context-Window Hygiene: Scope Your Toolsets
Never load every GitHub MCP tool at once. Filtering via X-MCP-Toolsets or X-MCP-Exclude-Tools trims thousands of JSON schema tokens per turn and sharpens agent tool selection.
Read-Only & Lockdown Modes
Append /readonly to the URL (or set X-MCP-Readonly: true) for zero-write audit sessions. Enable X-MCP-Lockdown: true on public repos to hide untrusted external issue/PR comments from prompt injection.

06 • Async Coding Agent & PR Review Automation GitHub Copilot Agent Mode & MCP

Delegate Issues to @copilot & Automate PR Code Reviews

When you assign a GitHub Issue to Copilot Coding Agent, GitHub spins up an ephemeral Actions runner, executes your custom setup workflow, writes and tests the implementation, runs built-in security & self-review checks, and opens a Draft PR ready for human and AI review.

1 Scope Issue

Include target file paths, clear acceptance criteria, and the exact test command.

2 Assign @copilot

Select Copilot in Issue Assignees, pick a model, or delegate directly from VS Code / CLI.

3 Actions Sandbox

Runs copilot-setup-steps.yml, edits code, runs linters/tests, and self-reviews diffs.

4 Draft PR Loop

Leave PR review comments tagging @copilot to trigger automated follow-up commits.

Pre-Warming the Sandbox: .github/workflows/copilot-setup-steps.yml

The Coding Agent executes inside a firewalled Actions environment. Pre-installing runtimes, package caches, and database binaries in copilot-setup-steps.yml prevents firewall blocks during npm install or pip install and cuts task latency by 40–60%. Copilot Code Review also reuses this file by default. 

name: "Copilot Setup Steps"
on:
  workflow_dispatch:
  push:
    paths: [".github/workflows/copilot-setup-steps.yml"]

jobs:
  copilot-setup-steps:          # Exact job name required by GitHub Copilot
    runs-on: ubuntu-latest       # Ephemeral runner — NEVER a deploy runner
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: "pnpm" }
      - run: corepack enable && pnpm install --frozen-lockfile
      - run: pnpm build:types      # Pre-generate types so agent typecheck runs fast
R Automated PR Reviews via Branch Rulesets
  • Scale with Rulesets: Enable Automatically request Copilot code review in Repo or Org Branch Rulesets rather than relying on individual user toggles.
  • Choose Review Depth: Select Lite (fast syntax/bug pass), Balanced (default agentic diff check), or Max (deep cross-file reasoning for critical services).
  • Comment-Only Safety: Copilot Code Review leaves inline suggestions and comments—it never counts toward required human approvals or auto-merges code.
I Steering Coding Agent PRs Like a Teammate
  • Batch Your Feedback: Use GitHub's Start a review workflow to submit 3–5 inline comments in one review round so @copilot addresses everything in a single Actions run.
  • Inspect Session Logs: Click View session on the PR timeline to audit every shell command, file read, and test output the agent executed.
  • CLI / IDE Takeover: For the last 10% polish, check out the agent's copilot/* branch locally or hand off to Copilot CLI.
Security Gate: Manual Actions Approval on Agent PRs
By design, GitHub Actions CI workflows on a Copilot Coding Agent PR do not run automatically until a repository maintainer with write access clicks Approve and run workflows. Keep this gate enabled to review diffs before CI executes untrusted test code.

Hardening Autonomous Agents: Firewall, Exclusions & Audit

Autonomous agents execute shell commands, call external APIs through MCP, and open pull requests at machine speed. Enterprise security teams must pair developer autonomy with four non-negotiable guardrails across egress networking, file exclusions, secret protection, and audit telemetry.

Enterprise 4-Pillar Security Matrix

Security Pillar Risk Mitigated Recommended Control Verification Check
Coding Agent Firewall Prompt-injected data exfiltration or unauthorized package downloads from Actions sandboxes. Keep the default egress firewall ON with GitHub's recommended allowlist; review every custom domain entry. Test blocked curl in a scratch Coding Agent session; verify firewall logs.
Content Exclusions Sensitive credentials, customer PII, or proprietary algorithms leaking into prompts or reviews. Configure org-wide glob exclusions for .env*, **/secrets/**, *.pem, and *.key. Confirm excluded files show the blocked icon in VS Code & are skipped by Code Review.
Secret Scanning & Push Protection Agents accidentally committing hardcoded test tokens or leaking env vars into PR diffs. Enable GitHub Push Protection + Branch Protection + manual Actions workflow approval on agent PRs. Require 1+ human CODEOWNERS approval & green CodeQL check before merge.
MCP Governance & SIEM Audit Over-privileged third-party MCP servers or unmonitored agent mutations across org repos. Enforce Enterprise MCP Registry allowlists, OAuth 2.1 scopes, X-MCP-Lockdown, and SIEM audit streaming. Query SIEM for copilot.mcp_* and copilot.agent_* events weekly.
Z Zero-Trust MCP Hardening Checklist
  • Prefer Remote OAuth: Retire static PATs; OAuth 2.1 enforces per-user RBAC and instant revocation.
  • Default Read-Only: Start new MCP connections on /readonly and opt into write toolsets only per repo.
  • Block Untrusted Inputs: Enable X-MCP-Lockdown: true on public or open-source repositories to stop indirect prompt injection from external comments.
  • Pin Enterprise Registry: Restrict VS Code & Coding Agent to admin-approved MCP servers via Enterprise Policy.
E Phased Enterprise Rollout (4 Weeks)
  • Week 1 (Policies): Set Content Exclusions, Public Code Matching, and Enterprise MCP Registry allowlists.
  • Week 2 (Pilot): Enable VS Code Agent Mode + Remote GitHub MCP on 2 non-production repos with AGENTS.md.
  • Week 3 (Cloud Sandbox): Add copilot-setup-steps.yml + Branch Ruleset Copilot Code Review (Balanced).
  • Week 4 (Telemetry): Stream audit logs to Splunk/Sentinel, review AI credit burn, and publish internal templates.
Critical Rule: Never Run Copilot Coding Agent on Deployment Runners
Always run copilot-setup-steps.yml on ephemeral GitHub-hosted runners (or dedicated, network-isolated ephemeral self-hosted runners) with permissions: contents: read. Never assign Coding Agent to a runner pool that holds cloud deployment credentials, production kubeconfigs, or persistent disk state.

Troubleshooting Clinic (Top 7 Fixes) & Pre-Flight Checklist

When an autonomous workflow stalls, the cause is almost always a misconfigured toolset header, a firewalled Actions install, or bloated context. Use this clinic to diagnose issues in under two minutes, then run the 6-point pre-flight check before team rollout.

Top 7 Copilot Agent Mode & GitHub MCP Fixes

Symptom Root Cause Immediate Fix
1. Agent ignores custom instructions Wrong filename, invalid applyTo glob, or bloated 500+ line file diluted in context. Verify exact paths (.github/copilot-instructions.md or .github/instructions/*.instructions.md); check References drawer in Chat to confirm injection.
2. GitHub MCP OAuth fails or tools missing Enterprise MCP policy disabled, typo in X-MCP-Toolsets, or stale OAuth token. Sign out/in of GitHub in VS Code Accounts; verify exact toolset names (repos,issues,pull_requests,actions) and org MCP policy status.
3. Coding Agent fails npm/pip install Egress firewall blocks private registry or uncached downloads during agent execution. Move dependency installs into .github/workflows/copilot-setup-steps.yml and add private registries to the Coding Agent firewall allowlist.
4. Agent Mode loops & burns AI credits Unclear acceptance criteria, huge thread history, or missing test command in instructions. Stop the loop, revert to the last Checkpoint, start a fresh thread in Plan Mode, and set chat.agent.maxRequests to 25.
5. Code Review leaves noisy style nitpicks No review-specific instructions; reviewer defaults to generic style checks. Add a focused .instructions.md rule telling Copilot to flag only logic, auth, and security defects while ignoring formatting covered by Prettier/ESLint.
6. MCP write calls rejected (403) Connected to /readonly URL, X-MCP-Readonly: true set, or user lacks repo write role. Remove /readonly or set X-MCP-Readonly: false in .vscode/mcp.json and confirm your GitHub account has write access to the target repo.
7. Content exclusions not blocking files Glob pattern syntax mismatch or surface hasn't refreshed org policy cache. Use explicit repo-relative globs (**/.env*, **/secrets/**) in Org Copilot settings and reload VS Code window to pull updated policies.
