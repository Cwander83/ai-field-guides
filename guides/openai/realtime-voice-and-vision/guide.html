02 • Models, Cost & Transport Selection Choosing Between Realtime Models & Connection Bridges

Model Tiers & Transport Selection Matrix

Every Realtime build begins with two architectural choices: which native speech-to-speech model fits your reasoning and budget profile, and which network transport carries your audio frames cleanly from the user’s device to OpenAI.

1 gpt-realtime-2.1 (Flagship)
  • Best For: Complex troubleshooting, live camera inspection, multi-tool MCP orchestration, and empathetic customer care.
  • Strengths: Deepest instruction adherence, nuanced vocal prosody, reliable structured tool schemas, and sharp visual detail on dense UIs or hardware.
  • Tradeoff: Higher per-minute audio and image token rate; reserve for high-value interactive sessions.
2 gpt-realtime-2.1-mini (High-Volume)
  • Best For: Receptionist routing, appointment reminders, voice search, and high-concurrency kiosks or outbound campaigns.
  • Strengths: Dramatically lower per-minute spend, crisp snappy turn-taking, and low first-byte latency on straightforward intents.
  • Tradeoff: Lighter multi-step reasoning; keep prompts concise and hand off complex edge cases when needed.

Transport Decision Matrix: WebRTC vs. WebSockets vs. SIP / RTP

Rule of Thumb: Never Proxy Browser Audio Through Your Own WebSocket If WebRTC Fits
Proxying microphone chunks from a browser through your Node or Python backend over TCP WebSockets adds head-of-line blocking and extra round-trip jitter. Let browsers talk directly to OpenAI over WebRTC using an ephemeral token, and keep your server solely for minting secrets and running privileged MCP tools.

04 • Transports & Zero-Leak Authentication WebRTC Ephemeral Client Secrets, WebSockets & SIP Telephony

WebRTC Ephemeral Secrets, WebSockets & SIP

Golden Rule: Never embed your permanent OPENAI_API_KEY in browser JavaScript or mobile bundles. Instead, mint a single-use ephemeral key on your backend via POST /v1/realtime/client_secrets and hand only that short-lived token to the client.

1. Backend Route: Mint Ephemeral Secret (Node / Next.js)

// POST /api/realtime-token (runs strictly on your server)
const resp = await fetch('https://api.openai.com/v1/realtime/client_secrets', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + process.env.OPENAI_API_KEY,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    session: { type: 'realtime', model: 'gpt-realtime-2.1' }
  })
});
const { value: ephemeralKey } = await resp.json(); // Expires ~60s

2. Browser Client: Connect Over WebRTC

import { RealtimeAgent, RealtimeSession } from '@openai/agents/realtime';

const agent = new RealtimeAgent({
  name: 'SupportCopilot',
  instructions: 'Speak concisely in warm plain sentences.'
});
const session = new RealtimeSession(agent);
const { ephemeralKey } = await fetch('/api/realtime-token', { method: 'POST' }).then(r => r.json());
await session.connect({ apiKey: ephemeralKey }); // Auto-uses WebRTC
A WebSockets for Server Relays

When your backend already owns an audio stream (such as a Twilio Media Stream, game server, or compliance proxy), connect directly from Node or Python to wss://api.openai.com/v1/realtime?model=gpt-realtime-2.1 using your server-side API key and exchange base64 audio events.

B SIP / RTP Telephony Bridges

Connect Twilio, Telnyx, or enterprise SBC trunks via SIP signaling or carrier WebSocket bridges. Match codec settings to g711_ulaw (North America/Japan) or g711_alaw (Europe/global) at 8kHz so phone calls sound crisp with zero transcoding artifacts.

Three Transports, One Conversation Engine: Whether a caller joins via browser WebRTC (sapphire arch), a server-hosted WebSocket relay (violet fiber), or a PSTN SIP trunk (rose-gold coil), every pathway converges into the same gpt-realtime-2.1 full-duplex session.

Live Vision via addImage() & Voice Personas

Unlike text models where you upload an image and wait for a turn, addImage() lets your app push camera or screen frames silently into an ongoing voice conversation—giving the assistant shared eyes without interrupting audio. 

// Capture a clean 960px JPEG frame every 2 seconds (or on scene change) and push silently:
const canvas = document.createElement('canvas');
canvas.width = 960; canvas.height = 540;
canvas.getContext('2d')?.drawImage(videoEl, 0, 0, 960, 540);
const frameDataUrl = canvas.toDataURL('image/jpeg', 0.72);

// triggerResponse: false stores the visual frame in context without forcing the model to speak immediately
await session.addImage(frameDataUrl, { triggerResponse: false });
Throttle to 0.5–1 fps

Sending 30 frames per second wastes tokens and saturates mobile uplinks. One crisp frame every 1–2 seconds (or on button tap) covers 95% of visual tasks.

Cap Width at 768–1024px

Downscale 4K webcam or Retina screen grabs to 960px JPEG at 0.72 quality before calling addImage() to keep payloads fast.

Silent Context Updates

Keep triggerResponse: false for background frames so the model only comments when the user asks or a safety hazard appears.

06 • Turn-Taking & Non-Blocking Tools Server VAD, interrupt() Audio Truncation & Async MCP Calls

Native VAD, Barge-In & Async MCP Calls

Natural conversation demands two hard engineering guarantees: when the user cuts in, buffered assistant audio must stop within milliseconds; and when the model runs a slow database query, the voice channel must never go dead silent.

1. Tuning Server VAD & Clean interrupt()

// Configure Server VAD turn boundaries on session connect
turn_detection: {
  type: 'server_vad',
  threshold: 0.55,          // Raise to 0.65 in noisy rooms
  prefix_padding_ms: 300,   // Keep word-start consonants
  silence_duration_ms: 500  // Wait 500ms before claiming turn
}

// When user starts talking while playback buffer still plays:
session.on('audio_interrupted', () => {
  player.stopAndFlush();    // Clear WebAudio / speaker queue
  session.interrupt();      // Truncate unplayed server state
});

2. Non-Blocking Async MCP & Function Responses

// Do NOT block the audio loop waiting 2s for a CRM database!
// 1. Let the model speak a quick filler: "Checking order 402..."
// 2. Run MCP / API call asynchronously in the background:
const order = await mcpClient.callTool('get_order', { id: '402' });

// 3. Inject completed output back into the live session:
await session.sendMcpResponse(callId, order);
// (Or for standard function tools:)
await session.sendFunctionCallOutput(callId, JSON.stringify(order));
Why Calling interrupt() Keeps Memory Accurate
When a listener barges in two seconds into a ten-second audio reply, the model may have already generated text tokens ahead of the speaker buffer. Calling interrupt() (which triggers conversation.item.truncate) tells OpenAI the exact millisecond the listener actually heard, preventing the model from hallucinating that it finished explaining steps the user never heard.
Two Parallel Planes of Responsiveness: Top lane—incoming and outgoing soundwaves part instantaneously at the VAD Barge-In Gate when interrupt() fires. Bottom lane—glowing Async MCP Tool Sparks execute database and API calls off the main audio thread, delivering results via sendMcpResponse() with zero dead air.

07 • Acoustic Engineering & Spoken Safety Production Audio Hygiene, Codecs & Deterministic Guardrails

Production Audio Hygiene & Guardrails

Ninety percent of “the AI interrupted itself” or “the phone audio sounded robotic” bug reports are acoustic and codec hygiene issues—not model defects. Lock down these four production layers before going live.

1 Acoustic Echo Cancellation (AEC)

Without AEC, your laptop or phone speaker audio feeds straight back into the microphone—causing the assistant to hear its own voice and trigger a false barge-in loop.

  • In browsers, always request echoCancellation: true, noiseSuppression: true, and autoGainControl: true inside navigator.mediaDevices.getUserMedia().
  • On custom native apps, pair hardware AEC or WebRTC APM—never open raw uncancelled mic streams alongside loudspeakers.
2 Match Codec & Sample Rate End-to-End

Mismatched sample rates (sending 16kHz PCM into a 24kHz slot, or mixing mu-law and a-law) produce chipmunk pitch shifts or static hiss.

  • WebRTC: Opus 48kHz negotiated automatically via SDP.
  • WebSocket Server: pcm16 at 24000 Hz mono little-endian.
  • PSTN / SIP: g711_ulaw (US) or g711_alaw (EU) at 8000 Hz.

Deterministic Spoken Guardrails & Irreversible Action Gates

Guardrail Layer What Goes Wrong Without It Production Implementation Pattern
1. Two-Step Verbal Confirmation Background TV speech or misheard digits trigger an unwanted refund, cancellation, or wire transfer. Require explicit read-back inside tool logic: return a needsConfirmation state until the user confirms exact amount & target aloud.
2. Input & Topic Boundaries Callers jailbreak a public voice kiosk into giving medical, legal, or off-brand advice. Combine concise system boundaries with server-side classifier checks on transcripts before executing privileged MCP calls.
3. Quiet-Environment VAD Tuning Coffeeshop clatter or street traffic keeps resetting speech_started, blocking the assistant from speaking. Enable OpenAI’s near_field / far_field input noise reduction and raise VAD threshold from 0.50 to 0.65–0.72.
4. Silent Warm Handoff When two tool retries fail or caller frustration spikes, the bot loops apologetically forever. Expose an escalate_to_human tool that transfers the SIP call (or opens live chat) while passing a structured summary card.
Pro Audio Tip: Never Mix Push-to-Talk Prompts with Server VAD
If your UI offers a physical “Hold to Talk” button, disable turn_detection (null) and commit the buffer explicitly on release. Leaving server_vad active under push-to-talk causes premature cutoffs whenever a user pauses mid-thought while still holding the button.

09 • Observability & Resilience Latency Budgeting, ICE/TURN Diagnostics & Session Recovery

Latency Budgeting, Telemetry & Recovery

Sub-second voice feels effortless only when every hop in the audio path stays inside budget. Instrument these four timing checkpoints and build clean reconnect logic before exposing mobile users to spotty cellular handoffs.

End-to-End 800ms Perceived Turn-Around Budget

1. Capture + Network (~55ms)

Browser Opus frame encoding (~20ms) plus direct UDP WebRTC hop to OpenAI edge (~35ms). TCP proxies or distant TURN relays add 80–250ms.

2. VAD Endpoint (~350–500ms)

Controlled by silence_duration_ms. Dropping from 700ms to 400ms makes quick Q&A feel electric, while 850ms suits reflective coaching.

3. First Audio Byte (~220ms)

Measured from speech_stopped to first received audio packet. Keep system prompts lean and push large docs behind async MCP tools.

📡 WebRTC ICE / TURN Firewall Diagnostics

Corporate VPNs and strict hospital/school Wi-Fi networks frequently block outbound UDP ports, silently breaking plain STUN peer connections:

  • Log peerConnection.iceConnectionState and selected candidate pair (host, srflx, or relay).
  • Configure a TURN over TLS (port 443) fallback ICE server so enterprise users fall back gracefully instead of hanging on connecting.
! Reconnect & Transcript Audit Trails

Mobile callers switch from Wi-Fi to 5G mid-call. Recover smoothly without forcing the user to repeat their story:

  • Persist compacted user/assistant transcript turns and active tool results in local/server state as events arrive.
  • On WebRTC disconnect, mint a fresh ephemeral token, reconnect, and replay the last 4–6 turns via conversation item injection.
  • Scrub card numbers and SSNs from stored logs using audio/transcript PII redaction before archiving.
Track Time-to-First-Audio-Byte (TTFAB) Separately from Total Turn Duration
A 4-second spoken answer feels instant if audio starts in 240ms, whereas a 1-second answer feels broken if silence stretches past 1.4 seconds before the first syllable plays. Alert on P95 TTFAB spikes caused by bloated system instructions or oversized addImage() payloads.

11 • Diagnostics & Launch Readiness Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Almost every Realtime production hiccup maps to one of these seven transport, audio, or token issues. Run through this clinic and the six-point checklist before shipping to users.

Symptom / Error Root Cause 10-Second Fix
1. WebRTC hangs at connecting behind corporate NAT Strict firewall blocks outbound UDP STUN traffic, preventing peer-to-peer ICE negotiation. Inspect iceConnectionState and add a TURN over TLS (port 443) relay fallback in your RTC configuration so corporate browsers connect over HTTPS/TCP.
2. Self-echo triggers false barge-in loops Speaker playback bleeds back into the microphone and tricks Server VAD into firing speech_started. Enable echoCancellation: true and noiseSuppression: true in getUserMedia(), test with headphones first, and raise VAD threshold to 0.60+.
3. Exposed static API key flagged in client JS Browser bundle passes permanent sk-... OPENAI_API_KEY directly to session.connect(). Move OPENAI_API_KEY strictly to your backend and mint short-lived ek_... tokens via POST /v1/realtime/client_secrets per session.
4. SIP / G.711 audio sounds distorted or sped up Sample rate or codec mismatch (e.g., feeding 8kHz g711_ulaw carrier audio into a 24kHz PCM16 session). Explicitly declare g711_ulaw (or g711_alaw) on both input and output audio formats in session config, matching your carrier trunk verbatim.
5. addImage() payloads throttled or lagging audio Client uploads uncompressed 4K PNGs at 15–30 fps over the WebRTC data channel. Downscale canvas snapshots to 960px JPEG at 0.72 quality, throttle to 0.5–1 fps, and keep triggerResponse: false until needed.
6. Awkward dead air during tool calls Tool handler awaits a 3-second database query synchronously before the model can speak again. Prompt the model to speak a brief acknowledgment first, run slow MCP queries asynchronously, and return data via sendMcpResponse().
7. Ephemeral token expires before user clicks Start App pre-fetches ek_... on page load, but the user waits >60 seconds before clicking “Start Voice”. Mint the ephemeral secret on demand inside the Start click handler right before calling session.connect(), never at initial page render.
