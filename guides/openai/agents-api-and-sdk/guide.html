From Swarm Experiments to a Production Harness

In early LLM apps, engineers wrote fragile while True loops by hand: parsing tool JSON, catching schema errors, appending messages, and guessing why an agent stalled. The Agents SDK replaces that plumbing with a transparent execution loop owned by Runner. You define lightweight Agent objects (instructions, model, tools, handoffs, guardrails) and hand them to Runner.run(). If you prefer zero infrastructure management, the hosted Agents API runs the exact same harness server-side with managed threads, retries, and background execution.

Why Developers Love This Minimalist Design
Instead of learning proprietary graph DSLs, you write ordinary Python functions or TypeScript modules. Every step—tool calls, handoffs, MCP requests, and guardrail verdicts—emits structured spans automatically so debugging feels like reading a web request trace.

04 • Multi-Agent Orchestration Handoffs vs. Agents-as-Tools

Orchestration: Handoffs vs. Agents-as-Tools

Multi-agent engineering boils down to one architectural choice: should the specialist take over the conversation and speak directly to the user (Handoff), or perform a focused subtask and return data to a central manager (Agent-as-Tool)?

A Pattern 1: Specialist Handoffs

In a Handoff, the current agent invokes a built-in transfer tool (like transfer_to_billing_agent). The Runner swaps the active agent, passes conversation history (optionally pruned via input_filter), and lets the specialist own the user relationship from then on. 

triage = Agent(
    name="TriageRouter",
    instructions="Route billing or tech questions.",
    handoffs=[billing_agent, tech_agent],
)
B Pattern 2: Agents-as-Tools

With agent.as_tool() (Python) or agent.asTool() (TypeScript), a sub-agent runs inside an isolated tool call and returns a string or JSON result back to the Manager. The manager keeps full ownership of tone, final synthesis, and multi-source aggregation. 

manager = Agent(
    name="ReleaseManager",
    tools=[
        research_agent.as_tool(
            tool_name="fetch_changelog",
            tool_description="Summarize recent PRs."
        )
    ],
)
Left (Baton-Relay Handoff Ring): Control passes cleanly from node to node—ideal for customer triage, bilingual routing, and multi-stage onboarding where each specialist talks directly to the user. Right (Hub-and-Spoke Manager): A central conductor invokes specialist agents as tools in parallel and synthesizes one unified response.
Use Handoffs When:
  • Different domains need distinct personas, languages, or toolsets.
  • The user will continue chatting back and forth with that specialist.
Use Agents-as-Tools When:
  • You need one consistent voice synthesizing multiple sub-tasks.
  • Sub-agents should never leak intermediate reasoning to the user.

05 • Typed Tools & Structured Outputs Pydantic / Zod Contracts & Instruction Anatomy

Structured Tool Contracts & Typed Outputs

Reliable agents never rely on regex parsing. The Agents SDK generates strict JSON Schemas straight from your Python type hints (Pydantic) or TypeScript Zod definitions—and automatically feeds validation errors back to the model for deterministic self-correction.

Python: @function_tool + Pydantic output_type

from pydantic import BaseModel, Field
from agents import Agent, function_tool

class RefundDecision(BaseModel):
    approved: bool
    reason: str
    credit_cents: int = Field(ge=0)

@function_tool
def lookup_order(order_id: str) -> dict:
    """Fetch order status and purchase date by ID."""
    return db.get_order(order_id)

agent = Agent(
    name="RefundPolicy",
    tools=[lookup_order],
    output_type=RefundDecision,
)

TypeScript: tool() / functionTool + Zod

import { z } from "zod";
import { Agent, tool } from "@openai/agents";

const RefundDecision = z.object({
  approved: z.boolean(),
  reason: z.string(),
  creditCents: z.number().int().nonnegative(),
});

const lookupOrder = tool({
  name: "lookup_order",
  description: "Fetch order status and purchase date by ID.",
  parameters: z.object({ orderId: z.string() }),
  execute: async ({ orderId }) => db.getOrder(orderId),
});

const agent = new Agent({
  name: "RefundPolicy",
  tools: [lookupOrder],
  outputType: RefundDecision,
});

You are the Senior Billing Policy Evaluator for Acme Cloud. Always call lookup_order(order_id) before evaluating eligibility; never guess invoice totals or purchase dates from memory. 06 • Safety Gates & Built-In Tracing Parallel Guardrails, Tripwires & Span Telemetry

Defense-in-Depth Guardrails & Built-In Tracing

Treat prompts as guidance and Guardrails as enforceable gates. By running fast lightweight classifiers in parallel with your main agent, you block prompt injections, PII leaks, and off-topic abuse without adding extra serial latency.

1 Input Guardrails

Inspect user messages on entry. Default parallel mode starts checking while the main model begins thinking—canceling immediately if a tripwire fires, or set blocking mode to protect costly reasoning tokens.

2 Tool Guardrails

Validate arguments and side-effect scopes right before tool execution (e.g., blocking SQL writes, enforcing customer ID ownership, or masking secrets returned from MCP servers).

3 Output Guardrails

Verify the final response before it reaches the customer—checking for leaked system instructions, banned medical/legal claims, or unverified discount promises.

from agents import Agent, GuardrailFunctionOutput, InputGuardrail, InputGuardrailTripwireTriggered, Runner, trace

async def pii_gate(ctx, agent, user_input):
    verdict = await Runner.run(pii_classifier, user_input, context=ctx.context)
    return GuardrailFunctionOutput(
        output_info=verdict.final_output,
        tripwire_triggered=verdict.final_output.contains_ssn_or_card,
    )

support_agent = Agent(name="Support", input_guardrails=[InputGuardrail(guardrail_function=pii_gate)])

with trace("CustomerSupportTurn"):
    try:
        res = await Runner.run(support_agent, user_message)
    except InputGuardrailTripwireTriggered:
        res_text = "Please remove card numbers or SSNs before continuing."
Simultaneous Defense & Observability: Each stream passes through illuminated indigo input, tool, and output security gates while casting real-time span ribbons into the OpenAI Traces observatory—zero external APM agent required.
Group Multi-Turn Workflows With with trace("WorkflowName")
Wrapping several Runner.run() calls inside a single trace() block links triage, tool retries, and follow-up turns under one searchable parent timeline in the dashboard.

07 • Session Persistence & MCP SQLite Dev Memory, Redis Clusters & Stateful MCP Connectors

Durable State & Stateful MCP Server Sessions

Stateless scripts forget everything after one reply. The Agents SDK provides a drop-in Session protocol—starting with zero-setup SQLiteSession locally and scaling horizontally with RedisSession—alongside first-class connectors for persistent MCP tool servers.

1 Local Dev → Horizontal Redis

Pass a session directly to Runner.run(). The SDK automatically loads prior turns before inference and appends new tool and assistant items afterward. 

# Local dev: zero external infra
from agents import SQLiteSession
session = SQLiteSession("user_42", "dev_chat.db")

# Production cluster: pip install "openai-agents[redis]"
from agents.extensions.memory import RedisSession
session = RedisSession.from_url(
    "user_42",
    url="redis://cache.internal:6379/0",
    ttl=86400,
)
result = await Runner.run(agent, msg, session=session)
2 Three Native MCP Transports
  • MCPServerStdio: Launches local CLI tools (filesystem, git, sqlite) as a child process over stdin/stdout.
  • MCPServerSse: Connects to legacy remote MCP servers using HTTP Server-Sent Events streams.
  • MCPServerStreamableHttp: The modern production transport for cloud-hosted MCP gateways, supporting OAuth headers, clean bidirectional streaming, and load-balanced horizontal scaling.

Call list_tools() caching on connect to avoid redundant schema handshakes.

Wiring Persistent MCP Connectors Safely in Python & TypeScript

Always manage MCP server lifecycles with an async context manager (Python) or explicit try / finally cleanup (TypeScript) so child processes and HTTP keep-alive sockets close cleanly on errors: 

# Python: Connect streamable HTTP + stdio MCP servers with guaranteed cleanup
from agents import Agent, Runner
from agents.mcp import MCPServerStdio, MCPServerStreamableHttp

async with (
    MCPServerStdio(params={"command": "npx", "args": ["-y", "@modelcontextprotocol/server-git"]}) as git_mcp,
    MCPServerStreamableHttp(params={"url": "https://mcp.internal.dev/mcp", "headers": {"Authorization": "Bearer ..."}}) as prod_mcp,
):
    ops_agent = Agent(name="OpsResponder", mcp_servers=[git_mcp, prod_mcp], instructions="Diagnose incidents safely.")
    res = await Runner.run(ops_agent, "Check the last 5 commits and inspect failing service health.", session=session)
Tool Filtering Tip: Trim Unused MCP Tools Before Passing to the Agent
Large MCP servers can expose 40+ tools, inflating prompt tokens and confusing routing. Use create_static_tool_filter(allowed_tool_names=[...]) or dynamic per-user filters on your MCP connector so each specialist sees only the 3–6 tools it truly needs.

Never fix a production agent bug by guesswork. Export failed or tripped trace spans directly into an OpenAI Evals suite (or pytest/Vitest fixture) so every prompt or schema tweak is verified against real edge cases before deploy.

11 • Diagnostics & Launch Readiness Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Almost every multi-agent bug traces back to one of seven well-known runtime traps. Use this quick clinic to diagnose failures in ten seconds, then clear the six-point pre-flight checklist before shipping to production.

Symptom / Error Root Cause 10-Second Fix
1. Infinite handoff ping-pong between two agents Both specialists include each other in handoffs=[...] with overlapping routing instructions. Make handoffs a clean DAG (Router → Specialist), clarify negative routing boundaries, and cap turns with max_turns=8.
2. Process crashes with GuardrailTripwireTriggered Runner.run() raised a tripwire exception that wasn’t caught by the API route handler. Wrap Runner.run() in try / except (InputGuardrailTripwireTriggered, OutputGuardrailTripwireTriggered) and return a safe HTTP 400/200 fallback.
3. Strict JSON schema error on tool / output_type OpenAI strict mode rejects optional fields without defaults, untyped dict parameters, or additionalProperties. Use explicit Pydantic models or Zod objects with concrete types, clear field descriptions, and no bare unannotated dictionaries.
4. RedisSession stalls or times out under load A new Redis TCP client is created per request instead of sharing an async connection pool. Instantiate one shared redis.asyncio connection pool at app startup and pass it into RedisSession with an explicit ttl.
5. Zombie MCP subprocesses or socket leaks MCPServerStdio or MCPServerStreamableHttp was opened manually without closing on error. Always enter MCP servers via async with server: (Python) or try { ... } finally { await server.close(); } (TypeScript).
6. Customer PII appearing in OpenAI trace payloads Default tracing logs raw prompt and tool arguments when compliance requires metadata-only telemetry. Pass RunConfig(trace_include_sensitive_data=False) or scrub fields inside a custom TracingProcessor before export.
7. MaxTurnsExceeded aborts multi-step workflow An agent hits the default turn cap while sequentially polling 10+ tool calls one by one. Enable parallel tool calling, batch lookups into a single tool, or raise max_turns intentionally for deep research loops.

6-Point Pre-Flight Checklist Before Production Deploy

✓
Loop Budget Set: Every Runner.run() call sets an explicit max_turns cap and handles MaxTurnsExceeded.
✓
Tripwires Caught Cleanly: Both input and output guardrail exceptions return user-friendly fallback replies.
✓
Strict Schemas Verified: All tools and output_type classes pass Pydantic/Zod strict JSON Schema checks.
✓
Durable Session Pooled: Replaced local SQLiteSession with pooled RedisSession (plus TTL) or hosted Agents API threads.
✓
MCP Lifecycles Scoped: Connected MCP servers run inside context managers with filtered tool allowlists.
✓
Traces & Evals Wired: trace() spans scrub sensitive data where needed and failed spans feed your eval suite.
