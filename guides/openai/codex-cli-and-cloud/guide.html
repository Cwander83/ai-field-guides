Golden Pairing Rule: Start in local-container + automatic
Never jump straight to full-host out of convenience. Running automatic inside local-container lets GPT-6.1 Sol iterate through dozens of compile-and-test cycles uninterrupted while guaranteeing it cannot touch ~/.ssh, sibling repositories, or live production APIs.

Mastering config.toml, MCPs & AGENTS.md

Two plain-text files govern almost everything Codex does: ~/.codex/config.toml controls your model, sandbox defaults, and MCP tools, while hierarchical AGENTS.md files serve as your repository’s living engineering constitution.

1. ~/.codex/config.toml — Defaults & MCP Wiring

model = "gpt-6.1-sol"
approval_policy = "automatic"
sandbox_mode = "local-container"

[sandbox_workspace_write]
network_access = false

[mcp_servers.postgres_ro]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres"]
env = { DATABASE_URL = "${STAGING_RO_URL}" }

[mcp_servers.docs]
url = "https://mcp.internal.company.dev/sse"

2. Hierarchical AGENTS.md Cascade

1 Global (~/.codex/AGENTS.md): Personal preferences—preferred test flags, commit style, never touch .env.
2 Repo Root (./AGENTS.md): Architecture map, build/lint commands, and PR expectations shared via Git.
3 Subdirectory (./services/billing/AGENTS.md): Local overrides loaded only when editing files inside that service folder.
Keep AGENTS.md Actionable and Under 150 Lines
Treat AGENTS.md as an executive briefing, not a novel: list exact test commands (pnpm test --filter api), forbidden directories, and architectural boundaries. Push rare or step-heavy procedures into on-demand SKILL.md modules instead.
Defense in Depth Across Three Isolation Domes: Whether Codex runs inside a sealed read-only vault, a jailed local-container prism, or a full-host workshop, config.toml enforces tool boundaries deterministically while AGENTS.md supplies project judgment.

05 • Progressive Disclosure Skills Modular ~/.agents/skills/<name>/SKILL.md

On-Demand Skills: Keep Context Lean with SKILL.md

Stuffing twenty playbooks into AGENTS.md wastes precious context tokens and distracts the model. Codex solves this with progressive disclosure: only tiny skill names and trigger descriptions load at startup, while full SKILL.md instructions load only when a task matches.

Skill Folder Layout (User or Repo Scoped)

~/.agents/skills/db-migration/   # Personal across all repos
# or <repo>/.agents/skills/db-migration/
├── SKILL.md        # YAML frontmatter + step-by-step playbook
├── scripts/        # Optional deterministic verification scripts
└── references/     # Loaded only when deep schema docs needed

Frontmatter Index (Always Loaded, ~30 Tokens)

---
name: db-migration
description: Create, verify, and test reversible SQL
  migrations in packages/db. Use whenever adding columns,
  indexes, or altering Prisma/Postgres schemas.
---

Anatomy of a High-Precision SKILL.md Specification

Great skills trigger reliably without false positives. Combine these five color-coded building blocks inside your frontmatter and instructions:

[1. Crisp Trigger Description] [2. File Scope] [3. Ordered Workflow] [4. Scripts & MCPs] [5. Stop & Safety Guard]
Trigger when the user requests schema changes, table additions, or migration rollbacks. Restrict edits strictly to packages/db/migrations/ and packages/db/schema.sql. Step 1: Inspect existing migration order. Step 2: Author forward + down SQL. Step 3: Run reset test twice to prove idempotency. Execute scripts/check-locks.sh and inspect staging schema via [mcp_servers.postgres_ro]. Never drop non-empty columns without an explicit two-phase deprecation note; halt and report if drift is detected.

3-Stage Progressive Loading Lifecycle

Loading Stage What Enters Context Why It Boosts GPT-6.1 Sol Accuracy
Stage 1: Discovery name + description Costs only ~25–40 tokens per skill so you can keep 30+ specialized workflows installed with near-zero prompt bloat.
Stage 2: Activation Full SKILL.md body Injected only after your prompt matches the trigger description (or when you invoke $skill-name explicitly).
Stage 3: Deep Assets scripts/ & references/ Read selectively during execution; deterministic helper scripts execute directly without pasting huge boilerplate into chat.
Pro Tip: Write Trigger Descriptions Around User Intent, Not Implementation
Avoid vague descriptions like “Database helper.” State concrete situations (“Use when modifying SQL tables, indexes, or fixing migration checksum errors”) so Codex activates the right skill automatically on the first turn.

06 • Interactive Terminal Mastery TDD Loops, Safe Refactoring & MCP Tool Calling

Terminal Power Workflows with GPT-6.1 Sol

Because GPT-6.1 Sol pairs a ~500k+ token window with low-latency tool execution, Codex CLI shines at tight verify-as-you-go loops. Give it a concrete verification signal up front and watch it self-correct before you review a single line.

1 Test-Driven Fix Loops (Red → Green)

Never ask Codex to “fix the bug” in the abstract. Point it at a failing test or tell it to reproduce the failure first:

  • Reproduce: Write a failing unit test capturing the edge case and confirm it fails.
  • Patch Narrowly: Edit only the responsible module while keeping public types intact.
  • Verify Full Suite: Re-run targeted + integration tests before finishing.
2 Safe Structural Refactoring

When splitting files or renaming shared interfaces across dozens of callers, anchor Codex to compiler and lint gates:

  • Baseline Proof: Run tsc --noEmit and tests before touching code.
  • Atomic Moves: Refactor one boundary at a time and re-typecheck after each step.
  • Inspect Cleanly: Use /diff to audit every changed hunk prior to committing.

Live MCP Tool Calling Inside Your Terminal Loop

Tools wired under [mcp_servers.*] in ~/.codex/config.toml become native capabilities inside Codex CLI. Instead of copy-pasting database schemas, Sentry stack traces, or GitHub issue threads into your prompt, let Codex fetch live facts directly inside the reasoning loop: 

# 1. Start an interactive session with automatic workspace execution

# 2. Prompt combining MCP context + TDD verification loop:

  using postgres_ro, write a regression test in tests/billing.spec.ts that fails
  against current code, fix the N+1 join, and run pnpm test billing until green.

# 3. Essential interactive slash commands during long sessions:
/diff       # Inspect colorized git diff of every edit Codex made so far
/review     # Run a dedicated second-pass bug & regression check on uncommitted changes
/compact    # Summarize older turns while preserving key file paths and decisions
/resume     # Reopen a previous terminal session with full conversation state
Fast Non-Interactive Pipe

Run codex exec "Generate changelog from last 15 commits" inside scripts or pre-commit hooks for scripted one-shot output.

Checkpoint Before Risk

Commit or git stash clean work before multi-file refactors so reverting an unwanted experiment takes a single command.

Headless CI Review

Pair codex exec --sandbox read-only with PR diffs to catch missing null checks or migration hazards before human review.

Rapid Iteration Habit: Define “Done” as a Passing Command
Prompts ending with “and do not finish until pytest and ruff check pass with zero warnings” unlock GPT-6.1 Sol’s self-healing loop—turning first-draft syntax slips into zero-touch fixes before you look back at the terminal.

09 • Security, Secrets & Enterprise Governance Network Egress, Secret Scopes & CI/CD Review Gates

Security, Secret Hygiene & Enterprise Governance

Autonomous agents move fast—which makes clear boundaries non-negotiable. Codex separates build-time setup secrets from runtime environment access and disables untrusted outbound networking by default so credentials never leak through generated code or logs.

Never Paste Production API Keys into Prompts, AGENTS.md, or SKILL.md
Prompt files and repo markdown are transmitted to model context and committed to Git. Store credentials strictly in OS environment variables, secret managers, or Codex Cloud’s encrypted environment vault—never inside text instructions.
Network Egress Controls (Local & Cloud)
  • Default-Deny Outbound: Inside local-container and Codex Cloud execution phases, outbound internet access is disabled by default so agents cannot exfiltrate source code or pull unvetted binaries mid-run.
  • Two-Phase Cloud Lifecycle: Network access is enabled only during the pre-flight setup phase (to install npm/pip packages), then severed before the agent reads prompts or writes code.
  • Domain Allowlists: Enterprise admins can permit specific internal registries or test endpoints (e.g., registry.npmjs.org, internal PyPI) while blocking arbitrary HTTP calls.
! Secret Injection & Scoping
  • Setup Secrets vs. Agent Secrets: Keep private package registry tokens scoped strictly to the container setup step; strip them before agent execution starts.
  • Least-Privilege Test Keys: Inject only ephemeral staging or local-mock tokens into Cloud test environments—never production DB or billing credentials.
  • MCP Read-Only Wrappers: Configure ~/.codex/config.toml MCP tools (like Postgres) with read-only database roles for local triage.

Enterprise Audit Logs & CI/CD Review Gates

Governance Control How Codex Enforces It Recommended Team Policy
1. Workspace Audit Trail Every CLI command, MCP tool call, Cloud container log, and diff artifact is logged with timestamps and user identity. Stream Team/Enterprise audit logs to your SIEM and retain Cloud container test transcripts alongside PR links.
2. Zero Auto-Merge Rule Codex Cloud opens pull requests or branches but leaves merge authority with GitHub/GitLab branch protection. Require at least one human reviewer plus passing CI checks (CODEOWNERS + secret scanning) before merging.
3. Managed config.toml Baseline Admins can enforce organization-wide sandbox floors and block full-host escalation on corporate laptops. Pin default sandbox_mode = "local-container" and restrict network egress in managed workstation profiles.
Prompt Injection Defense: Separate Untrusted Data from Write Privileges
When asking Codex to summarize external web pages, third-party GitHub issues, or untrusted logs, keep the session in read-only sandbox or review every proposed shell tool call in suggest mode so hidden instructions in external text cannot trigger unintended writes.

Troubleshooting Clinic & Pre-Flight Checklist

Most Codex CLI or Codex Cloud hiccups trace back to one of seven predictable setup or sandbox snags. Use these ten-second fixes to get unblocked fast, then verify your repo with the pre-flight checklist.

Symptom / Error Root Cause 10-Second Fix
1. TOML syntax error on CLI launch Unquoted inline tables, stray commas, or duplicate keys in ~/.codex/config.toml. Validate TOML with python3 -c "import tomllib; tomllib.load(open('...','rb'))"; quote string values and remove trailing commas.
2. Sandbox permission denied on write or install Session is running in read-only or trying to write outside the jailed workspace root. Switch to --sandbox local-container for project edits, or install global tools manually outside Codex before retrying.
3. Custom SKILL.md never triggers automatically Missing YAML frontmatter, file not named SKILL.md, or vague description field. Confirm path is .agents/skills/<name>/SKILL.md, rewrite description with explicit trigger verbs, or invoke $<name> directly.
4. Codex ignores updated AGENTS.md rules Long-running session cached earlier rules, or a subfolder AGENTS.md overrides root guidance. Check active hierarchy in the session banner, start a fresh session or /compact, and keep rules crisp near the top.
5. MCP server times out at startup Slow npx download, missing environment variable, or server printing logs to stdout. Pre-install the MCP binary locally, verify env keys in config.toml, and route server logs to stderr only.
6. Cloud container network block during tests Tests try to hit external APIs after the setup phase sealed outbound networking. Install dependencies in the setup script, mock external HTTP calls in tests, or allowlist required test hosts in org settings.
7. Dirty worktree or Cloud PR merge conflict Uncommitted local edits collided with codex cloud apply, or base branch moved mid-run. git stash local changes before applying Cloud patches, or ask Codex on the PR branch to rebase onto latest main.

6-Point Pre-Flight Checklist Before Dispatching Autonomous Work

✓
Narrowest Sandbox Active: Confirmed local-container (or read-only for audits) rather than unnecessary full-host.
✓
Clean Git Working Tree: Committed or stashed unrelated changes before letting Codex edit or apply Cloud diffs.
✓
Crisp AGENTS.md Commands: Verified exact test, lint, and typecheck commands sit in the top 50 lines of AGENTS.md.
✓
Lean Progressive Skills: Moved specialized playbooks into .agents/skills/*/SKILL.md with clear trigger descriptions.
✓
Secrets Out of Prompts: Confirmed API keys live only in env vars or Cloud setup secrets, never inside Markdown files.
✓
Human Review Gate Armed: Paired autonomous runs with /diff, /review, and protected PR merge checks.
