Setup, 4 Vault Connection Modes & Decision Matrix

There are four distinct bridges between desktop AI agents and an Obsidian vault. Setting up all four takes under five minutes and lets you match every task to the fastest, safest transport.

1 Prerequisites & Account Tiers
  • Obsidian Desktop 1.12.4+: Free for personal & commercial vaults; includes native Properties, Bases, and official CLI.
  • Claude Desktop: Free/Pro supports local MCP servers; Pro, Max, or Team unlocks Cowork folder sessions.
  • Google Antigravity Desktop: Supports local Vault Projects, AGENTS.md/GEMINI.md, Scheduled Tasks, and Google Workspace plugins.
  • Local Runtimes: Node.js 20+ (npx) and Astral uv (uvx) for zero-install MCP execution.
2 3-Minute Obsidian Bridge Activation
  1. Enable Local REST API: In Obsidian open Settings → Community plugins → Browse, install Local REST API (by Adam Coddington), enable it, and copy the API key (default HTTPS port 27124 on 127.0.0.1).
  2. Register Official CLI: Go to Settings → General → Command line interface, toggle it On, and click Register CLI to link /usr/local/bin/obsidian.
  3. Mount Workspace: Open ~/Vault as a Project in Antigravity Desktop and grant folder access in Claude Cowork.
# Verify local runtimes, official Obsidian CLI registration, and Local REST API listener:
obsidian version                                   # Confirms /usr/local/bin/obsidian talks to running app
curl -k -s -H "Authorization: Bearer $OBSIDIAN_API_KEY" https://127.0.0.1:27124/ | head -c 120
which npx uvx                                      # Required by Claude Desktop & Antigravity MCP servers

04 • Claude Desktop Mastery Cowork Folders, Filesystem MCP & Surgical REST Patching

Claude Desktop: Cowork Folders & Surgical MCP Patching

Claude Desktop shines when wired with two complementary vault tools: direct folder access for sweeping research synthesis, and mcp-obsidian over port 27124 for surgical single-heading and frontmatter edits.

Production claude_desktop_config.json (Filesystem + Local REST API MCP)

Edit ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) or %APPDATA%\Claude\claude_desktop_config.json (Windows), then fully quit and relaunch Claude Desktop: 

{
  "mcpServers": {
    "vault-files": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/alex/Vault"]
    },
    "mcp-obsidian": {
      "command": "uvx",
      "args": ["mcp-obsidian"],
      "env": {
        "OBSIDIAN_API_KEY": "paste-your-local-rest-api-plugin-key",
        "OBSIDIAN_HOST": "127.0.0.1",
        "OBSIDIAN_PORT": "27124"
      }
    }
  }
}
A When to Use Cowork / vault-files

Choose Cowork folder sessions when creating brand-new notes, sorting 25 raw captures in 00-Inbox/, or distilling long PDFs into atomic resource notes. Because Cowork operates directly on disk alongside CLAUDE.md, it works even when Obsidian is closed and handles multi-file moves effortlessly.

B When to Use Surgical Patching

Never ask an LLM to rewrite a 2,000-word project hub just to add two action items. With mcp-obsidian (patch_content / vault_patch), Claude sets targetType: "heading", target: "Action Items", and operation: "append"—cutting token output by 90% and eliminating accidental prose deletions.

Two Precision Modes Over One Library: Surgical Local REST API conduits (left, amber beam) target a single heading or YAML key inside living notes, while workspace orchestration conduits (right, royal indigo) batch-route folders and scheduled rituals.
Tip: Use Absolute Executable Paths If Claude Cannot Find uvx or npx
GUI apps on macOS do not always inherit your shell’s Homebrew or Cargo PATH. If Claude Desktop shows a server startup warning, run which uvx and which npx in Terminal and paste full paths such as /opt/homebrew/bin/uvx into command.

06 • Vault Schema & Prompts Folder Taxonomy, AGENTS.md Laws & Prompt Anatomy

Vault Taxonomy, AGENTS.md Laws & Prompt Anatomy

AI agents thrive on predictable structure. A numbered six-folder taxonomy paired with a crisp AGENTS.md contract eliminates duplicate notes, malformed YAML frontmatter, and broken [[Wikilinks]].

1. Agent-Friendly Six-Folder Vault Taxonomy

00-Inbox/
Default landing zone for all new agent drafts, web clips, and untriaged transcripts.
01-Daily/
Chronological YYYY-MM-DD.md daily logs and YYYY-WXX-Review.md rollups.
02-Projects/
Active outcome-driven initiatives with clear deadlines and ## Action Items sections.
03-Areas/
Ongoing responsibilities (Health, Engineering, Finance, Team) with no end date.
04-Resources/
Atomic evergreen concept notes, paper summaries, and reusable reference guides.
99-Archive/
Completed projects and retired notes; agents treat as read-only historical context.

2. Production-Ready ~/Vault/AGENTS.md Schema Contract

# Vault Operating Contract (AGENTS.md)
1. WRITE BOUNDARIES: Place all brand-new notes in 00-Inbox/ unless a target path (such as 01-Daily/YYYY-MM-DD.md)
   is explicitly requested. NEVER modify .obsidian/workspace.json, .obsidian/app.json, or .obsidian/plugins/.
2. YAML FRONTMATTER: Every note MUST begin with valid YAML frontmatter containing:
   created: "YYYY-MM-DD"        # Always double-quote strings containing colons (:) or brackets
   type: "daily" | "project" | "area" | "resource" | "meeting"
   status: "inbox" | "active" | "completed" | "archived"
   tags: [lowercase-kebab-tags]
   summary: "One-sentence plain-text takeaway under 140 characters"
3. WIKILINK POLICY: Use Obsidian [[Note Title]] or [[Note Title|Display Text]] links—never relative Markdown URLs.
   Before creating a link, search existing titles in 02-Projects/, 03-Areas/, and 04-Resources/ to prevent duplicates.
4. SURGICAL EDITS: On existing notes over 300 words, append or patch target sections instead of rewriting whole files.

3. Color-Coded Vault Prompt Anatomy

Combine five explicit building blocks whenever asking Claude Desktop or Antigravity Desktop to transform messy inputs into linked vault knowledge:

[Scope] Read only @00-Inbox/2026-11-12-customer-call.md and @02-Projects/ onboarding hub notes. [Context] Extract the three recurring onboarding friction points and concrete engineering follow-ups raised during today’s enterprise call. [Frontmatter Contract] Follow AGENTS.md YAML schema with type: "meeting", status: "active", double-quoted summary, and tags: [onboarding, customer-research]. [Link Policy] Resolve existing note titles first; weave natural [[Note Title|Alias]] wikilinks to matching 02-Projects/ and 04-Resources/ notes without linking generic nouns. [Write Target] Save the clean meeting note to 00-Inbox/Customer-Call-Onboarding-Synthesis.md and surgically append owner-tagged checkboxes under ## Action Items in 02-Projects/Onboarding-Revamp.md.
Why [Scope] + [Link Policy] Matter
Explicitly naming source folders prevents 5,000-file fishing expeditions, while title-resolution before linking keeps your Obsidian Graph clean and connected rather than littered with ghost nodes.
Why [Write Target] Splits Output
Separating new synthesis (written to 00-Inbox/) from action-item mutation (patched under ## Action Items) gives you safe human review without losing momentum on active projects.

09 • Vault Safety & Rollback Protecting .obsidian/, Snapshots & Git

Protecting .obsidian/ Configs & 10-Second Rollback Safety

Giving desktop AI agents write access to years of personal notes requires defense in depth. Three lightweight guardrails guarantee that an over-eager bulk edit can always be undone in under ten seconds.

1. Why Agents Must Never Touch .obsidian/workspace.json or Plugin Binaries

Inside your vault root sits the hidden .obsidian/ configuration folder. While Obsidian is running, it continuously flushes pane geometry, cursor positions, and recent file state into .obsidian/workspace.json. If an agent edits that file mid-session, Obsidian immediately overwrites it or corrupts your split layout. Worse, allowing agents to modify .obsidian/plugins/*/main.js introduces arbitrary JavaScript execution inside a desktop Electron app. Treat .obsidian/ as strictly off-limits unless you explicitly ask for a CSS snippet inside .obsidian/snippets/.

Layer 1: Hard Rule + Perms

Forbid .obsidian/ writes in AGENTS.md and configure Antigravity Project-Level Permission Grants to require manual review outside 00-Inbox/ and 01-Daily/.

Layer 2: File Recovery

Open Obsidian Settings → Core plugins → File recovery. Set Snapshot interval to 5 minutes and History length to 30+ days for visual side-by-side diffs and 1-click single-note restore.

Layer 3: Git Checkpoints

Initialize Git in ~/Vault. Taking a two-second snapshot commit before any multi-file refactor gives you atomic diff inspection (git diff) and instant vault-wide undo.

2. Clean Vault .gitignore + Pre-Refactor Checkpoint Ritual

# ~/Vault/.gitignore — Track notes, templates, AGENTS.md & .agents/ skills; ignore volatile UI state:
.obsidian/workspace.json
.obsidian/workspace-mobile.json
.obsidian/cache
.trash/
.DS_Store

# Run before any bulk inbox sweep, frontmatter migration, or multi-note wikilink pass:
git add -A && git commit -m "checkpoint: pre-agent vault sweep"
# Inspect every changed line afterward — or roll back the entire batch in 2 seconds:
git diff --stat                  # Review exact notes touched
git checkout -- 02-Projects/     # Instant rollback if a batch edit over-reached

Credentials & API Keys OS Keychain or ~/.zshrc environment variables—never plain Markdown notes Passed only via MCP env config blocks, never indexed in prose.

11 • Troubleshooting & Pre-Flight Top 7 Fixes & 6-Point Vault Checklist

Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Nearly every hiccup between Obsidian, Claude Desktop, and Antigravity Desktop traces back to one of seven local configuration snags—each solvable in ten seconds.

Symptom / Error Root Cause 10-Second Fix
1. Local REST API TLS error or port 27124 refused Obsidian is closed, plugin disabled, or custom client rejects localhost self-signed cert. Keep Obsidian running, verify Local REST API is enabled on 127.0.0.1:27124, use mcp-obsidian (handles local cert), or test with curl -k.
2. Broken [[Wikilinks]] or duplicate note titles Agent guessed note names or emitted Markdown URLs instead of resolving vault titles. Add title-search rule to AGENTS.md: run obsidian search or directory list across 02-Projects/ & 04-Resources/ before writing links.
3. YAML frontmatter colons break Properties UI Unquoted colons in summary: Q4 Review: Phase 1 break Obsidian’s strict YAML parser. Enforce double quotes around all string values in AGENTS.md (summary: "Q4 Review: Phase 1") and run Recipe #3 on broken files.
4. Constant .obsidian/workspace.json churn Obsidian writes tab/scroll state every few seconds; agents or Git keep flagging diffs. Add .obsidian/workspace*.json and .obsidian/cache to .gitignore and forbid .obsidian/ edits in AGENTS.md.
5. macOS TCC blocks Documents / Desktop vault macOS privacy sandbox denies background node/uvx access to TCC-protected folders. Move vault to ~/Vault/ (home folder avoids TCC prompts) or grant Full Disk / Files & Folders access to Claude & Antigravity in System Settings.
6. Stale MCP Node / uvx processes after edits Changing OBSIDIAN_API_KEY or paths in JSON does not hot-reload spawned stdio children. Fully quit Claude Desktop (Cmd+Q), run pkill -f mcp-obsidian if orphaned, and relaunch to spawn fresh MCP workers.
7. Context window overload on 5,000+ note vaults Broad prompt triggers full-vault file reads across years of archives and attachments. Scope prompts with @00-Inbox/ or @02-Projects/ mentions, keep 99-Archive/ excluded by default, and query via obsidian search first.
