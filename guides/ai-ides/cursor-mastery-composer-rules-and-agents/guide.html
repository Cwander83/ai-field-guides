Scoped .cursor/rules/*.mdc, AGENTS.md & Context Hygiene

The biggest mistake teams make in Cursor is dumping 1,500 lines of guidelines into a single global rule. Scoped .mdc files inject only the rules relevant to the files being edited, keeping the context window crisp and adherence high.

Layered Context Architecture: Team Rules → Project AGENTS.md → Glob-Scoped .cursor/rules/*.mdc → On-demand @Docs & MCP tools, filtered by .cursorignore.

The 4 Activation Modes of .cursor/rules/*.mdc

Activation Mode YAML Frontmatter Config When Cursor Injects It Best Use Case
Always Apply alwaysApply: true Every Agent & Inline Edit turn in the repo. Short (<40 lines) stack invariants, package manager, error style.
Apply to Specific Files globs: ["src/api/**/*.ts"]
alwaysApply: false		 Automatically when matching files are open or referenced. API validation, React component conventions, SQL migration rules.
Apply Intelligently description: "Use when..."
alwaysApply: false		 Agent decides based on task intent matching description. Workflows like "writing Playwright E2E tests" or "creating PRs".
Apply Manually No globs, no description, alwaysApply: false Only when explicitly invoked via @rule-name in chat. Heavy checklists, release runbooks, or security audit templates.
AGENTS.md Standard

Cross-IDE Markdown file at repo root (or subdirectories) read by Cursor, Claude Code, and Codex. Store universal build/test commands and repo map here; put Cursor-specific globs in .cursor/rules/.

@Docs & @Codebase

Index third-party API docs once in Settings → Indexing & Docs, then cite @Docs so agents stop hallucinating outdated SDK signatures. Use @Git to diff against main.

.cursorignore Shield

Uses .gitignore syntax to block .env*, keys, generated artifacts, and vendor bundles from Tab, Agent, and indexing—improving both security and retrieval signal.

Rule Precedence & Size Budget
Cursor merges rules in order: Team Rules (Admin) → Project .cursor/rules/*.mdc & AGENTS.md → User Rules. Keep each .mdc file under 80–120 lines and link to one canonical reference file instead of pasting huge boilerplate.

Anatomy of a High-Precision .mdc Rule & Agent Prompt

Vague rules like “write clean TypeScript” waste tokens and get ignored. High-precision rules and prompts follow a five-part contract: Scope, Role, Hard Invariants, Concrete Anchor, and Verification Gate.

Part A: Color-Coded 5-Part .cursor/rules/api-handlers.mdc Blueprint

1. Frontmatter Scope  ---
description: "Enforce Zod validation, typed errors, and auth guards on Next.js API routes"
globs: ["src/app/api/**/*.ts"] • alwaysApply: false  ---
2. Role & Boundary  You are modifying production HTTP route handlers. Keep handlers thin: parse input, check session, delegate business logic to src/services/.
3. Hard Invariants (NEVER / ALWAYS)  ALWAYS validate request bodies with zod before DB calls. NEVER return raw Prisma errors or stack traces. ALWAYS wrap mutations in withAuth() and return { data, error } envelope.
4. Canonical Code Anchor  Mirror the exact error mapping and status codes in @src/app/api/invoices/route.ts (lines 12–48). Do not invent new response helpers.
5. Verification Gate  After editing any route, run pnpm vitest run src/app/api and pnpm tsc --noEmit. Fix all failures before summarizing.

Part B: The 5-Part High-Precision Agent Prompt Formula

[1. Outcome] Add rate-limited webhook retry handling for invoice.payment_failed. [2. Explicit @Context] Reference @src/billing/webhook.ts, @src/lib/queue.ts, and @Docs: Stripe v17. [3. Constraints] Keep idempotency keys in Redis (24h TTL); do not modify DB schema or touch unrelated billing routes. [4. Plan Gate] First enter Plan Mode: list the exact files you will edit and edge cases for duplicate deliveries. Wait for approval. [5. Definition of Done] Add unit tests covering 1st success, duplicate event skip, and 5th-attempt dead-letter queue; run pnpm test billing until green.
✓ High-Signal Patterns (Do This)
  • Point to 1 real file (@src/services/orders.ts) instead of writing 60 lines of abstract prose.
  • State negative constraints (“Do NOT add new npm packages”) to curb over-engineering.
  • Start fresh chats per task (Cmd+N) once a feature merges so old diffs don't pollute context.
  • Include a runnable verifier (unit test, typecheck, curl, or Playwright script) in every task.
× Context Anti-Patterns (Avoid)
  • Mega-rules (>300 lines) set to alwaysApply: true—models silently drop middle instructions.
  • Pasting entire stack traces + 15 files when only 2 files matter—hurts retrieval precision.
  • Skipping Plan Mode on cross-cutting refactors, causing 4–5 expensive retry loops.
  • Asking “fix it” without pasting the failing test output or expected invariant.
Pro Tip: Auto-Generate Rules from PR Review Feedback
Whenever a human reviewer or Bugbot catches a recurring mistake, run one Agent prompt: “Turn this PR comment into a concise, glob-scoped .cursor/rules/ file under 40 lines.” Your repo gets smarter every sprint.

Scaling Out: Cloud Agents, Git Worktrees & Cursor CLI

Single-threaded prompting caps your throughput at one task at a time. Combine local Git worktrees, remote Cloud Agents (formerly Background Agents), and headless Cursor CLI to run 3–6 engineering streams in parallel.

1 Parallel Local Git Worktrees

Cursor creates isolated Git worktrees per Agent chat (via the Worktree picker or /worktree) so multiple agents edit, build, and run tests simultaneously without branch collisions.

// .cursor/worktrees.json
{
  "setup-worktree": [
    "cp $ROOT_WORKTREE_PATH/.env.local .env.local",
    "pnpm install --frozen-lockfile"
  ]
}

Best-of-N pattern: Launch 2–3 worktree agents on the same hard refactor (e.g., Composer 2.5 + Claude) and merge the cleanest diff.

2 Cloud Agents (Async Remote VMs)

Each Cloud Agent boots an isolated cloud VM, clones your repo (or multi-repo frontend + backend + shared libs), installs dependencies, runs tests, and opens a GitHub PR—even after you close your laptop.

  • Handoff from IDE/CLI: Prefix any prompt with & to push the session to a Cloud Agent.
  • Multi-surface triggers: Launch from Cursor Web, iOS voice chat, Slack @Cursor, or Linear/GitHub issues.
  • Ideal tasks: Test coverage gaps, dependency upgrades, lint/type migrations, well-specified bug tickets.

Cursor CLI (agent / cursor-agent): Terminal & CI Automation

Cursor CLI runs the exact same agent harness, rules, and MCP config from any terminal, SSH box, or GitHub Actions runner:

CLI Command Behavior Production Workflow
agent / agent "refactor auth" Starts interactive terminal session; Shift+Tab cycles Agent/Plan/Ask. SSH remote boxes, tmux panes, fast keyboard-only coding.
agent --worktree "add caching" Spins up an isolated Git worktree and runs setup from worktrees.json. Parallel local branches without disturbing your current IDE state.
agent -p "prompt" --model composer-2.5 --output-format text Headless non-interactive run returning clean stdout for piping. GitHub Actions docs-sync, release notes, automated triage scripts.
agent --mode=ask -p "audit diff" Strictly read-only exploration with zero file modification rights. CI security checks, PR summaries, architecture Q&A bots.
agent --sandbox enabled Restricts shell execution to workspace sandbox; /sandbox sets network. Safe autonomous runs in untrusted branches or CI pipelines.
agent ls / agent --resume="id" Lists or resumes prior CLI sessions; /open opens repo in Cursor IDE. Start in terminal, hand off to IDE for visual diff review.
Decision Rule: Local Worktree vs. Cloud Agent vs. Cursor CLI
Use Local Worktrees when you need rapid visual review, local Docker DBs, or browser preview. Use Cloud Agents when tasks take 10–45 minutes or span multiple repos asynchronously. Use Cursor CLI (-p) when triggering deterministic agent steps inside GitHub Actions or shell scripts.

Bugbot Automated PR Reviews & .cursor/mcp.json Wiring

Shipping faster with agents increases PR volume. Pair Bugbot (automated PR bug & security auditing) with Model Context Protocol (MCP) servers so Cursor reads live specs, issues, schemas, and PR checks directly.

Live Tool Fabric: Cursor connects to Figma, Linear, Supabase, and GitHub via .cursor/mcp.json (stdio & Streamable HTTP), while Bugbot guards every PR before merge.
B Bugbot PR Review Engine
  • Fast Composer 2.5 engine: Reviews PRs in ~90 seconds on average, flagging logic bugs, null dereferences, race conditions, and auth flaws.
  • Separate rules file: Bugbot reads .cursor/BUGBOT.md (and Automation rules)—it does not read .cursor/rules/*.mdc.
  • Manual trigger & Autofix: Comment cursor review or bugbot run on any PR; click Fix in Cursor or Autofix to patch inline.
  • Noise control: Document intentional patterns in BUGBOT.md so Bugbot stays high-signal and reviewers never scroll past it.
M .cursor/mcp.json Architecture
  • Project vs. Global: Commit .cursor/mcp.json for team-shared tools; keep personal tokens in ~/.cursor/mcp.json or env vars.
  • Two transports: stdio (local child process via command + args) and Streamable HTTP / SSE (remote url + OAuth).
  • Team MCPs: Enterprise/Teams admins can distribute vetted MCP servers centrally via Settings → Tools & MCP.
  • Least privilege: Start every new MCP server in read-only mode and require explicit tool-call approval for write mutations.

Privacy Mode, Team Security Hardening & Spend Control

Enterprise adoption succeeds when security and finance teams have verifiable controls. Understand exactly what Cursor's Privacy Mode guarantees, where retention exceptions exist, and how to cap multi-model spend.

1 What Privacy Mode Guarantees
  • No model training: Prompts, diffs, and codebase snippets are never used to train Cursor or third-party foundation models.
  • Zero Data Retention (ZDR): Cursor maintains ZDR agreements with supported Cursor-routed inference providers.
  • Org enforcement: Teams & Enterprise admins lock Privacy Mode ON org-wide so individual seats cannot disable it.
! What Privacy Mode Does NOT Do
  • Not local inference: Prompts and relevant code context still traverse Cursor servers to model providers over TLS.
  • Cloud Agent retention: Cloud Agent transcripts persist by default and VM snapshots expire after 30 days of inactivity.
  • Exceptions: Non-ZDR models (opt-in) and BYOK provider keys follow the external provider's own retention terms.

Defense-in-Depth Governance Controls

Control Layer Exact Configuration Risk Mitigated
Secret Exclusion Commit .cursorignore blocking .env*, *.pem, secrets/, terraform.tfstate. Prevents API keys and PII fixtures from entering Tab, Agent, or codebase embeddings.
Command Sandboxing Enable OS sandbox (--sandbox enabled); allowlist only pnpm test, vitest, tsc, eslint. Blocks runaway shell commands, accidental rm -rf, or unauthorized network exfiltration.
MCP Approval Gates Restrict Team MCPs to vetted servers; require click confirmation on all write/delete tools. Stops prompt-injection attacks via external GitHub issues or tickets from mutating prod systems.
Spend & Pool Caps Set per-seat monthly third-party API caps; route routine loops to Cursor weekly pool (Composer 2.5). Prevents unexpected API overages when engineers leave frontier reasoning models selected all day.

Multi-Model Cost Control Playbook (Cut Spend 40–65%)

1. Default to Composer 2.5

Draws from your included weekly Cursor pool at 4× faster speed. Switch to third-party Claude/GPT/Gemini only for Plan Mode or thorny root-cause bugs.

2. Reset Chats Per Task

Long 40-turn threads resend tens of thousands of stale tokens on every message. Open a new chat (Cmd+N) for each sub-task or PR.

3. Trim Global Rules

Move framework guidelines out of alwaysApply: true into glob-scoped .mdc files so backend edits never pay for frontend prompt tokens.

Security Rule of Thumb for Regulated Repos (SOC 2 / HIPAA / GDPR)
Pair Admin-Enforced Privacy Mode + .cursorignore + Disabled Non-ZDR Models + Read-Only Dev MCPs. Review Cloud Agent transcript retention policy with Legal before enabling Cloud Agents on regulated repositories.
