Installation, Aider Edit Formats & Harness Matrix

Both Aider and Block Goose install cleanly on macOS, Linux, and Windows (WSL2 or native) without vendor lock-in. Choosing the right installation channel and Aider edit format prevents patchy diffs and wasted tokens on your very first run.

1 Fast Install: Aider & Block Goose
  • Aider via uv (Recommended): Run uv tool install aider-chat (or python -m pip install aider-install && aider-install) inside an initialized Git repo.
  • Aider Model Prefixes: Set API keys in environment or .env, then launch with anthropic/..., openai/..., gemini/..., or local ollama_chat/....
  • Goose CLI (AAIF / Block): Run curl -fsSL https://github.com/aaif-goose/goose/releases/download/stable/download_cli.sh | bash or brew install block-goose-cli, then run goose configure.
  • Goose Desktop & Web: Pair the terminal CLI with Goose Desktop (macOS/Windows) or goose web for visual recipe forms and clickable activities.
2 Mastering Aider Edit Formats
  • diff (Search/Replace): Default for most frontier models; replaces targeted blocks using SEARCH/REPLACE fences so large files stay cheap.
  • udiff (Unified Diff): Simplified unified diff syntax ideal for reasoning models like GPT-4o/o-series on multi-hunk edits across long files.
  • whole (Full File Rewrite): Model outputs the entire updated file; reliable for smaller files or local 7B–14B Ollama models that fumble line anchors.
  • architect + editor-diff / editor-whole: Separates free-form design reasoning from strict syntax patching across two specialized models.

04 • Aider Core Workflows Repo Map, Context Hygiene, /architect Split & Lint/Test Loops

Aider Mastery: Repo Map, Context Hygiene & Auto-Fix Loops

Aider earns its reputation on reliability: instead of stuffing random files into an overflowing prompt, it builds a graph-ranked map of your repository, edits only explicitly staged files, and tests every patch automatically.

Graph-Ranked Precision: Tree-sitter parses functions and call sites into a PageRank graph, guiding the /architect planner and fast editor model straight to the files that need atomic commits.

Four Habits That Make Aider Unbeatable on Real Codebases

1 Tune the Tree-Sitter Repo Map

Aider parses code into ASTs with tree-sitter and runs PageRank over cross-file symbol references. Default --map-tokens is 1024; bump to 2048–4096 on multi-package repos, inspect with /map, or pass --subtree-only in giant monorepos.

2 Separate /add From /read-only

Add only the files you intend to modify via /add path/to/file. Load style guides, OpenAPI specs, or reference modules with /read-only so Aider reads them accurately without accidentally editing them, and run /drop as soon as a module is done.

3 Split Reasoning With /architect

Run /architect (or --architect) so a strong reasoning model proposes architectural changes in plain prose without wrestling diff syntax, while a fast --editor-model (such as a local Ollama coder or Haiku) applies exact editor-diff patches.

4 Wire Auto-Lint & Auto-Test Loops

Run /lint on modified files or /test pytest -q inside chat—or enable --auto-lint and --auto-test. Whenever a linter warning or test traceback fires, Aider captures stdout and self-corrects before moving on. 

# Launch Aider in dual-model Architect mode with read-only conventions, 2048-token Repo Map, and test auto-fix loop:
aider --architect \
  --model anthropic/claude-sonnet-4-5 \
  --editor-model ollama_chat/qwen2.5-coder:32b --editor-edit-format editor-diff \
  --read CONVENTIONS.md --map-tokens 2048 \
  --lint-cmd "ruff check" --auto-lint --test-cmd "pytest -q" --auto-test
Pro Tip: Use /ask Before Refactoring, /code When Ready
Unsure how a module interacts with billing or auth? Prefix a turn with /ask (or switch temporarily out of edit mode) to interrogate the Repo Map with zero file modifications, then return to /code or /architect once the plan is crisp.

05 • Config, Watch Mode & Formula .aider.conf.yml, CONVENTIONS.md, # AI! Comments & 5-Part Loop

.aider.conf.yml, Watch Comments & the 5-Part Formula

Once your repo includes .aider.conf.yml and CONVENTIONS.md, starting Aider takes two words. Watch mode (--watch-files) turns any IDE or text editor into a live prompt canvas using inline AI! and AI? comments.

Editor-Native Watch Mode (--watch-files)
  • # ... AI! (Trigger Edit): Save a comment like // Add rate-limit retry with backoff AI! in VS Code, Neovim, or Zed. Aider modifies the code, deletes the marker, and commits cleanly.
  • # ... AI? (Ask Without Editing): Save # Why does this deadlock under load? AI? to get an explanation right in the terminal pane without altering source files.
  • Zero Context Switching: Works alongside any editor, Markdown doc, or Obsidian note—ideal when spotting small bugs mid-review.
Config Precedence & CONVENTIONS.md
  • 4-Layer Precedence: CLI flags override environment variables (AIDER_*), which override repo-root .aider.conf.yml, which overrides ~/.aider.conf.yml.
  • Persistent CONVENTIONS.md: List read: [CONVENTIONS.md] in YAML so Aider always obeys your typing rules, test fixtures, and error conventions read-only.
  • Weak Model Savings: Assign weak-model to a fast inexpensive model to generate Git commit messages and Repo Map summaries automatically.

The 5-Part Open-Harness Execution Formula

[1. Repo Map & Hints] Scoped AST graph + CONVENTIONS.md / .goosehints, [2. Architect / Lead Plan] reasoned by a frontier model without syntax clutter, [3. Editor / Worker Diff] patched cleanly into scoped files or MCP actions, [4. Lint, Test & Smart Approve] verified by automated gates & human consent, [5. Atomic Commit / Recipe] and saved as a reversible Git commit or YAML Recipe.
Harness Stage What It Governs What Breaks When Skipped
Repo Map & Hints Supplies real symbol names, repo conventions, and off-limits secrets. Models hallucinate non-existent helpers or invent inconsistent patterns.
Architect / Lead Plan Isolates multi-file design choices before generating line-by-line diffs. Single-pass coding models jump into dead-end patches and waste turns.
Editor / Worker Diff Uses fast, low-cost models tuned for clean diff / whole or tool calls. Frontier models burn 5x–10x budget rewriting boilerplate lines manually.
Verify & Approve Runs /lint, /test, and smart_approve checks before acceptance. Silent regressions or unsafe shell side effects slip into your workspace.
Commit / Recipe Records an atomic Git SHA (/undo) or reusable Goose YAML workflow. Broken multi-file edits tangle with human WIP and cannot be cleanly reverted.

07 • Reusable YAML Recipes & Lead/Worker Parameters, Sub-Recipes, Deeplinks & Routing

YAML Recipes, Sub-Recipes & Lead/Worker Routing

Once a multi-step MCP workflow clicks, freeze it into a versioned Goose YAML Recipe. Recipes lock down exact extensions, typed parameters, isolated sub_recipes, and Lead/Worker model routing—and share cleanly across teams via goose:// deeplinks.

Composable Isolation: A parent YAML Recipe delegates independent scans to isolated sub_recipes so worker sub-sessions never bloat the parent context window, then merges verified results safely.
1 Parameters, Sub-Recipes & Deeplinks
  • Typed parameters: Define key, input_type (string, number, boolean, date, file, select), and requirement (required, optional, user_prompt), interpolated via {{ key }}.
  • Isolated sub_recipes: Delegate parallel audits or clean-room subtasks without polluting parent chat memory.
  • Validate & Share: Run goose recipe validate file.yaml, execute via goose run --recipe, or mint a clickable Desktop link with goose recipe deeplink file.yaml.
2 Lead/Worker Cost & Recovery Routing
  • Smart Handoff: Set GOOSE_LEAD_MODEL (plus GOOSE_LEAD_PROVIDER) for planning while your configured fast GOOSE_MODEL executes routine tool steps.
  • GOOSE_LEAD_TURNS: Controls how many opening turns the Lead model directs architecture before handing execution to the worker.
  • Auto-Rescue Thresholds: Set GOOSE_LEAD_FAILURE_THRESHOLD (e.g., 2 errors) and GOOSE_LEAD_FALLBACK_TURNS so the Lead model automatically steps back in whenever the worker gets stuck.
version: "1.0.0"
title: "PR Security & Dependency Audit"
description: "Runs isolated dependency and secret checks against a target branch."
parameters:
  - key: target_branch
    input_type: string
    requirement: optional
    default: "main"
    description: "Git branch or tag to diff against"
instructions: |
  Diff current changes against {{ target_branch }}, invoke both sub-recipes, and return a concise Markdown risk report.
extensions:
  - type: builtin
    name: developer
    timeout: 300
sub_recipes:
  - name: "dep_audit"
    path: "./subrecipes/dep-audit.yaml"
  - name: "secrets_scan"
    path: "./subrecipes/secrets-scan.yaml"

09 • Safety, Permissions & Governance Git Reversibility, GOOSE_MODE & Ignore Guards

Git Commit Safety, Permission Modes & Team Guardrails

Autonomous terminal agents hold real keys to your filesystem, Git history, and external MCP APIs. Pairing Aider’s clean commit isolation with Goose’s risk-tiered GOOSE_MODE and permission.yaml policies keeps experimentation fearless and auditable.

1 Aider Git Isolation & Secret Masks
  • dirty-commits: true + /undo: Commits any dirty human edits in their own commit first so AI changes land on a clean SHA that /undo reverts safely.
  • Commit Attribution: Configure attribute-author and attribute-committer flags in .aider.conf.yml so code reviewers see AI-coauthored commits clearly.
  • .aiderignore Shield: Block .env*, private keys, certificates, and bulky node_modules/ or dist/ builds from ever entering the Repo Map or chat.
2 Goose GOOSE_MODE & Tool Tiers
  • Four Macro Modes: Choose chat (zero tools), approve (ask before every write/shell), smart_approve (auto-allow safe reads, prompt on risky writes), or auto (unattended—sandbox only!).
  • permission.yaml Rules: Pin individual MCP tools under always_allow, ask_before, or never_allow inside ~/.config/goose/config/permission.yaml.
  • .gooseignore Shield: Uses gitignore syntax to block Goose from reading .env secrets, credentials, or sensitive customer exports.

Change Rollback Atomic Git commit per turn + instant /undo Git status diff + approve pre-write review Always work on a feature branch

10 • Cross-Tool Synergy MCP Discovery → Git Coding → Team Recipe

Cross-Tool Synergy: Goose Orchestration + Aider Commits

Instead of forcing one tool to do everything poorly, chain Block Goose and Aider across four crisp stages: Goose gathers cross-app evidence via MCP, Aider writes tested Git commits inside strict file scopes, and Goose ships verified PRs and reusable team recipes.

Four-Step Daily Execution Loop

1 Triage Cross-App Context in Goose

Let Goose pull issue comments, database schemas, or failing CI logs via MCP, then distill findings into a focused spec file (specs/task.md) before touching production code.

2 Scope & Plan Inside Aider

Add specs/task.md and CONVENTIONS.md via /read-only, /add only the modules to modify, and verify callers through the tree-sitter Repo Map and /architect.

3 Patch, Auto-Test & Commit Atomically

Let the editor model apply clean diff patches (or respond to # AI! watch markers), verify green /lint and /test runs, and keep or /undo each commit cleanly.

4 Verify & Package as a Team Recipe

Hand final checks back to Goose sub_recipes (browser smoke checks via computercontroller, PR updates via MCP), and export repeatable steps with goose recipe deeplink.

Compound Every Session Back Into Shared Hints
Whenever an agent trips over an obscure environment flag, mock fixture, or API quirk, add a single crisp bullet to both CONVENTIONS.md and .goosehints (or Goose’s memory extension) so neither harness makes the same mistake twice.

11 • Diagnostics & Pre-Flight Top 7 Harness Issues, 10-Second Fixes & 6-Point Rollout Checklist

Troubleshooting Clinic & Pre-Flight Checklist

Keep this clinic handy whenever Aider hallucinates out-of-scope symbols, local models break diff syntax, watch markers get ignored, or Goose MCP servers and YAML Recipes need a quick diagnostic check.

Symptom / Issue Root Cause 10-Second Fix
1. Aider misses callers or invents wrong function names --map-tokens too tight, or target files weren’t added via /add or /read-only. Run /map to inspect coverage, raise --map-tokens 2048 (or 4096), and add reference headers with /read-only.
2. Local Ollama model mangles diff patches Small/mid local coders struggle with strict SEARCH/REPLACE fencing. Pass --edit-format whole for small files, or pair a frontier --architect model with --editor-edit-format editor-whole.
3. /undo refuses or entangles human WIP Dirty uncommitted edits in Git mixed with AI patches, or --no-auto-commits set. Enable dirty-commits: true and auto-commits: true in .aider.conf.yml, or commit WIP before starting Aider.
4. --watch-files ignores # AI! comments Comment syntax missing trailing AI!/AI?, or file matched .aiderignore. End comment cleanly with AI! (edit) or AI? (question), save the file, and verify path is not excluded in .aiderignore.
5. Goose MCP extension fails or times out Missing npx/uvx binary on PATH, bad env var, or default timeout too short. Test standalone with goose mcp <name>, check ~/.config/goose/config.yaml, and set timeout: 300 on slow servers.
6. Goose runs shell commands without asking Session launched in GOOSE_MODE=auto instead of gated approval. Set export GOOSE_MODE=smart_approve (or /mode approve live) and place developer__shell under ask_before in permission.yaml.
7. YAML Recipe params fail or Lead/Worker loops Missing key/requirement match or low GOOSE_LEAD_FAILURE_THRESHOLD. Run goose recipe validate file.yaml, verify {{ param }} names match parameters[].key, and tune GOOSE_LEAD_FAILURE_THRESHOLD=2.
