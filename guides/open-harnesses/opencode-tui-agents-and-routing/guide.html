04 • Dual-Mode Discipline Mastering Read-Only Plan Mode vs. Full-Access Build Mode

The Tab Key Habit: Separate Architecture From Mutation

The fastest way to wreck a codebase is letting an eager agent edit ten files before understanding how your auth middleware works. Pressing Tab switches OpenCode into Plan Mode—physically disabling file edits and destructive shell commands while the agent maps out a surgical blueprint.

Two Modes, One Keystroke (Tab): Inspect, search, and crystallize edge cases safely inside the read-only Plan frame (left) before flipping to Build mode (right) to execute verified multi-file patches and tests.
1 PLAN Mode (Read-Only Architect)
  • Hard Write Lock: File creation, patch edits, and mutating bash tools are denied or gated by permission policy.
  • Deep Exploration: Uses grep, glob, file reads, and @explore subagents to verify call sites before proposing changes.
  • Best Model Choice: Route to high-reasoning models (claude-opus-4-6, gpt-5, or gemini-2.5-pro).
2 BUILD Mode (Full-Access Implementer)
  • Full Execution Loop: Applies surgical patches, receives automatic LSP compiler feedback, and runs test suites.
  • Follows the Approved Plan: Executes step by step against the blueprint already agreed upon in the same session context.
  • Best Model Choice: Fast, high-throughput coding models (claude-sonnet-4-5 or local qwen3-coder).

The 4-Step Plan → Review → Build Rhythm

1. Press [Tab] -> Confirm badge reads PLAN.
2. Prompt: "Trace @src/auth/session.ts and propose a 3-step plan to rotate refresh tokens."
3. Challenge assumptions ("Keep backward compatibility for mobile v2 tokens; skip DB migration").
4. Press [Tab] -> Badge flips to BUILD -> Prompt: "Execute steps 1-3 and run !pnpm test auth"

Native LSP Loops, AGENTS.md & Token Compaction

Most terminal agents waste three turns running full builds just to discover a missing import. OpenCode spawns language servers directly behind the scenes, streaming instant compiler diagnostics into the agent turn the moment a file is written.

1 Built-In & Custom LSP Configuration

OpenCode auto-detects TypeScript, Python, Go, Rust, Elixir, Zig, C#, and Astro language servers. Customize or disable servers in opencode.json:

{
  "lsp": {
    "pyright": {
      "env": { "VIRTUAL_ENV": ".venv" }
    },
    "eslint": { "disabled": true }
  }
}
2 High-Signal AGENTS.md via /init

Running /init scans your build scripts, lint rules, and folder conventions to write AGENTS.md (also compatible with CLAUDE.md fallback):

  • Pin exact single-file test commands (pnpm vitest run path/to/file).
  • List architectural boundaries and forbidden directories.
  • Load shared team docs via "instructions": ["docs/arch.md"].

07 • Reversible Time-Travel Shadow Git Snapshots, /undo, /redo & Branching

Fearless Experimentation with /undo & /redo Snapshots

Traditional git reset --hard wipes your manual edits or pollutes commit history. OpenCode maintains a private shadow Git object store behind your repository so every turn is atomically reversible without touching your real Git staging index.

Coupled Code + Context Rewind: Running /undo rolls back both the workspace files and the bad conversation turn simultaneously, letting you refine your prompt and replay cleanly from a known-good checkpoint.
1 How /undo Beats Follow-Up Nagging

When an agent goes down the wrong architectural path, arguing with it in turn 6 leaves five turns of broken code polluting its context window. Instead:

  1. Run /undo (Ctrl+X u) once or twice to restore exact pre-turn files; your original prompt pops right back into the input box.
  2. Add the missing constraint or @file reference and hit Enter.
  3. Changed your mind? Run /redo (Ctrl+X r) to restore the reverted turn and patches intact.
2 Comparing Two Models on One Bug

Benchmark two providers head-to-head on your real repo in under two minutes:

  1. Let Model A attempt the fix and run !pnpm test.
  2. Run /undo to rewind the working tree to its exact starting state.
  3. Switch models with /models (Ctrl+X m) to Model B and submit the exact same pre-filled prompt.
Git Repository Required for Snapshot Tracking
OpenCode’s /undo and /redo engine relies on your folder being initialized with git init. Always initialize Git in scratch prototypes before starting heavy multi-file Build loops.

Session Sharing Controls, Privacy Locks & IDE Companions

OpenCode makes code review walkthroughs effortless with one-command share links, while giving enterprise security teams a single config switch to lock sharing off completely across private repositories.

1 Three Session share Modes

Configure "share" in opencode.json to match your repo’s confidentiality level:

  • "manual" (Default): Nothing leaves your machine unless you explicitly run /share (Ctrl+X s); revoke anytime with /unshare.
  • "disabled" (Enterprise Lock): Hard-blocks /share in proprietary repos so source snippets can never be published to a public URL.
  • "auto": Automatically creates shareable links for open-source PR walkthroughs.
2 Secret & Env Variable Substitution
  • Never Hardcode Keys: Reference environment secrets in opencode.json with "{env:LITELLM_API_KEY}" or file contents via "{file:~/.secrets/token}".
  • Block Sensitive Reads: Add .env*, *.pem, and secrets/ deny rules under permission.read so prompts never ingest raw credentials.
  • Zero-Telemetry Local Stack: Pair "share": "disabled" with local Ollama or VPC Bedrock/Vertex endpoints for full data residency.
3 VS Code, Cursor & Neovim Companion

Run OpenCode inside your editor’s integrated terminal pane: active file selections, line ranges, and diagnostic problems jump straight into your TUI prompt with a single shortcut while diffs update live in editor buffers.

4 Themes & TrueColor Terminal Tuning

Run /themes (Ctrl+X t) and pick system or built-in palettes (Catppuccin, Tokyonight, Gruvbox, Rose Pine). Use a TrueColor terminal (Ghostty, Kitty, WezTerm, iTerm2, or Alacritty) for crisp diff highlights.

Commit "share": "disabled" on Day One in Private Client Repos
Adding {"share": "disabled"} to your repository’s checked-in opencode.json protects every developer on the team from accidentally running Ctrl+X s during a late-night debugging session.

11 • Clinic & Pre-Flight Troubleshooting Clinic & 6-Point Daily Checklist

Troubleshooting Clinic & 6-Point Pre-Flight Checklist

Fix the seven most frequent TUI, local-model, LSP, and snapshot hiccups in ten seconds flat, then run the 6-point checklist when onboarding any new repository.

Symptom / Issue 10-Second Root-Cause Fix
1. Local Ollama model forgets system tools or loops Ollama defaults to a tiny 4096 token context window! Build a Modelfile with PARAMETER num_ctx 32768 (or 65536) before selecting it in OpenCode.
2. Agent refuses to edit files even when asked Check the bottom-left mode badge—you are still in read-only PLAN mode! Press Tab once to flip the badge to BUILD.
3. /undo reports snapshot unavailable The directory is not a Git repository. Run git init at the workspace root so OpenCode can initialize its shadow snapshot tree.
4. LSP diagnostics missing for Python or TypeScript Language server binary isn’t on PATH or wrong venv is active. Install pyright / typescript-language-server or pass VIRTUAL_ENV under lsp in opencode.json.
5. Newly added API key doesn’t show models in /models Run /connect inside the TUI or verify the provider ID via opencode auth list and opencode models --refresh.
6. Diff colors look washed out inside tmux Enable 24-bit TrueColor in ~/.tmux.conf (set -ga terminal-overrides ",xterm-256color:Tc") and select /themes → system.
7. Responses slow down & cost spikes after 40 turns Long raw tool outputs are re-sent each turn. Run /compact (Ctrl+X c) to distill history or start a fresh thread with /new.
