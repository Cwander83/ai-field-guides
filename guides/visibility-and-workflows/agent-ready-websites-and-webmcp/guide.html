Prioritized Remediation Formula (Never Chase Bonus Points First)
1. Essential Failures → 2. Essential Partials → 3. Recommended Checks → 4. Deploy & Verify scanned_at

Always apply the specific fix in each issue’s recommendation field because it is generated directly from observed scan evidence. Ignore missing bonus signals until every Essential and Recommended item passes.

Zero-Bloat Discovery: /llms.txt & Accept: text/markdown

Raw HTML pages wrap a few paragraphs of useful knowledge inside megabytes of navigation menus, React hydration bundles, and cookie banners. Clean Markdown files and HTTP content negotiation eliminate that waste.

Figure 6.1 • Token-Light Content Negotiation: Heavy visual web pages route through an edge negotiator when an agent sends Accept: text/markdown, delivering clean, structured Markdown at the exact same canonical URL.
1 /llms.txt & /llms-full.txt

Place /llms.txt at your domain root using four simple Markdown elements: one # H1 site title, a > blockquote summary, ## Section headings with - [Title](url): Description links, and an optional ## Optional section for secondary reading.

Pair it with /llms-full.txt when you want agents to ingest an entire documentation corpus in a single fetch.

2 Accept: text/markdown Headers

Keep URLs identical for humans and bots. When a client sends Accept: text/markdown, respond with Content-Type: text/markdown; charset=utf-8, include Vary: Accept so CDNs cache both variants separately, and optionally expose x-markdown-tokens.

Advertise alternate links in HTML via <link rel="alternate" type="text/markdown">.

Next.js App Router Middleware: Serving Clean Markdown on the Same URL

import { NextRequest, NextResponse } from 'next/server';

export function middleware(req: NextRequest) {
  const accept = req.headers.get('accept') || '';
  if (accept.includes('text/markdown')) {
    const target = req.nextUrl.clone();
    target.pathname = '/api/markdown' + target.pathname;
    const res = NextResponse.rewrite(target);
    res.headers.set('Vary', 'Accept');
    return res;
  }
  return NextResponse.next();
}

Browser WebMCP: Turning Pages into Native Agent Tools

Developed in the W3C Web Machine Learning Community Group (behind chrome://flags/#enable-webmcp-testing or --enable-features=WebMCP in Chrome 146–156+), WebMCP lets websites publish structured tools directly inside the user’s browser session.

1 Declarative HTML Forms (Chrome 156 Notes)

Chrome 156 supports toolname, tooldescription, toolautosubmit, and toolparamdescription on forms (setting e.agentInvoked on submit). Note: the W3C Draft CG Report removed Declarative forms in Oct 2026, and forms without toolautosubmit wait for a human click (always set a call timeout).

2 Imperative document.modelContext & Polyfill

Register dynamic tools via document.modelContext.registerTool() (legacy navigator.modelContext fails in Chrome 156+). Load the official Nov 2026 W3C WebMCP polyfill so registration code runs across all browsers and in-site assistants.

WebMCP Tool Registration Contract Anatomy
toolname / name + tooldescription + JSON inputSchema + execute(input, client) + readOnlyHint / consequentialHint

Pattern A: Declarative HTML Form with Agent Response Hook

<form id="demo-form" toolname="book_demo" tooldescription="Reserve a product walkthrough slot" toolautosubmit>
  <input name="email" type="email" required toolparamdescription="Work email for calendar invite" />
  <input name="date" type="date" required toolparamdescription="Preferred date in YYYY-MM-DD" />
  <button type="submit">Book Demo</button>
</form>
<script>
  document.getElementById('demo-form').addEventListener('submit', (e) => {
    e.preventDefault();
    const booking = saveDemoSlot(new FormData(e.target));
    if (e.agentInvoked && typeof e.respondWith === 'function') {
      e.respondWith(Promise.resolve({ content: [{ type: 'text', text: JSON.stringify(booking) }] }));
    }
  });
</script>

Pattern B: Imperative Read-Only Lookup via document.modelContext.registerTool

const mc = document.modelContext; // Chrome 156+ standard (or W3C WebMCP polyfill)
if (mc) {
  mc.registerTool({
    name: 'search_docs',
    description: 'Search product documentation pages by keyword and return matching snippets.',
    inputSchema: {
      type: 'object',
      properties: { query: { type: 'string', description: 'Search keyword or error code' } },
      required: ['query']
    },
    annotations: { readOnlyHint: true },
    execute: async ({ query }) => ({
      content: [{ type: 'text', text: JSON.stringify(await runLocalDocSearch(query)) }]
    })
  });
}

Machine-Readable Errors: RFC 9457 & Agent Recovery

Returning a 40KB styled HTML error page for a rate limit or missing route forces an LLM to burn tokens guessing what went wrong. RFC 9457 application/problem+json turns failures into deterministic instructions.

Figure 8.1 • Deterministic Error & Protocol Contracts: Instead of dumping unparsed HTML error pages into an agent context window, RFC 9457 gateways wrap failures in a golden protective schema carrying a stable code and an explicit resolution hint.

RFC 9457 application/problem+json Response Contract

HTTP/1.1 429 Too Many Requests
Content-Type: application/problem+json
Retry-After: 30

{
  "type": "https://is-agentic.com/errors/rate-limit-exceeded",
  "title": "Rate limit exceeded",
  "status": 429,
  "detail": "Exceeded 120 requests per 60 seconds from this IP address.",
  "code": "rate_limit_exceeded",
  "resolution": "Honor the Retry-After header and wait 30 seconds before retrying."
}
Stable code HTTP Meaning Automated Agent Recovery Action
invalid_url 400 Target is malformed or private Validate scheme and pass a public http:// or https:// URL.
report_not_found 404 No cached scan exists yet Run npx is-agentic <url> --json or open /scan/<target>.
rate_limit_exceeded 429 Burst exceeded 120 req / 60s Read the HTTP Retry-After header and sleep before retrying.
report_temporarily_unavailable 503 Transient backend hiccup Retry briefly with backoff; do not trigger duplicate scans.

Security Boundaries, Rate Limits & Human Confirmation Gates

Because browser WebMCP tools run directly inside an authenticated user’s session with live cookies, high-stakes actions like purchases or account deletions must never execute silently.

1 120 req / 60s Rate Limit

is-agentic.com enforces 120 requests per IP per 60 seconds. Cache JSON results locally in CI and obey HTTP Retry-After headers on 429 responses.

2 6-Hour Snapshot Cache

Reports are immutable snapshots that refresh only when a visit finds them older than 6 hours. Compare scanned_at after deploys or trigger manual Rescan.

3 Auth Surface Hygiene

Private MCP servers yield score: null. Keep internal admin dashboards out of /llms.txt and sitemap.xml while allowing public docs.

Human-in-the-Loop Checkout Gate Using client.requestUserInteraction()

(document.modelContext ?? navigator.modelContext).registerTool({
  name: 'place_order',
  description: 'Submit the active shopping cart for final checkout after user confirmation.',
  inputSchema: {
    type: 'object',
    properties: { shippingMethod: { type: 'string', enum: ['standard', 'express'] } },
    required: ['shippingMethod']
  },
  annotations: { readOnlyHint: false, consequentialHint: true },
  execute: async ({ shippingMethod }, client) => {
    const approved = await client.requestUserInteraction(async () => {
      return window.confirm('Confirm checkout using ' + shippingMethod + ' shipping?');
    });
    if (!approved) {
      throw new Error('Checkout cancelled by user.');
    }
    const res = await fetch('/api/checkout', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ shippingMethod })
    });
    const order = await res.json();
    return { content: [{ type: 'text', text: 'Confirmed Order ID: ' + order.orderId }] };
  }
});
Proposal-Only Tool Design & Backend Authorization
Treat every mutating WebMCP tool as a proposal rather than an authoritative command. Display exact dollar totals, recipients, and shipping terms inside your confirmation modal, and verify session tokens, CSRF origins, and cryptographic bot-auth signatures independently on the backend API before committing any write.
